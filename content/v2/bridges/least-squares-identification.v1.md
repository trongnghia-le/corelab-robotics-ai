# Fitting a first-order model: least squares, identifiability, randomisation

This optional bridge takes about 25 minutes. You can skip it and open any activity. Reading it creates no evidence.

System identification asks which parameters make a declared model reproduce a log. Here the model is a discrete first-order law with one output y and one input u:

y[k+1] = a·y[k] + b·u[k]

a is a decay (dimensionless) and b an input gain. Everything below is true only if that law is the truth, and every example is a made-up, synthetic log.

## Each step is one linear equation

Every pair (y[k], u[k]) and its successor y[k+1] gives one equation in the unknowns (a, b). With two or more steps the system is usually over-determined. If the log is noise-free and generated by the law, all equations hold exactly and any two independent ones recover (a, b). If the log is noisy, no pair fits every step, so you pick the pair with the smallest squared residuals r[k] = y[k+1] − (a·y[k] + b·u[k]).

## The normal equations

Stack the regressors as two columns, y[k] and u[k], and the targets as y[k+1]. Minimising Σ r[k]² leads to the 2×2 normal equations G p = g with p = (a, b):

- G = [[Σy², Σyu], [Σyu, Σu²]] (the Gram matrix of the regressors),
- g = [Σ y[k+1]·y[k], Σ y[k+1]·u[k]],

all sums over k = 0 … n−1. Cramer's rule solves the 2×2 system: a = (g₀·G₁₁ − G₀₁·g₁)/det G and b = (G₀₀·g₁ − G₁₀·g₀)/det G, with det G = G₀₀·G₁₁ − G₀₁². At the solution the residual is orthogonal to both columns (Σ r·y = 0 and Σ r·u = 0), which is a good independent check on your arithmetic.

Worked example. Log y = [1, 2, 2, 4, 3], u = [1, 0, 2, 0]. Then Σy² = 1 + 4 + 4 + 16 = 25, Σyu = 1 + 0 + 4 + 0 = 5, Σu² = 5, g = [2·1 + 2·2 + 4·2 + 3·4, 2·1 + 2·0 + 4·2 + 3·0] = [26, 10]. det G = 125 − 25 = 100, so a = (26·5 − 5·10)/100 = 0.8 and b = (25·10 − 5·26)/100 = 1.2. The residuals are 0, 0.4, 0 and −0.2, and 0.4·2 − 0.2·4 = 0 confirms orthogonality to the y column. Their RMS is √((0.16 + 0.04)/4) ≈ 0.2236.

## Identifiability: can this log tell a and b apart?

If the two columns are parallel, G is singular and many (a, b) pairs give exactly the same residuals: the parameters are not identifiable from that log. Typical causes are an input that is all zero (b is invisible), a log with y all zero (a is invisible), and a settled response with constant input: if y = 2 and u = 1 forever, every pair with 2a + b = 2 fits perfectly. A constant input is not automatically fatal. While y is still changing (a step response before settling), the column y[k] is not parallel to the constant column and G is invertible.

Between "singular" and "fine" is a weak zone. The condition number λ_max/λ_min of G measures how much noise is amplified. A common convention, used in this lab, is: at most 1e4 identifiable, above 1e4 but finite weak, infinite unidentifiable. Under independent target noise of standard deviation σ, the estimates have standard deviations σ·√(G⁻¹₀₀) for a and σ·√(G⁻¹₁₁) for b, and for a nearly singular G they are huge. For a symmetric 2×2 G, get the eigenvalues from the trace t and determinant d: λ = t/2 ± √(t²/4 − d), and the condition number is the larger over the smaller (compute λ_min as d/λ_max to avoid cancellation). Example: G = [[52, 40], [40, 48]] has t = 100, d = 896, λ = 50 ± 40.05, so the condition number is about 9.05.

These bands are a convention, not a theorem. "Unidentifiable" in the lab means numerically singular (determinant at most 1e-12 times the squared trace), which also catches badly scaled or tiny-signal logs that are not exactly parallel, and the condition number changes if you change the units of y or u. Treat the label as a warning about this log in these units, not as a property of the plant.

The honest response to a weak or unidentifiable log is not a cleverer solver; it is a new log with a more varied input. Gram matrices of separate experiments add (the sums simply run over more rows, each log keeping its own y[k], y[k+1] pairs), so a second, well-excited log can repair the first.

## Overfitting and held-out residuals

A good fit on the training log can be an accident: with a singular G the zero training residual is shared by infinitely many pairs. Always score the fitted pair on a separate log that was not used for the fit, using the one-step RMS residual, and compare it with a threshold you chose in advance. If the held-out residual is far larger than the training one, suspect low excitation, too few samples or a wrong model class, and check the Gram matrix before touching the threshold.

## Bounded randomisation

Domain randomisation draws plant parameters from declared ranges so that a design is exercised on many simulated plants. With an explicit draw d in [0, 1], a uniform parameter is lo + d·(hi − lo) and a log-uniform one (for positive quantities that span decades) is lo·(hi/lo)^d. Floating point can step an ulp outside the range, so clamp into [lo, hi]. The ranges are your assumption: a real plant outside them is simply not covered, and randomisation does not make a simulator true.

## Scope

The lab uses small synthetic logs with explicit noise numbers. It does not identify nonlinear, delayed, multi-input or closed-loop systems, does not use a physics simulator, and makes no sim-to-real claim. Passing it says nothing about a real robot.
