## Why this matters

A person-following robot, a pick-and-place arm tracking parts on a conveyor and a car watching pedestrians all need to know that "the object in this frame is the same one as in the last frame". A detector (V08) has no memory: it reports boxes, not identities. If the identity is wrong the robot follows the wrong person, a counter counts one object twice, and a velocity estimate mixes two motions. Tracking adds memory and a model of motion on top of detection. The tools are those you know: filtering (C07) to predict and smooth, and assignment to match predictions with new measurements. Every step has a failure mode you can predict and test.

## Intuition

At each frame a tracker holds a list of **tracks** (objects it believes exist, with a position and velocity) and receives a list of **detections**. Three questions: where should each track be now (predict), which detection belongs to which track (associate), and what is the new state (update). Then it handles leftovers: a detection that matches nothing might be a new object; a track with no detection might be hidden or gone.

The simplest association, "give each track the nearest detection to where it *was*", works when objects are far apart relative to how far they move. It fails when they cross or come close, because the nearest detection to the old position of A can be the new position of B. Predicting forward with the motion model before matching removes most of these errors.

## Theory and derivation

### Motion model and prediction

With a constant-velocity model and frame interval $\Delta t$ the state $(x,y,v_x,v_y)$ is predicted as
$$x^-=x+v_x\Delta t,\qquad y^-=y+v_y\Delta t,\qquad v^-=v .$$
A Kalman filter (C07) adds a covariance that grows with the prediction and shrinks with each measurement. The cheaper **alpha-beta** update, with residual $r=z-x^-$ and gains $\alpha,\beta$, is
$$x\leftarrow x^-+\alpha r,\qquad v\leftarrow v+\frac{\beta}{\Delta t}\,r .$$
With $\alpha=\beta=1$ the position becomes the measurement and the velocity the difference of consecutive measurements; smaller gains smooth noise but lag manoeuvres. If the measurement noise has standard deviation $\sigma$, that two-point velocity has standard deviation $\sqrt2\,\sigma/\Delta t$.

### Cost, gating

Build a cost matrix $C_{ij}$ between track prediction $i$ and detection $j$: Euclidean distance, $1-\mathrm{IoU}$ (V08), or Mahalanobis distance with the filter covariance, optionally plus an appearance distance. **Gating** forbids pairs with $C_{ij}>g$. For a 2-D Gaussian position error, the squared Mahalanobis distance is chi-square with 2 degrees of freedom: 95% of true matches have $d^2\le5.99$, 99% have $d^2\le9.21$. With isotropic noise $\sigma$ this is a radius $\sqrt{5.99}\,\sigma=2.45\sigma$.

### Assignment

*Nearest neighbour* lets each track choose independently; two tracks can claim the same detection. *Greedy* repeatedly takes the globally smallest remaining pair and removes its row and column; it is fast and often good but not optimal. *Optimal assignment* (Hungarian algorithm, `scipy.optimize.linear_sum_assignment`) minimises the total cost over one-to-one matchings in $O(n^3)$. Gating is handled by giving forbidden pairs a large cost and ignoring matches that use them.

Example: $C=\begin{bmatrix}1&2\\2&10\end{bmatrix}$ with gate 20. Greedy picks $(0,0)$ at cost 1, then is left with $(1,1)$ at 10: total 11. The matching $(0,1),(1,0)$ costs $2+2=4$. Greedy is optimal only when the smallest entries do not conflict.

### Track management

A new detection that matches nothing starts a **tentative** track; it becomes **confirmed** after a number of hits (for example 2 of the first 3 frames) so a single false detection does not become an object. A track with no match increments a miss counter and is deleted after $n_\text{miss}$ misses. During misses a track should keep *predicting* so it is in the right place when the object reappears. Too small an $n_\text{miss}$ breaks identity at every occlusion (fragmentation: the object gets a new ID); too large lets ghost tracks steal detections.

### Identity metrics

An **identity switch** occurs when the track ID assigned to a ground-truth object changes. Multi-object tracking accuracy (CLEAR MOT) summarises errors over all frames:
$$\mathrm{MOTA}=1-\frac{\mathrm{FN}+\mathrm{FP}+\mathrm{IDSW}}{\mathrm{GT}},$$
with $\mathrm{GT}$ the number of ground-truth object instances over all frames. MOTA can be negative. IDF1 measures how long identities are kept correctly. Always also report the number of identity switches and fragmentations, since MOTA hides them behind detection errors.

### Where tracking breaks

Occlusion, crossings, similar-looking objects, missed detections, camera motion (the whole image moves; use ego-motion compensation), non-constant motion (a person turns), and detector flicker.

## Worked example

### Constant-velocity prediction

**Problem.** A track is at $(40,50)$ with velocity $(30,0)$ pixels per frame. Where is it predicted to be in the next frame?

**Solution.**
1. The constant-velocity model advances the position by velocity times the time step: $(x,y)\to(x+v_x\Delta t,\;y+v_y\Delta t)$ with $\Delta t=1$ frame.
2. $x=40+30\cdot1=70$ and $y=50+0\cdot1=50$.
3. The predicted position is $(70,50)$, with unchanged velocity $(30,0)$.

**Check.** The displacement $(70-40,\,50-50)=(30,0)$ equals the velocity for one frame.

**Takeaway.** Prediction moves each track to where the object should be now, so that association compares detections with the expected position rather than with the old one.

### Crossing objects: nearest neighbour versus prediction

**Problem.** Object A moves right at 30 px per frame along $y=50$, object B moves left along $y=52$; the detections at frames $t=0,\dots,5$ are $A=(30t,50)$ and $B=(150-30t,52)$. Before the crossing the tracker has estimated $v_A=(30,0)$ and $v_B=(-30,0)$. At frame 3 the track positions (from frame 2) are $A=(60,50)$ and $B=(90,52)$, and the new detections are $d_A=(90,50)$ and $d_B=(60,52)$. Assign detections to tracks (a) with Euclidean cost against the last position, (b) against the predicted position.

**Solution.**
1. (a) Cost against the last positions, $C=\lVert\text{track}-\text{detection}\rVert$: track A to $d_A$: $\lVert(60,50)-(90,50)\rVert=30$; track A to $d_B$: $\lVert(60,50)-(60,52)\rVert=\sqrt{0+4}=2$; track B to $d_A$: $\lVert(90,52)-(90,50)\rVert=2$; track B to $d_B$: $\lVert(90,52)-(60,52)\rVert=30$.
2. The smallest costs (2 and 2) are the cross pairs, so the assignment is a swap: A takes $d_B$ and B takes $d_A$. Both identities switch.
3. (b) Predict first: A $\to(60,50)+(30,0)=(90,50)$, B $\to(90,52)+(-30,0)=(60,52)$.
4. Costs against the predictions: A to $d_A$: $0$; A to $d_B$: $\lVert(90,50)-(60,52)\rVert=30.07\approx30$; B to $d_A$: $30.07\approx30$; B to $d_B$: $0$.
5. The smallest costs (0 and 0) give the correct pairing: A with $d_A$, B with $d_B$, no switch.
6. In the lab simulation over six frames the nearest-neighbour tracker returns track IDs $[0,1],[0,1],[0,1],[1,0],[1,0],[1,0]$: the IDs swap at frame 3 and stay swapped, giving two identity switches (one per object). With prediction the IDs stay $[0,1]$ in every frame: no switches.

**Check.** The two objects pass at frame 3 with only 2 px of vertical separation, which is smaller than the 30 px each object moves in a frame: that is the condition under which last-position matching must fail. Prediction removes the 30 px motion from the cost, leaving residuals of 0.

**Takeaway.** Matching to the last position fails when objects cross because the other object is closer than the object's own old position; a motion model fixes this.

### Gating radius

**Problem.** Position noise is isotropic with standard deviation $\sigma=3$ px in two dimensions. What gate radius contains 95% of true matches?

**Solution.**
1. For 2-D Gaussian position error, the squared Mahalanobis distance is chi-square with 2 degrees of freedom; its 95% point is $d^2=5.991$ (since $1-e^{-d^2/2}=0.95$ gives $d^2=-2\ln0.05=5.991$).
2. With isotropic noise the gate is a circle of radius $\sqrt{5.991}\,\sigma=2.448\,\sigma$.
3. Substituting $\sigma=3$ px: $2.448\cdot3=7.34$ px.

**Check.** Dimension check: a radius in pixels. The multiplier $2.45\sigma$ is the one stated in the theory.

**Takeaway.** A gate in units of $\sigma$ (about $2.45\sigma$ for 95%) rejects far-away pairs while keeping nearly all true matches.

### Greedy versus optimal assignment

**Problem.** For the cost matrix $C=\begin{bmatrix}1&2\\2&10\end{bmatrix}$ with gate 20, compare the total cost of the greedy assignment and of the optimal one-to-one assignment.

**Solution.**
1. Greedy takes the smallest remaining entry first: $C_{00}=1$, which removes row 0 and column 0.
2. Only $(1,1)$ is left, with cost $10$, so greedy costs $1+10=11$ (all entries are within the gate 20).
3. The one-to-one matchings are $\{(0,0),(1,1)\}$ with cost $1+10=11$ and $\{(0,1),(1,0)\}$ with cost $2+2=4$.
4. The optimal assignment is therefore $\{(0,1),(1,0)\}$ with total $4$.

**Check.** The Hungarian algorithm minimises the total over all permutations, and there are only $2!=2$ of them, so $4<11$ is exhaustive.

**Takeaway.** Greedy is optimal only when the smallest entries do not conflict; here taking the cheapest pair forces an expensive second pair.

### MOTA

**Problem.** A sequence has 100 ground-truth object instances, 8 misses (false negatives), 5 false positives and 2 identity switches. Compute $\mathrm{MOTA}$.

**Solution.**
1. $\mathrm{MOTA}=1-\dfrac{\mathrm{FN}+\mathrm{FP}+\mathrm{IDSW}}{\mathrm{GT}}$.
2. Total errors: $8+5+2=15$.
3. $\mathrm{MOTA}=1-15/100=0.85$.

**Check.** Each error type counts once, and with zero errors the formula gives 1, with errors equal to GT it gives 0.

**Takeaway.** MOTA folds three error types into one number, so the identity switches (2 of 15 errors) are almost hidden: report them separately as well.

### Occlusion and track deletion

**Problem.** An object moves 10 px per frame along a line, $x=10t$, and is detected at frames 0 to 3 and 6 to 8 but not at frames 4 and 5. The tracker uses a gate of 15 px (assumed, as in the lab) and deletes a track when its miss count exceeds $n_\text{miss}$. What happens at frame 6 for $n_\text{miss}=1$ and for $n_\text{miss}=3$ with prediction through the gap?

**Solution.**
1. By frame 3 the track is at $x=30$ with velocity 10 px per frame.
2. Frame 4 has no detection: miss count 1. Frame 5: miss count 2.
3. $n_\text{miss}=1$: the count 2 exceeds 1 at frame 5, so the track is deleted. At frame 6 the detection at $x=60$ matches nothing and starts a new ID: fragmentation.
4. $n_\text{miss}=3$: the count 2 does not exceed 3, so the track survives and keeps predicting through the gap: $x=40$ at frame 4, $x=50$ at frame 5, $x=60$ at frame 6.
5. At frame 6 the detection is at $x=60$, at distance $|60-60|=0\le15$ from the prediction, so it is matched and the object keeps ID 0.

**Check.** Without prediction the surviving track would sit at $x=30$, $|60-30|=30>15$, and no match would occur, so prediction is what makes the long $n_\text{miss}$ useful.

**Takeaway.** A deletion threshold shorter than the occlusion fragments the identity, and a track must keep predicting during misses so that it is where the object reappears.

## Reference implementation

Prediction, cost matrix, gating, greedy assignment and MOTA, checked on the worked example.

```python
import math

def predict(track, dt=1.0):
    x, y, vx, vy = track
    return (x + vx * dt, y + vy * dt, vx, vy)

def cost_matrix(preds, dets):
    return [[math.hypot(p[0] - d[0], p[1] - d[1]) for d in dets] for p in preds]

def greedy_assign(cost, gate):
    pairs = sorted((c, i, j) for i, row in enumerate(cost) for j, c in enumerate(row) if c <= gate)
    used_i, used_j, out = set(), set(), []
    for c, i, j in pairs:
        if i not in used_i and j not in used_j:
            used_i.add(i); used_j.add(j); out.append((i, j))
    return sorted(out)

def mota(fn, fp, idsw, gt):
    return 1 - (fn + fp + idsw) / gt

assert predict((40, 50, 30, 0)) == (70, 50, 30, 0)
A, B = (60, 50, 30, 0), (90, 52, -30, 0)
dA, dB = (90, 50), (60, 52)
last = cost_matrix([A[:2], B[:2]], [dA, dB])
assert greedy_assign(last, 40) == [(0, 1), (1, 0)]                       # swap without prediction
pred = cost_matrix([predict(A)[:2], predict(B)[:2]], [dA, dB])
assert greedy_assign(pred, 40) == [(0, 0), (1, 1)]                       # correct with prediction
assert greedy_assign([[1, 2], [2, 10]], 20) == [(0, 0), (1, 1)]          # total 11, not optimal
assert greedy_assign([[1, 2], [2, 100]], 5) == [(0, 0)]                  # gating drops the pair
assert abs(math.sqrt(5.991) * 3 - 7.343) < 1e-3
assert abs(mota(8, 5, 2, 100) - 0.85) < 1e-12
print("reference checks passed")
```

## Failure modes

- **Association by last position.** Crossing objects swap IDs (2 switches in the lab scenario).
- **Independent argmin per track.** Two tracks claim one detection (Exercise 6).
- **No gate.** A track far from any detection is matched to a distant one, producing a jump.
- **Frozen track during occlusion.** The track stays at its last position and the reappearing object lies outside the gate; fragmentation.
- **Over-long memory.** Ghost tracks survive many frames and capture other objects.
- **Gates in the wrong units.** A pixel gate used in metres matches everything or nothing.
- **Camera motion.** The whole image shifts, so a constant-velocity prediction in image coordinates fails; compensate or track in a world frame.
- **Reporting MOTA alone.** Detection errors dominate, hiding identity behaviour.
- **Detector flicker.** An object detected in alternate frames fragments; smooth with misses allowed and a confirmation rule.

## Alternatives and trade-offs

| Choice | Benefit | Cost |
|---|---|---|
| Nearest neighbour | Trivial | Swaps identities |
| Greedy global | Fast, usually good | Can be suboptimal |
| Hungarian | Optimal sum of costs | $O(n^3)$, still local in time |
| Multi-hypothesis / JPDA | Handles ambiguity | Complex, costly |
| Distance only | Cheap | Fails for crossing in image |
| + Appearance embedding | Re-identifies after occlusion | Needs a model, more compute |
| Constant velocity | Simple | Fails for manoeuvres |
| Kalman / IMM | Principled uncertainty | More parameters |
| Detection-free (correlation, optical flow) | No detector needed | Drifts, no new objects |

For a single followed target, use the strongest cues (appearance and position) and make the loss of identity an explicit state with a safe behaviour (stop, search). For crowds, prefer Hungarian assignment with a Kalman filter and appearance (the SORT/DeepSORT family).

## Transfer and retention

Association appears in SLAM (matching landmarks), in sensor fusion (matching radar and camera objects) and in detection evaluation itself (V08 matching is a one-to-one assignment by score). Prediction moves the matching point to where the object should now be, so the correct detection is much closer than the wrong one. It stops helping when the motion is not predictable (sudden turns, jerky camera) or the model is wrong.

With $n_\text{miss}=3$ and no prediction: the track sits at $x=30$ (last position), the detection at frame 6 is at $x=60$, distance 30 > gate 15, so no match: a new ID and fragmentation, while the old track is deleted later. With $\beta=0.2$ the velocity is an exponentially weighted average of past differences: lower noise, but lag when the object accelerates.
