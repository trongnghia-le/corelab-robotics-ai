## Why this matters

Turn mathematical notation into precise, testable statements. This lesson develops the core calculation before asking you to apply it in a new setting. Start with the diagnostic if you think you already know it; prior tool use is not evidence of understanding.

## Intuition

A function is a machine with a declared input contract. A sensor calibration converts a raw count into metres; it does not merely rename the count. Notation lets us write the contract before choosing Python or C++. A symbol has no built-in meaning: define it, its units, and its valid range.

![Left: x squared maps two different inputs to the same output, so it has no inverse on the whole real line. Right: a piecewise calibration with a declared domain n at least 10.](/lesson-figures/M01.svg)

*A function is a rule plus a domain; the calibration is only defined where its contract says it is.*

## Theory and derivation

For a function $f:D\to Y$, every input in $D$ has exactly one output in $Y$. The square function $f(x)=x^2$ maps both $-2$ and $2$ to $4$, so a function need not have a unique inverse. Restricting its domain to $[0,\infty)$ makes the nonnegative square root an inverse.

A sum $\sum_{i=1}^{3} x_i$ means $x_1+x_2+x_3$; the index is a local placeholder. In $y=ax+b$, $x$ is the input while $a,b$ are fixed parameters for this evaluation. Parentheses matter: $(x+1)^2=x^2+2x+1$, whereas $x^2+1$ has no cross term. The equals sign asserts a statement; it is not a command to change a variable.

Derive a constant-speed model from the definition $v=\Delta d/\Delta t$: multiply by $\Delta t$ to obtain $d(t)=d_0+vt$. Dimensional analysis checks that $[v][t]=(\mathrm{m/s})\mathrm{s}=\mathrm{m}$, matching $d_0$. A sum of metres and seconds is undefined, even if the computer accepts two floats.

## Worked example

With d₀ = 2 m, v = 3 m/s and t = 4 s, d(4) = 2 + 3×4 = 14 m. For f(x)=2x²−1, evaluate the square first: f(−3)=2×9−1=17. A sensor model s(n)=0.01n metres has domain n∈{0,…,1023}; extrapolating outside it is a new modeling assumption.

## Exercises

1. **(Easy)** Is "$y=\pm\sqrt{x}$" a function of $x$ on $[0,\infty)$? Is "$y=\sqrt{x}$" (the nonnegative root)? Explain using the rule "exactly one output per input". *(Adapted from: OpenStax Precalculus, Functions and Function Notation)*
2. **(Easy)** Let $f(x)=2x^2-1$. Compute $f(-3)$, $f(0)$ and $f(\tfrac12)$. Which mistake gives $-19$ for $f(-3)$?
3. **(Easy)** Evaluate $\sum_{i=1}^{4}(2i-1)$ and write the sum out term by term.
4. **(Medium)** A test cart moves at $90$ km/h. Convert this speed to m/s, then find $d(12\,\mathrm{s})$ if $d_0=5$ m and $d(t)=d_0+vt$.
5. **(Medium)** **Find the bug.** The function should compute $(x+1)^2$:
   ```python
   def f(x):
       return x**2 + 1
   ```
   Give an input where it passes, an input where it fails, and the correct expansion. Why would a test using only $x=0$ miss the bug?
6. **(Medium)** **Predict the output.**
   ```python
   def cal(n):
       if n < 10:
           raise ValueError("invalid")
       return 0.02 * (n - 10)
   print(round(cal(10), 2), round(cal(60), 2), round(cal(110), 2))
   ```
7. **(Medium)** Find the inverse of $g(x)=3x-5$ and state its domain. Then explain why $h(x)=x^2$ on $\mathbb R$ has no inverse function, and give a domain restriction that fixes it. *(Adapted from: OpenStax Precalculus, Inverse Functions)*
8. **(Hard)** A 10-bit ADC maps voltages $0$ to $3.3$ V onto counts $0,\dots,1023$. Write the model $V(n)$, find the voltage step between adjacent counts, and say what the model should do for $n=1500$. A student's log shows a reading of $4.84$ V from this sensor; what does that tell you about the data pipeline?
9. **(Hard)** **Proof.** Let $f(x)=ax+b$ and $g(x)=cx+d$. Show $f\circ g$ is again of the form $px+q$ and find $p,q$. Then show $f\circ g=g\circ f$ exactly when $ad+b=cb+d$. Interpret it for two sensor-correction steps (gain-then-offset versus offset-then-gain). *(Adapted from: OpenStax Precalculus, Composition of Functions)*
10. **(Project)** Write `calibrate(n)` for a distance sensor: invalid below 10 or above 1023, otherwise $0.02(n-10)$ m. Add `invert(m)`. Write a table of at least six test inputs, including both boundaries and one value just outside each, and run it.

## Reference implementation

Read the contract first. Predict the output before running the code locally. This reference is for studying; a submission copied from it is assisted practice, not independent evidence.

```python
def distance(t, d0=2.0, speed=3.0):
    if t < 0:
        raise ValueError("time must be nonnegative")
    return d0 + speed * t

assert distance(4) == 14
```

## Independent practice

### Goal
Implement a validated calibration function, its inverse, and affine composition, then prove your tests would catch a broken version.

### Setup
Python 3 standard library only. Save as `m01_lab.py`.

### Tasks
1. Implement `calib(n)` for integer counts: raise `ValueError` outside $10\le n\le1023$, otherwise return $0.02(n-10)$ metres.
2. Implement `calib_inverse(m)` returning the integer count that produced distance `m`; reject distances outside the range of `calib`.
3. Implement `expand_sq(a)` returning the coefficients $(1,-2a,a^2)$ of $(x-a)^2$, and `horner(coeffs, x)` to evaluate a polynomial.
4. Implement `affine_compose(f, g)` for pairs $(a,b)$ meaning $ax+b$, returning the pair for $f\circ g$.
5. Run the tests, then deliberately change `0.02` to `0.2` or drop a sign and confirm a test fails.

### Tests
Paste this below the starter code (same file) and run it. Every check is a plain `assert`; the first failure stops the run.

```python
def close(a, b): return abs(a - b) < 1e-9
# hand-computed cases
assert close(calib(10), 0.0) and close(calib(20), 0.2) and close(calib(110), 2.0)
assert close(calib(1023), 20.26)
for bad in (9, 1024, -5):
    try: calib(bad); raise SystemExit("no error for %d" % bad)
    except ValueError: pass
assert calib_inverse(2.0) == 110
try: calib_inverse(25.0); raise SystemExit("no error for 25 m")
except ValueError: pass
assert expand_sq(3) == (1, -6, 9)
assert horner((1, -6, 9), 5) == 4 and horner((2, 0, -1), -3) == 17
assert affine_compose((2, 1), (3, -4)) == (6, -7)
# invariants
assert all(calib_inverse(calib(n)) == n for n in range(10, 1024))
for a in (-2, 0, 1, 4):
    for x in (-3, 0, 2.5):
        assert horner(expand_sq(a), x) == (x - a) ** 2
f, g = (2, 1), (3, -4)
a, b = affine_compose(f, g)
assert all(a * x + b == f[0] * (g[0] * x + g[1]) + f[1] for x in (-1, 0, 7))
print("calib(110) =", calib(110), "| (x-3)^2 at 5 =", horner(expand_sq(3), 5), "| f.g =", affine_compose(f, g))
print("all tests passed")
```

### Expected output
A correct solution prints the following and exits silently otherwise. A failed assert shows the line that broke.

```text
calib(110) = 2.0 | (x-3)^2 at 5 = 4 | f.g = (6, -7)
all tests passed
```

## Failure modes

An inverse is not the reciprocal: f⁻¹(y) asks which input produced y; 1/f(x) divides by an output. A quantity and its numerical representation also differ: 100 cm and 1 m represent the same length.

## Alternatives and trade-offs

A table interpolates measured values without a simple formula. A symbolic function exposes assumptions and units. Neither representation justifies extrapolation beyond the calibration domain.

## Exercise answers

1. $\pm\sqrt{x}$ is not a function: $x=4$ gives two outputs, $+2$ and $-2$. $\sqrt{x}$ with the nonnegative convention gives exactly one output per input, so it is a function.
2. $f(-3)=2\cdot9-1=17$; $f(0)=-1$; $f(\tfrac12)=2\cdot\tfrac14-1=-\tfrac12$. The value $-19$ comes from reading $-3^2$ as $-(3^2)=-9$, i.e. losing the parentheses: $2(-9)-1=-19$. The square applies to $-3$ as a whole.
3. $1+3+5+7=16$.
4. $90$ km/h $=90\cdot1000/3600=25$ m/s. $d(12)=5+25\cdot12=305$ m.
5. Passes at $x=0$ (both give 1). Fails at $x=2$: gives $5$, correct is $9$. $(x+1)^2=x^2+2x+1$, the cross term $2x$ is missing. At $x=0$ the cross term vanishes, so it cannot be seen.
6. $0.02\cdot0=0.0$; $0.02\cdot50=1.0$; $0.02\cdot100=2.0$. Output: `0.0 1.0 2.0`.
7. $y=3x-5\Rightarrow x=(y+5)/3$, so $g^{-1}(y)=(y+5)/3$ with domain $\mathbb R$. $h(-2)=h(2)=4$, so output 4 does not determine the input; restrict to $[0,\infty)$ to get inverse $\sqrt{y}$.
8. $V(n)=3.3\,n/1023$ for $n\in\{0,\dots,1023\}$. Step $=3.3/1023\approx3.226$ mV. For $n=1500$ the model is outside its domain: raise an error (or clip with a flag), do not return $4.84$ V silently. A logged $4.84$ V is above the 3.3 V full scale, so the value cannot come from this ADC model: the data came from extrapolation, a different scaling, or a wiring/unit fault, and should be investigated.
9. $f(g(x))=a(cx+d)+b=acx+(ad+b)$, so $p=ac$, $q=ad+b$. Likewise $g(f(x))=acx+(cb+d)$. The slopes agree, so equality holds iff $ad+b=cb+d$.
10. A good answer has: both boundaries ($n=10\to0.0$, $n=1023\to20.26$), outside values ($9$ and $1024$ raise), a middle value ($110\to2.0$), and a round trip `invert(calibrate(n))==n`. The tests should be written from hand-computed values, not from the function's own output.
