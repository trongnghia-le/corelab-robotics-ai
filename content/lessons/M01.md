## Why this matters

Turn mathematical notation into precise, testable statements. This lesson develops the core calculation before asking you to apply it in a new setting. Start with the diagnostic if you think you already know it; prior tool use is not evidence of understanding.

## Intuition

Think of a vending machine. You press a code, and out comes exactly one item. Three things make it trustworthy: the buttons it accepts (the input contract), the rule that links each button to an item, and the promise that pressing the same button twice gives the same item. A mathematical function is that machine. A sensor calibration is the same machine with a robot's data: it takes a raw count from an analog-to-digital converter (ADC), such as $n=110$, and returns a distance in metres, $2.0$ m. It does not merely rename the count; it attaches a unit and a meaning, and it only promises to work for the counts the manufacturer tested, say $10\le n\le1023$.

Notation is the shorthand we use to write down the machine before choosing Python or C++. A symbol has no built-in meaning: until you say what $x$ is, what unit it carries and which values it may take, a formula is a riddle, not a statement. Beginners often read $f(x)$ as "$f$ times $x$". It is not: $f$ is the machine and $x$ is what you feed it, so $f(3)$ means "feed 3 into the machine". Parentheses do double duty in mathematics (grouping and function application), which is the source of many slips.

Predict before you compute. A cart starts 2 m from a wall and drives away at 3 m/s. Before reading any formula, guess its distance after 4 s. Each second adds 3 m, so after 4 seconds it has added 12 m on top of the 2 m it already had. Now guess whether the answer would change if the speed were written as 3 km/h but you still plugged in the number 3 and the time in seconds: the machine would happily return a number, but the number would no longer mean metres. Units are part of the input contract.

The common wrong intuition is that "a function is a formula". A formula is only the rule. The same formula $x^2$ is a one-to-one machine on $[0,\infty)$ and a two-to-one machine on all real numbers, so the domain matters as much as the rule. A second wrong intuition is that an inverse is "one over the function": $f^{-1}(y)$ asks which input produced the output $y$, while $1/f(x)$ divides by the output. Keep both pictures in mind: the machine with a stated domain, and the question "what went in?" asked backwards.

![Left: x squared maps two different inputs to the same output, so it has no inverse on the whole real line. Right: a piecewise calibration with a declared domain n at least 10.](/lesson-figures/M01.svg)

*A function is a rule plus a domain; the calibration is only defined where its contract says it is.*

**Example.** A distance sensor reports $n=110$. The machine is $0.02(n-10)$ with input contract $10\le n\le1023$. What does it output, and what should the same machine do for $n=9$?

**Solution.** The count $110$ lies inside the contract, so the output is $0.02\cdot(110-10)=0.02\cdot100=2.0$ m. For $n=9$ the contract is violated and the formula would return $0.02\cdot(9-10)=-0.02$ m, a negative distance, which is outside what the sensor can mean; the machine should therefore refuse with an error instead of returning $-0.02$ m.

## Theory and derivation

For a function $f:D\to Y$, every input in $D$ has exactly one output in $Y$. The square function $f(x)=x^2$ maps both $-2$ and $2$ to $4$, so a function need not have a unique inverse. Restricting its domain to $[0,\infty)$ makes the nonnegative square root an inverse.

A sum $\sum_{i=1}^{3} x_i$ means $x_1+x_2+x_3$; the index is a local placeholder. In $y=ax+b$, $x$ is the input while $a,b$ are fixed parameters for this evaluation. Parentheses matter: $(x+1)^2=x^2+2x+1$, whereas $x^2+1$ has no cross term. The equals sign asserts a statement; it is not a command to change a variable.

Derive a constant-speed model from the definition $v=\Delta d/\Delta t$: multiply by $\Delta t$ to obtain $d(t)=d_0+vt$. Dimensional analysis checks that $[v][t]=(\mathrm{m/s})\mathrm{s}=\mathrm{m}$, matching $d_0$. A sum of metres and seconds is undefined, even if the computer accepts two floats.

### Notation as a contract: sets, intervals, sums and piecewise rules

Every formula is a short sentence in a precise language, and it is only as good as the definitions behind its symbols. A *set* is an unordered collection without repeats: $\{1,2,6\}=\{6,1,2\}$, whereas the vector $(1,2,6)$ differs from $(6,1,2)$ because order matters (Boyd and Vandenberghe, VMLS, Appendix A, "Sets"). The statement $x\in S$ reads "$x$ belongs to $S$", and $\{x\mid\text{condition}(x)\}$ builds a set from a condition. Intervals are sets of real numbers: $[a,b]=\{x\mid a\le x\le b\}$ includes both end points (closed), $(a,b)$ excludes both (open), and $[a,\infty)$ is unbounded on the right; $\infty$ is not a number you can reach, so it always gets a round bracket. The counts of the calibration are not an interval of reals but the integer set $\{10,11,\dots,1023\}$; writing $n\in\{10,\dots,1023\}$ rather than $[10,1023]$ matters, because $n=10.5$ is a meaningless count. The dots are the ellipsis notation of the same appendix: $3,\dots,7$ means $3,4,5,6,7$.

A *function* is a domain $D$, a codomain $Y$ and a rule. Two rules with different domains are different functions even when the formula is the same: $f(x)=x^2$ on $\mathbb R$ is not injective, but on $[0,\infty)$ it is. For a piecewise rule such as
$$m(n)=\begin{cases}\text{error}, & n<10\\ 0.02\,(n-10), & 10\le n\le1023\end{cases}$$
the branches must not overlap, together they must cover the declared domain, and each boundary point belongs to exactly one branch. Testing the boundaries $n=10$ and $n=1023$ and one value just outside each is the standard way to test such a function, which is why the lab does it.

A sum $\sum_{i=1}^{n}a_i=a_1+\dots+a_n$ uses a bound index: renaming $i$ to $k$ changes nothing, and the result does not depend on $i$ at all (VMLS, Appendix A, "Ellipsis notation"; a sum over a set $\sum_{i\in S}a_i$ adds only the listed terms). Three rules follow from commutativity and distributivity of real-number arithmetic: $\sum(a_i+b_i)=\sum a_i+\sum b_i$, $\sum c\,a_i=c\sum a_i$, and $\sum_{i=1}^{n}c=nc$. A frequent error is $\sum_{i=1}^{n}(a_i+c)=\sum a_i+c$, which forgets that the constant is added $n$ times. For a worked identity, write $S=1+2+\dots+n$ forwards and backwards; each of the $n$ column pairs adds to $n+1$, so $2S=n(n+1)$. Then $\sum_{i=1}^{n}(2i-1)=2\cdot\tfrac{n(n+1)}{2}-n=n^2$, so the sum in Exercise 3 is $4^2=16$.

Finally the equals sign and the order of operations. In mathematics $x=x+1$ is a false statement for every real $x$; in many programming languages `x = x + 1` is a valid instruction, `==` compares, and with floating-point numbers even `==` is hazardous (Exercise 14). Exponents bind tighter than a leading minus: $-3^2=-9$ but $(-3)^2=9$, and Python agrees, since `-3**2` is `-9`. When in doubt, add parentheses; they cost nothing and remove ambiguity.

**Example.** For the sensor count $n=9$, $n=10$ and $n=1023$, what does the piecewise rule above return, and which faulty implementations do these three boundary tests catch?

**Solution.** For $n=9$ the rule is "error" (below the contract). For $n=10$ it gives $0.02\cdot0=0.0$ m, and for $n=1023$ it gives $0.02\cdot1013=20.26$ m. A version that used $n>10$ would wrongly reject $n=10$, and one that used $n\le1024$ would wrongly accept $1024$; these three boundary tests would catch such an off-by-one error.

### Units and dimensional analysis: what the numbers mean

A *quantity* is a number times a unit, for example $d=14\ \mathrm{m}$. The *dimension* (length, time, mass, ...) is what the unit measures: metres, feet and kilometres are different units of one dimension. The SI fixes base units (metre, second, kilogram, ...) and derived units such as m/s or the watt, W = J/s; NIST SP 811, chapters 4 and 6, lists the units and the printing rules (a space between number and unit symbol, no plural "s" on symbols). Four rules do most of the work. First, only quantities of the same dimension can be added, compared or set equal. Second, products and quotients create new dimensions: $(\mathrm{m/s})\cdot\mathrm{s}=\mathrm{m}$. Third, the argument of $\sin$, $\exp$ or $\log$ must be dimensionless; in Python `math.sin` expects radians, so an angle given in degrees must be converted first. Fourth, a conversion factor is a fraction equal to one, such as $\frac{1000\,\mathrm{m}}{1\,\mathrm{km}}$ or $\frac{1\,\mathrm{h}}{3600\,\mathrm{s}}$ (NIST SP 811, Appendix B lists factors); multiplying by it changes the unit and not the quantity, and the units must cancel on paper.

Dimensional analysis can prove a formula wrong but never right. The candidate $d=d_0+vt^2$ has $(\mathrm{m/s})\mathrm{s}^2=\mathrm{m\,s}\ne\mathrm{m}$ and is rejected at once; the correct $d_0+vt$ passes, but so would $d_0+2vt$, since pure numbers are invisible to the check.

Some conversions are affine rather than multiplicative. NIST SP 811 defines the Celsius temperature by $t=T-T_0$ with $T_0=273.15$ K, so $T=t+273.15$: converting a temperature adds an offset, while converting a temperature *difference* does not ($10\,^\circ\mathrm C=10$ K as a difference). This ties to the next subsection: the slopes $a_i$ of the thermal model in Exercise 11 have the same value in $^\circ$C/W and K/W, but the intercept $b$ does not. It also explains why "twice as hot as $20\,^\circ$C" has no meaning: the zero of the Celsius scale is a convention, so multiplying by two is not a physical operation.

**Example.** A test cart is quoted at $90$ km/h and starts at $5$ m with $d(t)=5+vt$. Convert the speed to m/s, then find $d(12\ \mathrm s)$ both correctly and by forgetting the conversion. How large is the error? Also convert a battery at $35\,^\circ$C to kelvin.

**Solution.** The conversion is $90\cdot\frac{1000}{3600}=25$ m/s, so correctly $d(12\ \mathrm s)=5+25\cdot12=305$ m. If a program forgets to convert and uses $90$ in a formula meant for metres and seconds, $d=5+90\cdot12=1085$ m, and $1085/305\approx3.6$ times too large (close to the speed ratio $90/25=3.6$). For the battery, $35+273.15=308.15$ K.

### Linear and affine functions: superposition and the inner-product representation

The calibration $0.02(n-10)$ and the composition $px+q$ of the exercises are affine functions. Boyd and Vandenberghe (*Introduction to Applied Linear Algebra*, §2.1) give the general statement for $f:\mathbb R^n\to\mathbb R$. Call $f$ **linear** if superposition holds: $f(\alpha x+\beta y)=\alpha f(x)+\beta f(y)$ for all vectors $x,y$ and all scalars $\alpha,\beta$. Every inner product $f(x)=a^Tx$ is linear. The converse is the useful part: every linear $f$ is an inner product. Write $x=x_1e_1+\dots+x_ne_n$ with the standard unit vectors $e_i$. Multi-term superposition gives
$$f(x)=x_1f(e_1)+\dots+x_nf(e_n)=a^Tx,\qquad a=(f(e_1),\dots,f(e_n)).$$
So $n$ experiments, one per unit input, determine a linear device completely. The vector $a$ is unique: if $a^Tx=b^Tx$ for all $x$, then choosing $x=e_i$ gives $a_i=b_i$.

A function is **affine** if it is linear plus a constant, $f(x)=a^Tx+b$. Superposition then fails in general, because $f(2x)\ne 2f(x)$ when $b\ne0$, but it survives when the coefficients sum to one:
$$f(\alpha x+\beta y)=\alpha a^Tx+\beta a^Ty+(\alpha+\beta)b=\alpha f(x)+\beta f(y)\quad\text{if }\alpha+\beta=1.$$
This restricted superposition is also a test for failure. To show a function is not affine, find $x,y$ and $\alpha+\beta=1$ where it breaks. For $f(x)=\max(x_1,x_2)$ take $x=(1,-1)$, $y=(-1,1)$, $\alpha=\beta=\tfrac12$: then $f(\alpha x+\beta y)=0$ but $\alpha f(x)+\beta f(y)=1$. Two consequences for this lesson. First, a one-dimensional affine calibration is fixed by two measurements (a straight line through two points), and any third point is a check, not new information. Second, in $\mathbb R^n$ you need $n+1$ measurements at points that do not lie in a common lower-dimensional flat. The extrapolation $2x-y$ has coefficients $2$ and $-1$, which sum to one, so an affine model predicts it from the data at $x$ and $y$; a point whose coefficients do not sum to one is not determined by those two values alone.

**Example.** A calibration of a distance sensor is measured at two counts: $n=10$ gives $0$ m and $n=110$ gives $2$ m. What must an affine model predict at $n=60=\tfrac12\cdot10+\tfrac12\cdot110$ and at $n=210=2\cdot110-1\cdot10$ (coefficients $2,-1$, sum one), and do these agree with $0.02(n-10)$?

**Solution.** An affine map preserves combinations whose coefficients sum to one. For $n=60$: $\tfrac12\cdot0+\tfrac12\cdot2=1.0$ m. For $n=210$: $2\cdot2-1\cdot0=4.0$ m. Both agree with $0.02(n-10)$: $0.02\cdot50=1.0$ and $0.02\cdot200=4.0$.

### When does an inverse exist, and what is the inverse of a composition?

Section 3.8 of OpenStax *Precalculus 2e* states that a function needs to be one-to-one to have an inverse. Here is the complete argument. Let $f:D\to Y$. Call $f$ **injective** if $f(x_1)=f(x_2)$ implies $x_1=x_2$. Call it **onto its range** $R=f(D)$ always, and **surjective** onto $Y$ if $R=Y$. Claim: a function $g:R\to D$ with $g(f(x))=x$ for all $x\in D$ exists if and only if $f$ is injective. If $f$ is injective, define $g(y)$ as the unique $x$ with $f(x)=y$; uniqueness is exactly injectivity. Conversely, if $g$ exists and $f(x_1)=f(x_2)$, apply $g$ to both sides to get $x_1=x_2$. Two practical tests follow. A strictly increasing function is injective, because $x_1<x_2$ forces $f(x_1)<f(x_2)$; the affine calibration with slope $0.02>0$ is therefore invertible on its whole domain, and its inverse is also strictly increasing. A sensor with hysteresis (the same reading for two different physical inputs) is not injective, so no inverse function exists without more information such as the direction of travel.

For compositions, suppose $f:D\to E$ and $h:E\to Y$ are both injective with $h$ defined on all of $E$. Then $h\circ f$ is injective: $h(f(x_1))=h(f(x_2))$ gives $f(x_1)=f(x_2)$ by injectivity of $h$, hence $x_1=x_2$. Its inverse is
$$(h\circ f)^{-1}=f^{-1}\circ h^{-1},$$
because $f^{-1}(h^{-1}(h(f(x))))=f^{-1}(f(x))=x$: undo the last step first, as when you take off shoes before socks. For affine maps $f(x)=ax+b$ and $h(x)=cx+d$ with $a,c\ne0$, this reproduces $f^{-1}(y)=(y-b)/a$ and $(h\circ f)(x)=cax+(cb+d)$, so its inverse is $(y-cb-d)/(ca)$. A slope of zero destroys injectivity: $f(x)=0\cdot x+b$ sends every input to $b$.

**Example.** Take $g(x)=3x-5$. Which input gives the output $7$, and is $g$ invertible? Compare with $x^2=4$. For the two sensor-correction steps $g(x)=3x-4$ and $f(x)=2x+1$, find the pipeline $f\circ g$ and the input that produces the output $23$.

**Solution.** The output $7$ came from $x=(7+5)/3=4$ (check: $3\cdot4-5=7$), and every output has exactly one such input, so $g$ is invertible. By contrast $x^2=4$ is answered by both $x=2$ and $x=-2$, so squaring is not invertible. The pipeline is $f(g(x))=2(3x-4)+1=6x-7$; for output $23$, undo the last step first: $f^{-1}(23)=(23-1)/2=11$, then $g^{-1}(11)=(11+4)/3=5$, and indeed $6\cdot5-7=23$.

### First-order models and where to trust them

Most real sensor curves are not affine, but locally they are almost so. For a differentiable $f:\mathbb R^n\to\mathbb R$ the first-order Taylor approximation at $z$ is (Boyd and Vandenberghe, §2.2)
$$\hat f(x)=f(z)+\nabla f(z)^T(x-z).$$
It is affine in $x$, it agrees with $f$ at $z$, and its error is small only for $x$ near $z$. The gradient entries carry units: if $f$ is in watts and $x_i$ in volts then $\partial f/\partial x_i$ is in W/V, which is why $\hat f$ is dimensionally consistent. As a second harder case, take $f(x)=x_1^2/x_2$ near $z=(12,4)$. Then $\nabla f(z)=(2z_1/z_2,\,-z_1^2/z_2^2)=(6,-9)$ and $f(z)=36$. The model is exact along the ray through $z$ (because $f(sz)=sf(z)$ and $\nabla f(z)^Tz=36=f(z)$), and increasingly wrong as you move across the ray. The lesson for engineering: quote the region where the affine model was validated, just as the calibration quotes its count range.

**Example.** For $f(V,R)=V^2/R$ near $z=(12,4)$ the model is $\hat f=36+6(V-12)-9(R-4)$ W. What do the model and the true value give for $V=12.5$ V at fixed $R=4\ \Omega$, and what does the model give at $6$ V and $8\ \Omega$?

**Solution.** At $12.5$ V and $4\ \Omega$: $\hat f=36+6\cdot0.5=39$ W while the true value is $12.5^2/4=39.0625$ W, an error of $0.0625$ W (0.16%). At $6$ V and $8\ \Omega$: $\hat f=36+6(-6)-9(4)=-36$ W (the true value is $36/8=4.5$ W). A negative power in a resistor is a clear sign the model left its validated region.

## Worked example

### Case 1: a cart at constant speed (the basic case)

**Problem.** A cart starts $d_0=2$ m from a reference mark and drives away at the constant speed $v=3$ m/s. How far from the mark is it after $t=4$ s?

**Solution.**
1. Name the quantities with their units: start $d_0=2$ m, speed $v=3$ m/s, time $t=4$ s. The unknown is the distance $d(4)$ in metres.
2. Choose the model. Constant speed means $v=\Delta d/\Delta t$ (Theory and derivation). Multiplying by $\Delta t$ gives $\Delta d=v\,\Delta t$, and "new distance = start + change" gives $d(t)=d_0+vt$. Assumptions: the speed never changes and $t\ge0$ counts from the start.
3. Check the units before any number goes in: $[v][t]=(\mathrm{m/s})\cdot\mathrm{s}=\mathrm m$, the same unit as $d_0$, so the two terms may be added.
4. Substitute: $d(4)=2\ \mathrm m+(3\ \mathrm{m/s})(4\ \mathrm s)$.
5. Multiply first (multiplication binds tighter than addition): $(3\ \mathrm{m/s})(4\ \mathrm s)=12$ m; the seconds cancel.
6. Add: $2\ \mathrm m+12\ \mathrm m=14$ m.

**Check.** Count second by second: $t=0,1,2,3,4$ gives $2,5,8,11,14$ m, each second adds $3$ m. The unit of the answer is metres, as it must be. Adding before multiplying would give $(2+3)\cdot4=20$, which is wrong and has no unit meaning. In Python, `distance(4)` in the reference implementation returns `14.0`.

**Takeaway.** Write the model from the definition, check the units, then do the arithmetic in the right order.

### Case 2: evaluating $f(x)=2x^2-1$ and the lost parentheses

**Problem.** Let $f(x)=2x^2-1$. Compute $f(-3)$, $f(0)$ and $f(\tfrac12)$, and explain which mistake gives $-19$ for $f(-3)$.

**Solution.**
1. A function is a rule: replace every $x$ by the input, keeping the input in parentheses: $f(-3)=2(-3)^2-1$.
2. Apply the order of operations (exponent, then multiplication, then subtraction). Exponent: $(-3)^2=(-3)(-3)=9$.
3. Multiply: $2\cdot9=18$.
4. Subtract: $18-1=17$, so $f(-3)=17$.
5. Same steps for the others: $f(0)=2\cdot0-1=-1$ and $f(\tfrac12)=2\cdot\tfrac14-1=-\tfrac12$.
6. The wrong value: dropping the parentheses reads $-3^2$ as $-(3^2)=-9$, then $2(-9)-1=-19$.

**Check.** Since $x^2$ gives the same value for $x=3$ and $x=-3$, $f(3)$ must equal $f(-3)$: $2\cdot9-1=17$. Python confirms: `2*(-3)**2-1` is `17`, while `2*-3**2-1` is `-19`.

**Takeaway.** Substitute the input in parentheses, then follow the order of operations; the same $f$ giving $17$ at both $\pm3$ is why $x^2$ has no inverse on all of $\mathbb R$.

### Case 3 (harder): a calibrated distance sensor, evaluated, inverted and checked against its domain

**Problem.** A sensor returns an integer count $n\in\{10,\dots,1023\}$ and the calibration is $m(n)=0.02\,(n-10)$ metres. (a) Evaluate $m(60)$, $m(110)$ and $m(1023)$. (b) A log shows the distance $1.38$ m; which count produced it? (c) A log shows $25.0$ m; is this possible? (d) The logger stores centimetres, $g(m)=100\,m$. Find the formula and the inverse of the stored value $s=g(m(n))$, and the count for the stored value $138$ cm.

**Solution.**
1. (a) Substitute into the affine rule, subtracting 10 first: $m(60)=0.02\cdot50=1.0$ m; $m(110)=0.02\cdot100=2.0$ m; $m(1023)=0.02\cdot1013=20.26$ m. These are the three tests the lab uses.
2. (b) The slope $0.02>0$, so $m$ is strictly increasing and therefore injective: the inverse exists (Theory, inverse subsection). Solve $m=0.02(n-10)$ for $n$: $n=10+m/0.02=10+50m$.
3. Substitute $m=1.38$ m: $n=10+50\cdot1.38=10+69=79$. The count is an integer inside the domain, so the reading is plausible.
4. (c) Apply the same inverse to $25.0$ m: $n=10+50\cdot25=1260>1023$. No valid count produces $25.0$ m, because the largest distance is $m(1023)=20.26$ m. The log value is outside the contract and must be rejected or investigated, not silently accepted.
5. (d) Compose: $s(n)=g(m(n))=100\cdot0.02(n-10)=2(n-10)=2n-20$ cm. Solving $s=2n-20$ gives $n=(s+20)/2$. The rule $(g\circ m)^{-1}=m^{-1}\circ g^{-1}$ gives the same: $g^{-1}(138)=1.38$ m, then $m^{-1}(1.38)=79$.
6. Substitute $s=138$: $n=(138+20)/2=79$. The stored values are the even integers $0,2,\dots,2026$, so an odd value such as $139$ cm cannot come from this sensor.

**Check.** Forward again: $m(79)=0.02\cdot69=1.38$ m and $s(79)=2\cdot79-20=138$ cm, so both routes round-trip. In floating point, `0.02*(79-10)` prints `1.3800000000000001`, so in code the inverse should return `round(10 + m/0.02)` and compare with a tolerance (Exercise 14).

**Takeaway.** Evaluate, invert with the right order for compositions, and always test the answer against the declared domain.

(d) On the segment $x=(12+t,4-t)$: $f=(12+t)^2/(4-t)$ and $\hat f=36+6t+9t=36+15t$. The error is $f-\hat f=\frac{(12+t)^2-(36+15t)(4-t)}{4-t}=\frac{144+24t+t^2-144-24t+15t^2}{4-t}=\frac{16t^2}{4-t}$. Since $4-t>0$ near $z$, the error is positive and the condition $16t^2/(4-t)<1$ becomes $16t^2+t-4<0$, whose roots are $t=-0.5322$ and $t=0.4697$ (computed). So $|f-\hat f|<1$ W exactly for $-0.53<t<0.47$ (to two decimals; the interval is asymmetric because the denominator $4-t$ shrinks for positive $t$).
14. (a) The loop gives `0.9999999999999999`, so `s == 1.0` is `False` while `math.isclose(s, 1.0)` is `True`. Reason: $0.1$ is stored as the nearest binary fraction, not $1/10$, and the ten small errors do not cancel. (b) `bad(n)` fails for 71 counts in $10\le n\le1023$; the smallest is $n=39$, where `calib(39)/0.02` is `28.999999999999996`; `int` truncates it to 28, giving 38. (c) `round` fixes every count: 0 failures out of 1014. A version with `int(x + 1e-9)` also gives 0 failures. (d) Store the distance in integer millimetres, $20(n-10)$, so that the inverse is the exact integer division $\text{mm}//20+10$; the price is a fixed resolution of 1 mm and a unit conversion at the display boundary. Integers never need a tolerance, but the unit is now baked into the data type, so mistakes shift from rounding to unit confusion.
15. (a) $\int_0^2x^k\,dx=2^{k+1}/(k+1)$ for $k=0,1,2,3$, so $a=(2,\,2,\,\tfrac83,\,4)$. (b) $p'(x)=c_2+2c_3x+3c_4x^2$, so $p'(1)=c_2+2c_3+3c_4$ and $b=(0,1,2,3)$. (c) $p(x_0)=c_1+c_2x_0+c_3x_0^2+c_4x_0^3=(1,x_0,x_0^2,x_0^3)^Tc$, an inner product, hence linear in $c$. Horner's rule evaluates this inner product with fewer multiplications. (d) Take $c=e_1$, so $p=1$ and the functional equals $\int_0^21\,dx=2$. For $c=2e_1$, $p=2$ and the value is $\int_0^24\,dx=8$, but superposition would require $2\cdot2=4$. So it is not linear (it is quadratic in $c$).
