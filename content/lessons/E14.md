## Why this matters

A language model can write a convincing plan for "put the red block on the blue block": pick up the red block, move it over the blue one, release. Whether that plan *works* depends on facts the text does not contain: is something on top of the red block, is the blue block reachable, is the gripper already holding something? Embodied reasoning is the discipline of connecting plans to observed state and to the consequences of actions, so that a plan is checked against the world, repaired when the world differs, and updated when execution does not go as predicted.

The practical payoff is robustness to scene change. People move objects; detectors miss things; grasps slip. A robot that can say "step 3 is no longer valid because block B is covered" and fix the plan will outperform one that blindly replays the old sequence, and will fail more informatively.

## Intuition

A plan is a small program whose steps share state. Each step has **preconditions** (what must be true for it to work) and **effects** (what it changes). Step 2 can rely on step 1 only because step 1 *made* something true, such as "the gripper is holding the red block". That producer-consumer relation is a **causal link**. Any event that destroys the produced fact between producer and consumer is a **threat**.

![A four-step blocks-world plan with causal links between steps, and a scene change (block D placed on B) that breaks the precondition of the last step; execution feedback compares predicted and observed facts.](/lesson-figures/E14.svg)

*Steps are connected by the facts they produce. A scene change that removes a needed fact invalidates the consumer step and everything after it.*

Three questions drive the whole topic.

1. **Grounding:** do the symbols in the plan ("block B", "clear") correspond to what the cameras actually show, and how sure are we?
2. **Causal structure:** which steps depend on which, so that after a change we redo only what is needed?
3. **Feedback:** after acting, does the observed state match the predicted state, and if not, what is the difference?

## Theory and derivation

### States, actions, validity

Represent the world as a set of ground facts, for example
`on(C,A), ontable(A), ontable(B), clear(C), clear(B), handempty`. An action $a$ has a precondition set $\mathrm{pre}(a)$, an add set $\mathrm{add}(a)$ and a delete set $\mathrm{del}(a)$. It is applicable in state $s$ if $\mathrm{pre}(a)\subseteq s$, and its result is
$$s'=(s\setminus\mathrm{del}(a))\cup\mathrm{add}(a).$$
A plan $a_1,\dots,a_n$ is **valid from $s_0$** if each $a_i$ is applicable in $s_{i-1}$ where $s_i$ is the result of $a_i$, and it is a **solution** if $s_n$ contains the goal facts. The first index $i$ at which the plan stops being applicable is the **first invalid step**.

### Causal links and threats

A causal link $a_i\xrightarrow{f}a_j$ ($i<j$) means $a_i$ adds a fact $f$ that $a_j$ needs and $f$ is not removed in between. A step $a_k$ with $i<k<j$ is a **threat** to the link if $f\in\mathrm{del}(a_k)$. After a scene change that removes a fact $f$ from the initial state, every step that needs $f$ (directly from the initial state) is invalid; the steps that depend on those steps' effects are invalid too. Keeping the link structure lets you redo only the affected suffix or sub-plan.

### Grounding uncertainty

Each fact comes from perception with confidence $c_f$. If a plan depends on $m$ independently perceived facts, the probability that all are correct is
$$P(\text{plan grounded correctly})=\prod_{f}c_f .$$
Twelve facts at 0.97 each give $0.97^{12}=0.694$: perception errors alone invalidate roughly one plan in three. The same product applies to scene changes: if each precondition fact changes independently with probability $\epsilon$ before execution, the plan survives with probability $(1-\epsilon)^m$.

### Execution feedback

After each step compare the **predicted** state $\hat s_i$ with the **observed** state $o_i$. The informative quantities are the sets $\hat s_i\setminus o_i$ (predicted but not seen: the action did not do what we expected) and $o_i\setminus\hat s_i$ (seen but not predicted: something unexpected happened). Language-model planners can use these as text feedback (Inner Monologue); symbolic planners use them to trigger replanning from the observed state.

### Intervention versus observation

Observing that an object is lifted whenever the gripper is closed is a correlation; to *make* the object lift you must **intervene** on the gripper. A reasoner that confuses the two will cause wrong plans, for example "the lamp is on whenever the light switch is up, so jiggling the lamp will turn it on." Causal structure tells which variables can be set directly (gripper command) and which are consequences (object position).

## Worked example

Blocks world. Initial state $s_0$: `on(C,A)`, `ontable(A)`, `ontable(B)`, `clear(C)`, `clear(B)`, `handempty`. Goal: `on(A,B)`. Plan:

1. `unstack(C,A)` needs `on(C,A), clear(C), handempty`. Adds `holding(C), clear(A)`.
2. `putdown(C)` needs `holding(C)`. Adds `ontable(C), clear(C), handempty`.
3. `pickup(A)` needs `ontable(A), clear(A), handempty`. Adds `holding(A)`.
4. `stack(A,B)` needs `holding(A), clear(B)`. Adds `on(A,B), clear(A), handempty`.

**Validity from $s_0$.** Step 1: all three preconditions hold. After it, $s_1$ contains `holding(C)`, `clear(A)`, and no `handempty`. Step 2: applicable. Step 3 needs `clear(A)` (produced by step 1, link $a_1\xrightarrow{\text{clear(A)}}a_3$) and `handempty` (produced by step 2, link $a_2\to a_3$): both hold. Step 4 needs `holding(A)` (step 3) and `clear(B)` (from $s_0$). The plan is valid and reaches `on(A,B)`.

**Scene change.** Before execution a person places block D on B: the true state has `on(D,B)`, `clear(D)` and *not* `clear(B)`. Simulating the old plan from the new state: steps 1-3 stay applicable, so the validator returns **index 3 (step 4)**: `clear(B)` is missing. The robot would have moved C and A before discovering the failure; simulation before execution catches it without moving anything.

**Repair.** Breadth-first search from the new state finds a shortest plan of six steps, for example `unstack(D,B)`, `putdown(D)`, `unstack(C,A)`, `putdown(C)`, `pickup(A)`, `stack(A,B)` (BFS guarantees the length, not this particular order). The causal-link view shows that old steps 1-4 are reused unchanged and two steps are added at the front, rather than discarding everything.

**Feedback.** Suppose after `putdown(C)` the camera shows C resting on B instead of the table. Predicted $\hat s_2$ contains `ontable(C)`; observed contains `on(C,B)`. The difference is missing $=\{\text{ontable(C)}\}$, extra $=\{\text{on(C,B)}\}$ (and `clear(B)` would also be absent). That text tells the planner exactly which fact is wrong.

**Grounding arithmetic.** The plan reads five externally observed facts from $s_0$ (on(C,A), clear(C), handempty, ontable(A), clear(B)); the holding facts are produced internally. With detection confidence 0.97 per fact, $0.97^5=0.859$ is the probability that all five are grounded correctly.

## Reference implementation

The validator core; breadth-first `find_plan` is part of the lab below.

```python
def pre_add_del(a):
    k = a[0]
    if k == 'pickup':
        x = a[1]; return ({('ontable', x), ('clear', x), ('handempty',)}, {('holding', x)},
                          {('ontable', x), ('clear', x), ('handempty',)})
    if k == 'putdown':
        x = a[1]; return ({('holding', x)}, {('ontable', x), ('clear', x), ('handempty',)}, {('holding', x)})
    if k == 'stack':
        x, y = a[1], a[2]; return ({('holding', x), ('clear', y)}, {('on', x, y), ('clear', x), ('handempty',)},
                                   {('holding', x), ('clear', y)})
    x, y = a[1], a[2]    # unstack
    return ({('on', x, y), ('clear', x), ('handempty',)}, {('holding', x), ('clear', y)},
            {('on', x, y), ('clear', x), ('handempty',)})

def applicable(s, a): return pre_add_del(a)[0] <= s
def apply(s, a):
    _, add, dele = pre_add_del(a)
    return frozenset((s - dele) | add)

def first_invalid_step(s, plan):
    for i, a in enumerate(plan):
        if not applicable(s, a): return i
        s = apply(s, a)
    return None

if __name__ == "__main__":
    S0 = frozenset({('on', 'C', 'A'), ('ontable', 'A'), ('ontable', 'B'), ('clear', 'C'), ('clear', 'B'), ('handempty',)})
    plan = [('unstack', 'C', 'A'), ('putdown', 'C'), ('pickup', 'A'), ('stack', 'A', 'B')]
    print(first_invalid_step(S0, plan))                                    # None
    S1 = (S0 - {('clear', 'B')}) | {('on', 'D', 'B'), ('clear', 'D')}
    print(first_invalid_step(S1, plan))                                    # 3
    # --- self-test ---
    assert first_invalid_step(S0, plan) is None and first_invalid_step(S1, plan) == 3
    assert first_invalid_step(S0, []) is None
    print("self-test passed")
```

### Extension challenge

Add a causal-link extractor that returns all triples $(i,f,j)$ of a valid plan and a threat checker. Use it to find, for each possible single-fact removal from $s_0$, which plan steps become invalid, and compare against re-simulating the plan.

## Verification

- **Re-simulate by hand** the first three steps of any plan you test; each step's preconditions must be listed explicitly.
- **Differential test:** the first invalid step found with causal links must equal the one found by simulation.
- **Baseline:** blindly replaying the old plan on the changed scene; report how many steps execute before failure.
- **Check the goal separately:** a plan can be fully applicable yet not reach the goal; test `goal <= final_state`.
- **Compare predicted and observed state after every real step** and log the sets $\hat s\setminus o$ and $o\setminus\hat s$.

## Failure modes

| Mistake | Wrong result |
|---|---|
| Forgetting to delete `handempty` on pickup | the model allows picking up two blocks at once |
| Validating only the first step | scene change at step 4 detected after three physical moves |
| Treating grounded facts as certain | $0.97^{12}=0.69$ plan validity ignored |
| Plans from text only | steps like "grab the cup" with a covered cup pass reading but fail simulation |
| Replanning from the old predicted state instead of the observed state | repeats the same failure |
| Confusing correlation with intervention | wrong belief that moving the effect causes the cause |

## Alternatives and trade-offs

- **Classical symbolic planning** (PDDL, BFS or heuristic search): exact and checkable, needs a hand-built domain model and reliable perception.
- **Language-model planning**: flexible and open-vocabulary, but not guaranteed valid; pair it with a simulator, affordance scores (SayCan) or feedback (Inner Monologue).
- **Learned world models** (E08): predict consequences without symbolic rules, but errors are harder to inspect.
- **Behaviour trees and finite-state machines**: explicit recovery branches, predictable, labour-intensive.
- **Full replanning versus plan repair**: replanning from scratch is simple and optimal in length; repair reuses work but can be locally suboptimal.
