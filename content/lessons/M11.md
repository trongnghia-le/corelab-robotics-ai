## Why this matters

A robot's code never works with real numbers; it works with 64-bit (or 32-bit) approximations, and every arithmetic operation rounds. Most of the time this is invisible. It becomes a real bug when you subtract nearly equal numbers (two encoder readings, two timestamps), accumulate millions of tiny increments (odometry, integration), or solve a system whose answer is hypersensitive to its inputs (calibration, least-squares fits, inverse kinematics near a singularity). The skill of this lesson is to separate three different causes of a wrong digit: the **problem** is sensitive (conditioning), the **algorithm** amplifies rounding (instability), or the **inputs** were already wrong (data error). Only the first two are numerical computing; all three produce the same symptom.

## Intuition

Doubles are like a ruler whose tick marks get sparser as numbers grow. Near 1 the ticks are $2.2\times10^{-16}$ apart; near $10^{16}$ they are 2 apart, so $10^{16}+1$ is the same number as $10^{16}$. Each operation snaps its exact result to the nearest tick. That is a tiny relative error, about $10^{-16}$, and usually harmless.

Conditioning is a property of the question, not the code. Intersecting two lines that are almost parallel is hard: moving one line by a hair slides the intersection far away. An algorithm cannot repair that, because the data you gave it (already rounded to doubles) define a slightly different problem.

A concrete case: a robot stamps every camera frame with the Unix time, about $1.7\times10^9$ s. A double near that value sits on a grid with spacing $2^{-22}=0.24\,\mu$s, so the stamp is good to a quarter of a microsecond, plenty for a 30 Hz camera. Store the same stamp in float32 and the spacing near $1.7\times10^9$ becomes 128 s: two frames a minute apart can receive the same time. Nothing is wrong with the arithmetic; the format simply has too few ticks at that magnitude. The same robot, asked to find where two almost parallel walls meet, shows the other failure: the double stamps are fine, but the question amplifies whatever error the measured wall angles carry.

**Predict before you compute.** In double precision, what do `1.7e9 + 1e-7 - 1.7e9` and `1.7e9 + 2e-7 - 1.7e9` return? Decide before reading on: half the spacing is $0.12\,\mu$s, so the first correction (0.1 $\mu$s) rounds away and returns `0.0`, while the second (0.2 $\mu$s) rounds to one full grid step and returns $2.38\times10^{-7}$, not $2\times10^{-7}$. Then decide, for the nearly parallel walls, how large the intersection shift is when one wall moves by 1 mm and the walls meet at $0.01$ rad: about $1\text{ mm}/0.01=10$ cm.

**The common wrong intuition.** Two beliefs cause most numerical bugs. The first is "the computer prints 16 digits, so the answer has 16 correct digits"; printed digits only report the stored number, while the number of correct digits depends on the conditioning of the question. The second is "rounding errors are random and average out"; rounding is deterministic, and in a long sum the same small increment can be lost every single time, so the error piles up in one direction. A third, quieter belief is that a tiny residual certifies the answer; the worked example shows a residual of $3.5\times10^{-5}$ attached to an answer with no correct digit. When a number looks wrong, ask three questions in order: was the input already wrong (data error), does the question amplify small changes (conditioning), or does my formula amplify rounding that a better formula would avoid (stability)?

## Theory and derivation

### Floating point

A double stores a sign, 52 fraction bits and an 11-bit exponent: $x=\pm(1.f)_2\times2^e$. The gap between 1 and the next double is machine epsilon $\varepsilon=2^{-52}\approx2.22\times10^{-16}$ (float32: $2^{-23}\approx1.19\times10^{-7}$). Rounding to nearest gives unit roundoff $u=\varepsilon/2$ and the standard model

$$\mathrm{fl}(a\circ b)=(a\circ b)(1+\delta),\quad |\delta|\le u,\quad \circ\in\{+,-,\times,\div\}.$$

Consequences: addition is not associative; `0.1+0.2 != 0.3` because none of the three is exactly representable; and for $|x|\in[2^e,2^{e+1})$ the spacing is $2^{e-52}$ (double) or $2^{e-23}$ (float32).

**Cancellation.** Subtraction itself is exact when the operands are close (Sterbenz), but if the operands carry rounding errors, those errors are now large relative to the small difference. If $a$ and $b$ have relative error $u$ and $a-b$ is $10^{-k}$ of $a$, the relative error of $a-b$ is about $10^{k}u$: $k$ digits lost.

**Absorption.** $a+b$ with $|b|<u|a|$ returns $a$. Summing a million terms of size $h$ into a total near $S$ loses $h$ whenever $h<uS$.

The exponent field also encodes the exceptional values: $\pm\infty$ (overflow beyond about $1.8\times10^{308}$, or a non-zero number divided by zero), NaN (the result of $0/0$ or $\infty-\infty$, the only value that compares unequal to itself, so test it with `math.isnan`) and subnormal numbers below $2.2\times10^{-308}$, which give up precision to fill the gap near zero gradually (NumPy docs, `numpy.finfo`: `max`, `tiny`, `eps`). Away from these extremes the model above holds.

**Example.** A camera driver stamps frames with the Unix time $t=1.7\times10^{9}$ s in double precision. What is the spacing of representable stamps, what happens to corrections of 0.1 $\mu$s and 0.2 $\mu$s, and what is the spacing in float32?

**Solution.** Here $2^{30}\le t<2^{31}$, so $e=30$ and the spacing is $2^{30-52}=2^{-22}=2.38\times10^{-7}$ s. A correction of 0.1 $\mu$s is below half of that and vanishes (`1.7e9 + 1e-7 == 1.7e9` is `True`); a correction of 0.2 $\mu$s moves the stamp by one full step, $2.38\times10^{-7}$ s, not 0.2 $\mu$s. The same stamp in float32 has spacing $2^{30-23}=128$ s.

### Absolute and relative error; forward and backward error

For a computed $\hat y$ approximating $y=f(x)$: absolute error $|\hat y-y|$, relative error $|\hat y-y|/|y|$. **Forward error** compares outputs. **Backward error** asks: for which perturbed input $\hat x$ is $\hat y=f(\hat x)$ exact? A **backward stable** algorithm returns the exact answer to a problem with inputs perturbed by $O(u)$, which is the best you can ask, since the inputs were rounded anyway.

**Example.** A calculator returns $\hat y=1.4142$ for $y=\sqrt2$. Find the forward and the backward error and relate them.

**Solution.** The forward error is $|\hat y-y|=1.36\times10^{-5}$, relative $9.6\times10^{-6}$. For the backward view, $\hat y^2=1.99996164$, so $\hat y$ is the *exact* square root of $\hat x=1.99996164$, an input that differs from 2 by a relative $1.9\times10^{-5}$. The forward relative error is half the backward one, as it must be for a function with condition number $1/2$ (next subsection): forward $\approx\kappa\times$ backward.

### Conditioning

The relative condition number of $f$ at $x$ measures the worst amplification of a relative input perturbation:

$$\kappa_f(x)=\left|\frac{x f'(x)}{f(x)}\right|.$$

Rule of thumb: you lose about $\log_{10}\kappa$ digits no matter what algorithm you use. Examples: $\sqrt x$ has $\kappa=1/2$ (benign); $x-1$ at $x=1.0001$ has $\kappa=|1.0001/0.0001|\approx10^4$.

For $Ax=b$ the condition number is $\kappa(A)=\|A\|\,\|A^{-1}\|\ge1$. It equals the ratio of the largest to smallest singular value in the 2-norm. Perturbing $b$ gives $\|\delta x\|/\|x\|\le\kappa(A)\,\|\delta b\|/\|b\|$.

**Example.** A heading of $1.57$ rad ($89.95^\circ$) is passed to $\tan$. Find the condition number of $\tan$ there, the effect of a relative input error of $10^{-8}$, and the number of digits lost.

**Solution.** With $f=\tan$, $f'=1/\cos^2$ and $\kappa=|xf'/f|=x/(\sin x\cos x)=1971.6$. A relative input error of $10^{-8}$ therefore changes the output by a relative $1.97\times10^{-5}$ (checked numerically: $1.9716\times10^{-5}$), and $\log_{10}1972=3.3$ digits are lost whatever algorithm computes $\tan$. A heading from an encoder near $90^\circ$ is a poor place to divide by $\cos$.

### Residual versus error

Let $\hat x$ be a computed solution and $r=b-A\hat x$ its residual. Then $A(x-\hat x)=r$, so $\|x-\hat x\|\le\|A^{-1}\|\|r\|$, and $\|b\|\le\|A\|\|x\|$. Dividing,

$$\frac{\|x-\hat x\|}{\|x\|}\le\kappa(A)\,\frac{\|r\|}{\|b\|}.$$

Gaussian elimination with partial pivoting is backward stable in practice, so $\|r\|/\|b\|\approx u$ and the error is about $\kappa(A)u$. **A tiny residual says the algorithm worked; it says nothing about the error unless $\kappa$ is small.**

**Example.** Take the Hilbert matrix $H_5$ ($H_{ij}=1/(i+j+1)$, $i,j=0,\dots,4$), $\kappa_2=4.77\times10^{5}$, and $b=H_5\mathbf 1$ so the true solution is all ones. LAPACK (`np.linalg.solve`) returns $\hat x$ with relative residual $8.7\times10^{-17}$. What relative error does the bound $\kappa_2\times$residual allow, and how does it compare with the actual error?

**Solution.** The bound gives relative error $\le4.77\times10^5\times8.7\times10^{-17}=4.1\times10^{-11}$; the observed error is $1.7\times10^{-12}$. The bound holds with room to spare, and the lesson is the order of magnitude: about six digits of this answer are at risk although the residual is at rounding level.

### Scale and least squares

For a fit with design matrix $X$, the normal equations $X^TXc=X^Ty$ have $\kappa(X^TX)=\kappa(X)^2$: squaring the condition number doubles the digits lost. Badly scaled columns (a column of ones next to a column of 1.7e9) inflate $\kappa(X)$ itself. Centering and scaling the columns changes the *parameterization*, not the fitted curve, but can reduce $\kappa$ from $10^{18}$ to about 3.

**Example.** A fit uses times $t_i=1000+i$ s, $i=0,\dots,9$, and $y_i=3+0.5\,i$ (so $y=-497+0.5\,t$). Find $\kappa(X)$ and $\kappa(X^TX)$ for the columns $(1,t)$, say whether the normal equations still recover the fit, and what centering the time changes.

**Solution.** The columns $(1,t)$ give $\kappa(X)=3.5\times10^{5}$ and $\kappa(X^TX)=1.2\times10^{11}$; the normal equations still recover slope $0.5$ to $2\times10^{-12}$ and intercept $-497$ to $2\times10^{-9}$, because $\kappa^2u\approx10^{-5}$ is only an upper bound here. Subtract the mean time (centering) and $\kappa(X)$ drops to $2.87$. With the origin at $1.7\times10^9$ s instead (Exercise 7), $\kappa(X)=10^{18}$ and nothing survives.

### Summation error: the naive loop, pairwise and compensated sums

Let $\hat s_k=\mathrm{fl}(\hat s_{k-1}+x_k)=(\hat s_{k-1}+x_k)(1+\delta_k)$ with $|\delta_k|\le u$ and $\hat s_1=x_1$. Unrolling the recursion, each $x_i$ is multiplied by every rounding factor from its own addition onward:

$$\hat s_n=\sum_{i=1}^n x_i\prod_{k=\max(i,2)}^{n}(1+\delta_k).$$

A product of $j$ factors $(1+\delta_k)$ equals $1+\theta_j$ with $|\theta_j|\le (1+u)^j-1=ju+O(u^2)$. Early terms pass through $n-1$ additions, so

$$|\hat s_n-s_n|\le\big((n-1)u+O(u^2)\big)\sum_{i=1}^n|x_i|.$$

This is a worst-case bound on the error relative to $\sum|x_i|$ (not to $|s_n|$: if the terms cancel, the relative error of the result can still be large, which is the cancellation of the previous section). It grows linearly in $n$ because the running total is large and every new term is rounded onto its coarse grid. Two classical remedies reduce the growth. **Pairwise (divide-and-conquer) summation** adds the two halves recursively, so every term passes through only $\lceil\log_2 n\rceil$ additions and the bound becomes $\log_2(n)\,u\sum|x_i|$ (you prove this in Exercise 11). NumPy's `np.sum` uses a blocked form of it. **Compensated summation** (Kahan) carries the rounding error of each addition in a second variable and feeds it back; `math.fsum` goes further and keeps exact partial sums, returning the correctly rounded sum of the stored doubles (Python docs, `math.fsum`). Source for the pairwise formulation: MIT 18.335J, Spring 2019, Problem Set 1, Problem 4.

**Example.** A float32 odometer adds $10^{6}$ increments of 0.1 m. What total does a sequential float32 loop return compared with the exact sum, why, and what does pairwise summation give?

**Solution.** The exact total of the stored increments is $100\,000.0015$ m. The sequential float32 loop returns $100\,958.34$ m, an error of 958 m (0.96 %): near a total of $10^{5}$ m the float32 spacing is $2^{16-23}=0.0078$ m, so every addition of 0.1 m is rounded to that grid and the (here one-sided) rounding errors accumulate. `np.sum` with pairwise summation returns $100\,000.01$ m. The bound $(n-1)u\sum|x_i|$ is far larger than either error, but its linear-in-$n$ shape matches what the sequential loop does.

### Backward error of a computed solution and the forward bound

Given a computed $\hat x$ for $Ax=b$ with residual $r=b-A\hat x$, ask for the smallest perturbation $\delta A$ such that $\hat x$ solves $(A+\delta A)\hat x=b$ exactly. Any such $\delta A$ satisfies $\delta A\,\hat x=r$, hence $\|\delta A\|_2\ge\|r\|_2/\|\hat x\|_2$. The rank-one matrix

$$\delta A=\frac{r\,\hat x^{T}}{\hat x^{T}\hat x}$$

attains this value ($\delta A\,\hat x=r\,\hat x^T\hat x/\hat x^T\hat x=r$, and $\|\delta A\|_2=\|r\|_2\|\hat x\|_2/\|\hat x\|_2^2$). So the (normwise, matrix-only) backward error is

$$\eta(\hat x)=\frac{\|\delta A\|_2}{\|A\|_2}=\frac{\|r\|_2}{\|A\|_2\|\hat x\|_2}.$$

Now close the loop with conditioning: from $(A+\delta A)\hat x=b=Ax$ we get $A(x-\hat x)=\delta A\,\hat x$, hence $\|x-\hat x\|\le\|A^{-1}\|\|\delta A\|\|\hat x\|$ and

$$\frac{\|x-\hat x\|}{\|\hat x\|}\le\kappa_2(A)\,\eta(\hat x).$$

This is the rule "forward error $\lesssim$ condition number $\times$ backward error" in exact form. A backward-stable solver guarantees $\eta=O(u)$; whether the forward error is also small is then decided only by $\kappa(A)$. When both the matrix and the right-hand side are perturbed, $(A+\delta A)(x+\delta x)=b+\delta b$ gives $\delta x=(I+A^{-1}\delta A)^{-1}A^{-1}(\delta b-\delta A\,x)$. If $E=A^{-1}\delta A$ has $\|E\|<1$ then $\|(I+E)^{-1}\|\le1/(1-\|E\|)$ (Neumann series), so with $\|b\|\le\|A\|\|x\|$

$$\frac{\|\delta x\|}{\|x\|}\le\frac{\kappa(A)}{1-\kappa(A)\|\delta A\|/\|A\|}\left(\frac{\|\delta A\|}{\|A\|}+\frac{\|\delta b\|}{\|b\|}\right).$$

The bound is meaningful only while $\kappa(A)\,u\ll1$: once $\kappa\gtrsim1/u$ the perturbed matrix may be singular and no digit is guaranteed.

**Example.** Take the computed solution $\hat x=(0,2)$ of the lesson's $2\times2$ system with the original $b=(2,2.0001)$. Find the backward error $\eta$, the forward error, and check the bound $\kappa_2\eta$.

**Solution.** Then $r=(0,-10^{-4})$ and $\eta=\|r\|_2/(\|A\|_2\|\hat x\|_2)=10^{-4}/(2.0001\times2)=2.5\times10^{-5}$: $\hat x$ is the exact solution of a system whose matrix differs from $A$ by $2.5\times10^{-5}$ relative. The forward error is $\|x-\hat x\|/\|\hat x\|=1.414/2=0.707$, and the bound $\kappa_2\eta=40\,002\times2.5\times10^{-5}=1.0$ holds, with 0.707 below it.

### Stability of an algorithm: the quadratic formula

An algorithm can be unstable even when the problem is perfectly conditioned. Solve $ax^2+bx+c=0$ with $a=1$, $b<0$ and $b^2\gg4ac$. The textbook small root is $x_-=(-b-d)/(2a)$ with $d=\sqrt{b^2-4ac}$. Expand $d=|b|\sqrt{1-4ac/b^2}=|b|-2ac/|b|-\dots$ (binomial series), so $-b-d=|b|-d\approx2ac/|b|$: the subtraction takes two numbers of size $|b|$, each carrying an absolute rounding error of order $u|b|$, and returns a number of size $2ac/|b|$. By the cancellation rule the relative error of the result is about $u|b|/(2ac/|b|)=u\,b^2/(2ac)$. The root itself is harmless: by Vieta's relations $x_-x_+=c/a$ and $x_-+x_+=-b/a$, so $x_-\approx c/|b|$ depends on $c$ and $b$ with condition number about 1. The whole loss comes from the formula.

The repair avoids the subtraction. Compute $q=-\tfrac12\big(b+\operatorname{sgn}(b)\,d\big)$, whose two terms have the same sign and cannot cancel, then $x_+=q/a$ and $x_-=c/q$ (Vieta again). Each root now costs a handful of roundings, so its relative error is a small multiple of $u$. The same idea underlies the earlier remedies: choose the equivalent formula whose intermediate quantities are not nearly equal.

**Example.** For $x^2-10^4x+1=0$ the true small root is $1.00000001\times10^{-4}$. How accurate is the textbook formula in double precision, and how accurate is the stable formula?

**Solution.** The textbook formula in double precision returns $1.00000001112\times10^{-4}$, a relative error $1.1\times10^{-9}$ (about seven of sixteen digits lost; the estimate $u\,b^2/(2ac)=5.5\times10^{-9}$ has the right order). The stable formula returns $1.00000001\times10^{-4}$ with error below $10^{-15}$. For $b=10^8$ the same estimate is $O(1)$, which is Case 2 below.

### Overflow, underflow and the scaling principle

Cancellation is not the only way a formula that is correct on paper fails in floating point: intermediate quantities can leave the representable range $[\approx10^{-308},\approx10^{308}]$ although the answer lies comfortably inside it. The standard repair is to **factor out the largest magnitude**: for $\|(x,y)\|_2=\sqrt{x^2+y^2}$ write $m=\max(|x|,|y|)$ and compute $m\sqrt{(x/m)^2+(y/m)^2}$. The ratios lie in $[0,1]$, the sum under the root lies in $[1,2]$, so nothing overflows, and underflow of a tiny ratio to zero is harmless because it was negligible next to 1. This is what `math.hypot` and `np.hypot` do, and it is the same idea as subtracting the maximum in a softmax or log-sum-exp. The lesson: *a mathematically equivalent formula can have very different floating-point behaviour, so check the intermediate ranges as well as the final answer.* (Compare MIT 18.335J, Spring 2019, Problem Set 1, Problem 2.)

**Example.** A range sensor driver computes the length of the vector $(3\times10^{200},\,4\times10^{200})$ as `sqrt(x*x + y*y)`. What does it return, and how can the computation be rescaled to give the right length?

**Solution.** The squares are $9\times10^{400}$ and $1.6\times10^{401}$, beyond $1.8\times10^{308}$, so both overflow to `inf` and the result is `inf`. With $m=4\times10^{200}$ the ratios are $0.75$ and $1$, the sum under the root is $1.5625$, the root is $1.25$, and $m\cdot1.25=5\times10^{200}$ (what `math.hypot` returns, to within one ulp).

## Worked example

### Case 1: a 2x2 system whose answer moves 100 % for a 0.004 % change in the data

**Problem.** Solve $Ax=b$ with $A=\begin{pmatrix}1&1\\1&1.0001\end{pmatrix}$ and $b=(2,\;2.0001)^T$. Then change the second entry of $b$ to $2.0002$ and solve again. (a) Find both solutions. (b) Compare the relative change of the data with the relative change of the solution, and with $\kappa(A)$. (c) Treat $\hat x=(0,2)$ as an "answer" to the original system and compare its relative residual with its relative error.

**Solution.**
1. *Original system.* Eliminate: row 2 minus row 1 gives $0.0001\,y=0.0001$, so $y=1$ and, from row 1, $x=2-y=1$. Solution $(1,1)$.
2. *Perturbed system.* The same elimination gives $0.0001\,y=0.0002$, so $y=2$ and $x=0$. Solution $(0,2)$.
3. *Change of the data* (relative, 2-norm, "Conditioning"). $\|\delta b\|/\|b\|=10^{-4}/2.8285=3.54\times10^{-5}$.
4. *Change of the solution.* $\|(-1,1)\|/\|(1,1)\|=1.414/1.414=1$. The amplification is $1/(3.54\times10^{-5})=2.83\times10^{4}$.
5. *Condition number.* $A^{-1}=\begin{pmatrix}10001&-10000\\-10000&10000\end{pmatrix}$, so $\|A\|_\infty=2.0001$, $\|A^{-1}\|_\infty=20001$ and $\kappa_\infty=40004$ (2-norm: 40002). The observed amplification $2.8\times10^{4}$ is below $\kappa$, as the perturbation bound requires.
6. *Residual view* ("Residual versus error"). For $\hat x=(0,2)$ and the original $b$: $r=b-A\hat x=(2-2,\;2.0001-2.0002)=(0,-10^{-4})$, relative residual $\|r\|/\|b\|=3.54\times10^{-5}$, but the relative error is $\|x-\hat x\|/\|x\|=1$. The bound $\kappa_2\|r\|/\|b\|=40002\times3.54\times10^{-5}=1.41\ge1$ holds.

**Check.** `np.linalg.solve` returns $(1,1)$ and $(0,2)$ for the two right-hand sides, and `np.linalg.cond(A,2)` gives $40002.0$. The product of the amplification and the data change is exactly the relative error 1, so nothing is hidden.

**Takeaway.** A residual of $3.5\times10^{-5}$ looks excellent, yet no digit of the answer is correct: only $\kappa$ tells you how far a small residual can mislead.

### Case 2: the quadratic formula at $b=-10^{8}$, step by step in double precision

**Problem.** Solve $x^2-10^{8}x+1=0$ ($a=1$, $b=-10^8$, $c=1$). (a) Compute the small root with the textbook formula $x_-=(-b-d)/(2a)$, $d=\sqrt{b^2-4ac}$, in double precision, and find its relative error against the true root $1.0000000000000001\times10^{-8}$. (b) Explain where the digits go. (c) Compute it with the stable formula.

**Solution.**
1. *Inputs of the square root.* $b^2=10^{16}$ is exactly representable ($10^{16}=2^{16}5^{16}$ with $5^{16}<2^{53}$); $4ac=4$. Near $10^{16}$ the spacing is 2, so $b^2-4ac=10^{16}-4$ is also exact. No rounding has happened yet.
2. *The true square root.* $d=10^{8}\sqrt{1-4\times10^{-16}}=10^{8}-2.00\times10^{-8}-\dots$ (binomial series, "Stability of an algorithm").
3. *Rounding of $d$.* Between $2^{26}$ and $2^{27}$ the spacing is $2^{26-52}=1.49\times10^{-8}$, so the doubles just below $10^8$ are $10^8-1.49\times10^{-8}$ and $10^8-2.98\times10^{-8}$. The true $d$ lies $2.00\times10^{-8}$ below $10^8$, nearest to the first (distance $0.51\times10^{-8}$ against $0.98\times10^{-8}$). So $\hat d=10^{8}-1.49\times10^{-8}$, a relative error of $5\times10^{-17}\le u$: the model $\mathrm{fl}(\cdot)=(\cdot)(1+\delta)$ holds.
4. *The subtraction.* $-b-\hat d=10^8-\hat d=1.49\times10^{-8}$, computed exactly (Sterbenz: the operands are within a factor of 2). Divide by $2a=2$: $\hat x_-=7.45\times10^{-9}$.
5. *Error.* True root $1.00\times10^{-8}$, so the relative error is $|7.45-10.0|/10.0=25.5\,\%$. Cancellation rule: the difference is $2\times10^{-16}$ of its operands, so $\log_{10}(1/(2\times10^{-16}))\approx15.7$ digits are lost and the input error $5\times10^{-17}$ is amplified to $O(1)$.
6. *Stable formula.* With $\operatorname{sgn}(b)=-1$: $q=-\tfrac12(b+\operatorname{sgn}(b)\hat d)=\tfrac12(10^{8}+\hat d)=10^{8}-0.745\times10^{-8}$, a tie between two doubles, rounded to even: $q=10^{8}$. Then $x_+=q/a=10^{8}$ and $x_-=c/q=1/10^{8}=1.0\times10^{-8}$, with relative error below $10^{-16}$.

**Check.** Vieta: $x_-x_+$ must equal $c/a=1$. Naive: $7.45\times10^{-9}\times10^{8}=0.745$, wrong. Stable: $1.0\times10^{-8}\times10^{8}=1$. Residual of the naive root in the equation: $\hat x_-^2-10^{8}\hat x_-+1=5.6\times10^{-17}-0.745+1=0.255$, far from zero (Python: `p(7.450580596923828e-09)` gives $0.2549\ldots$).

**Takeaway.** The problem is well conditioned; the formula is not. Rewriting $-b-d$ as $c/q$ removes the subtraction and recovers all digits, with no extra precision.

## Reference implementation

```python
import math

def machine_eps():
    e = 1.0
    while 1.0 + e / 2 > 1.0:
        e /= 2
    return e

def kahan_sum(xs):
    s = 0.0
    c = 0.0
    for x in xs:
        y = x - c
        t = s + y
        c = (t - s) - y
        s = t
    return s

def solve(A, b):
    n = len(A)
    M = [list(map(float, A[i])) + [float(b[i])] for i in range(n)]
    for k in range(n):
        p = max(range(k, n), key=lambda i: abs(M[i][k]))
        if abs(M[p][k]) < 1e-300:
            raise ValueError("singular matrix")
        M[k], M[p] = M[p], M[k]
        for i in range(k + 1, n):
            f = M[i][k] / M[k][k]
            for j in range(k, n + 1):
                M[i][j] -= f * M[k][j]
    x = [0.0] * n
    for i in reversed(range(n)):
        x[i] = (M[i][n] - sum(M[i][j] * x[j] for j in range(i + 1, n))) / M[i][i]
    return x

def norm_inf(A):
    return max(sum(abs(v) for v in row) for row in A)

def cond_inf(A):
    n = len(A)
    cols = [solve(A, [1.0 if i == j else 0.0 for i in range(n)]) for j in range(n)]
    inv = [[cols[j][i] for j in range(n)] for i in range(n)]
    return norm_inf(A) * norm_inf(inv)

def quad_roots(a, b, c):
    d = math.sqrt(b * b - 4 * a * c)
    q = -0.5 * (b + math.copysign(d, b))
    return tuple(sorted((q / a, c / q), key=abs))

# self-test
assert machine_eps() == 2 ** -52
assert sum([0.1] * 10) != 1.0 and kahan_sum([0.1] * 10) == 1.0
assert solve([[0, 1], [1, 0]], [2, 3]) == [3.0, 2.0]
assert abs(cond_inf([[1, 1], [1, 1.0001]]) - 40004.0001) < 1e-2
small, large = quad_roots(1, -1e8, 1)
assert abs(small - 1e-8) < 1e-18 and abs(large - 1e8) < 1e-4
print("ok", cond_inf([[1, 1], [1, 1.0001]]))
```

## Verification

Verify a numerical result with three independent checks. (1) Reproduce a hand-computed small case, such as the worked 2x2 example. (2) Check an invariant: $Ax$ reproduces $b$ to about $\kappa\,u\,\|b\|$-consistent tolerance, and perturbing the input by a relative $10^{-8}$ changes the output by about $\kappa\times10^{-8}$. (3) Compare against a higher-precision or exact computation (`fractions.Fraction`, `math.fsum`) on a small instance. Always report the residual **and** the condition number; either alone can mislead. A test that could reject you: if the observed output change exceeds $\kappa\,u$-scaled expectations, you have an unstable algorithm, not just an ill-conditioned problem.

## Failure modes

- Comparing floats with `==`: `0.1+0.2==0.3` is False.
- Quadratic formula with $b^2\gg4ac$: small root off by 25% (7.45e-9 instead of 1e-8) from cancellation.
- Summing small increments into a large total (float32 at 20,000 m): increments below 1 mm vanish completely.
- Normal equations on unscaled data: slope $-0.0127$ instead of 0.5, because $\kappa(X)\approx10^{18}$ already exceeds $1/\varepsilon$ and squaring it only makes things worse. Even QR or SVD on the raw columns fails here; centering the time is the fix.
- Trusting a small residual: a relative residual of $3.5\times10^{-5}$ with 100% error in the worked example.

## Alternatives and trade-offs

QR or SVD solve least squares with $\kappa(X)$ rather than $\kappa(X)^2$, at roughly twice the cost of the normal equations; use them when $\kappa(X)$ may exceed $10^{4}$ to $10^{6}$ (they cannot save a problem whose $\kappa(X)$ is itself near $1/\varepsilon$, as with raw timestamps; rescale first). Pivoted elimination is cheap and stable for well-conditioned square systems; regularization (ridge, truncated SVD) intentionally accepts bias to tame a huge $\kappa$. Compensated summation (Kahan) or `math.fsum` costs a small constant factor and fixes absorption; pairwise summation (used by NumPy) is nearly free and good enough for most data. Higher precision (float128, `mpmath`, `fractions`) is a diagnostic tool for finding whether a result is numerically sound, rarely a production fix. Float32 halves memory and doubles GPU throughput; accept it for neural-network activations, avoid it for global coordinates or accumulated integrals.

## Transfer and retention

- Inverse-kinematics Jacobians near a singularity have huge $\kappa$; the joint-velocity solution blows up. Damped least squares trades a little bias for a bounded $\kappa$.
- Kalman filter covariance updates in the textbook form can lose symmetry or positive definiteness through cancellation; square-root and Joseph forms exist for this reason.

Relative error 25%. Fix: compute the large-magnitude root $q=-\tfrac12(b+\mathrm{sign}(b)d)$, then the other root as $c/q$; this gives $10^{-8}$.

(c) The problem is ill-conditioned: no algorithm can do better with that data. Fix by measuring the difference directly (e.g. relative encoder) or with a better sensor.
6. `sum` gives 0.9999999999999999, `fsum` gives 1.0. The summation error is $1.1\times10^{-16}$ (one ulp); the exactly rounded sum of the ten stored doubles is 1.0 (stored 0.1 is slightly above 0.1, and fsum's rounding returns 1.0).
7. (a) $\kappa(X)\approx10^{18}$ (columns of size 1 and $10^9$ are almost parallel), so $\kappa(X^TX)=\kappa(X)^2\approx10^{36}$ in exact arithmetic (the rounded matrix a computer forms is numerically singular); with $\varepsilon=2.2\times10^{-16}$ even $\kappa(X)\varepsilon\approx200$, so no digits are guaranteed and the normal equations lose everything. QR or SVD on the raw columns would not rescue it either. (b) With $t'=t-\bar t$ the columns are orthogonal-ish: $\kappa(X)\approx2.9$, and the solve gives intercept 5.25 and slope 0.5 (5.25 is the line's value at the mean time $t=1.7\times10^9+4.5$). (c) The two parameterizations describe the same line; only the arithmetic changes.
8. $A(x-\hat x)=r\Rightarrow\|x-\hat x\|\le\|A^{-1}\|\|r\|$. Also $b=Ax\Rightarrow\|b\|\le\|A\|\|x\|$, i.e. $1/\|x\|\le\|A\|/\|b\|$. Multiply: $\|x-\hat x\|/\|x\|\le\|A\|\|A^{-1}\|\|r\|/\|b\|$. Equality holds when $r$ aligns with the smallest singular direction while $b$ aligns with the largest, which is what the worked example does.
9. The bound is a worst case over all directions of $r$ and $b$. For a diagonal matrix, rounding errors in each component are relative to that component (componentwise error), so the small entry loses nothing. Practical rule: scale rows and columns to comparable size before judging $\kappa$ (equilibration), and treat norm-wise $\kappa$ as an upper bound. In a pipeline, check $\kappa$ (or the smallest singular value) before using a calibration or Jacobian solve; if $\kappa>1/\sqrt\varepsilon\approx7\times10^7$, rescale, switch to QR/SVD, regularize, or refuse the result and report it.
10. Expected: $\kappa_\infty$ grows from about 27 at $n=2$ to about $10^{13}$ at $n=10$; the relative residual stays at $10^{-16}$ to $10^{-15}$; the error grows like $\kappa u$ (4e-7 at $n=8$, about $3\times10^{-4}$ at $n=10$). Elimination is backward stable, so the residual is always small; the error is controlled by $\kappa$. (Figure `M11-3` and these numbers come from the reference `solve` with `b = [sum(row) for row in H]` and the residual evaluated in double: at $n=8$, $\kappa_\infty=3.39\times10^{10}$, residual $1.6\times10^{-16}$, error $4.2\times10^{-7}$; at $n=10$ the error is $3.2\times10^{-4}$. A different rounding of $b$, e.g. `H @ np.ones(n)` with NumPy, gives other digits of the same order, such as $7\times10^{-8}$ at $n=8$.)
11. (a) For $m=1$ the sum is $\mathrm{fl}(x_1+x_2)=(x_1+x_2)(1+\delta)$, which has the form with one factor per term. Assume it holds for $2^m$ terms. A sum of $2^{m+1}$ terms is $\big[\sum_{i\le 2^m}x_i\prod_{k\le m}(1+\delta_{i,k})+\sum_{i>2^m}x_i\prod_{k\le m}(1+\delta_{i,k})\big](1+\delta)$ where the last factor comes from adding the two halves and the inner factors are those of the half-sums. Every term now has $m+1$ factors, each bounded by $u$. (b) $\big|\prod_{k=1}^m(1+\delta_{i,k})-1\big|\le(1+u)^m-1=mu+O(u^2)$, so $|\tilde f-\sum x_i|\le\sum|x_i|\,(mu+O(u^2))$ with $m=\log_2 n$: logarithmic instead of linear growth. (c) Each term passes through at most $b-1$ additions in its block and $\log_2(n/b)$ in the tree, so the bound is $(b-1+\log_2(n/b))u\sum|x_i|$; with a block of, say, 128 terms the recursion overhead is paid once per 128 additions (a plain loop inside the block), so the speed is almost that of a loop, while the error constant is $\approx127+\log_2(n/128)$ instead of $n-1$. (d) Computed: the sequential `np.cumsum(a, dtype=np.float32)[-1]` gives $1.6777216\times10^{7}=2^{24}$, while `np.sum(a, dtype=np.float32)` gives $3.3554432\times10^{7}=2^{25}$ (exact). Explanation: float32 has 24 significant bits, so above $2^{24}$ the spacing is 2; $2^{24}+1$ is a tie between $2^{24}$ and $2^{24}+2$, and round-to-even returns $2^{24}$, so the running total never moves again (absorption). In the pairwise tree both halves are small when they are added, so the partial sums stay exact.
12. (a) `x**4` underflows: $(10^{-100})^4=10^{-400}\to0.0$, so the result is `0.0` instead of $10^{-100}$; in Python `1e100**4` raises `OverflowError` (NumPy would return `inf`), instead of the correct $10^{100}$. (b) With $m=\max(|x|,|y|)$ (return 0 if $m=0$): `m * ((abs(x)/m)**4 + (abs(y)/m)**4) ** 0.25`. The ratios are in $[0,1]$, their fourth powers in $[0,1]$ and the sum in $[1,2]$; a ratio that underflows to 0 contributes less than $10^{-300}\ll u$ to a sum $\ge1$, so it changes nothing. Only a few roundings happen (division, power, add, root, multiply), each a relative error $\le u$ amplified by modest factors ($\kappa$ of $s\mapsto s^{1/4}$ is $1/4$), so the final error is a small multiple of $u$. Returns `1e-100` and `1e+100` for the two inputs. (c) Computed on 20,000 random pairs (exponents uniform in $\pm300$, half of them with $y$ close to $x$): worst relative error $2.34\times10^{-16}$, about $1.05\varepsilon$.
13. (b) $\cot x-\cot(x+y)=\dfrac{\cos x\sin(x+y)-\cos(x+y)\sin x}{\sin x\sin(x+y)}=\dfrac{\sin y}{\sin x\,\sin(x+y)}$ because the numerator is $\sin((x+y)-x)$. (a) At $(1,10^{-20})$: $x+y$ rounds to 1.0 so the naive formula returns exactly `0.0`; the stable formula gives $1.4122829274373917\times10^{-20}$ (matching $y/\sin^2 1$). At $(0.3,10^{-12})$ the naive value is $1.14499521\times10^{-11}$ versus stable $1.14505313\times10^{-11}$: relative error $5.06\times10^{-5}$, about 11 digits lost. (c) For small $y$ the function is $\approx y/\sin^2x$, so $\kappa=1$ with respect to $y$: the problem is benign, and the loss comes from the algorithm subtracting two nearly equal numbers. At $(1,0.5)$ the naive and stable results (0.5711777716316782 and 0.5711777716316783) differ by $1.9\times10^{-16}$ in relative terms, so the stable form costs nothing there. (Both formulas are still ill-conditioned in $x$ near multiples of $\pi$, where $\sin x\to0$; that is a property of the problem.)
14. (a) For a perturbation $\delta A$: $\|\delta A\,x\|_2\le\|\delta A\|_F\|x\|_2$ (Cauchy-Schwarz row by row), so $\dfrac{\|\delta A\,x\|/\|Ax\|}{\|\delta A\|_F/\|A\|_F}\le\dfrac{\|A\|_F\|x\|_2}{\|Ax\|_2}$. Equality holds for $\delta A=u\,x^T/\|x\|$ with any unit vector $u$: then $\|\delta A\|_F=1$ and $\delta A\,x=\|x\|u$ has norm $\|x\|$. Since $g$ is linear in $A$ the bound is exact, so $\kappa_g=\|A\|_F\|x\|_2/\|Ax\|_2$ and the supremum is attained. (b) $\|A\|_F=\sqrt{30}=5.4772$, $Ax=(3,7)$, $\|Ax\|=\sqrt{58}=7.6158$, $\|x\|=1.4142$, so $\kappa_g=1.01710$. A random search over 200,000 normalised $\delta A$ gave a maximum of $1.01709$ (never above the bound). (c) For $x\mapsto Ax$ the condition number is $\|A\|_2\|x\|_2/\|Ax\|_2=1.01482$ here; it reaches $\kappa_2(A)$ only when $x$ is aligned with the smallest right singular vector. For $g(A)$, using $\|A\|_F\le\sqrt r\,\sigma_1$ ($r$ the rank) and $\|Ax\|\ge\sigma_{\min}\|x\|$, we get $\kappa_g\le\sqrt r\,\kappa_2(A)$, again approached only when $Ax$ is small compared with $\|A\|\|x\|$.
