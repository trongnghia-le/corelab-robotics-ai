## Why this matters

Make array dimensions explicit before vectorizing computations. This lesson develops the core calculation before asking you to apply it in a new setting. Start with the diagnostic if you think you already know it; prior tool use is not evidence of understanding.

## Intuition

A batch of vectors is a table whose axes have meaning. NumPy can repeat compatible singleton dimensions without physically copying data, but it cannot know whether a dimension means sample, feature, or camera. Shape reasoning is therefore part of mathematical correctness.

![Broadcasting a (3,) mean row across a (4,3) data matrix to center each feature](/lesson-figures/PY04.svg)

*Figure: broadcasting reuses the mean row for every sample; shapes are compared from the right.*

## Theory and derivation

An array of $N$ samples with $D$ features has shape $(N,D)$ under the row-sample convention. Broadcasting compares dimensions from the right: a pair is compatible if equal or either is 1; missing leading dimensions behave as 1. Thus $(N,D)-(D,)$ centers features, while $(N,D)-(N,)$ usually fails or, when $N=D$, can silently mean the wrong thing.

Feature means use `X.mean(axis=0)`, which reduces the sample axis and gives shape `(D,)`. Per-row means use `axis=1, keepdims=True`, preserving shape `(N,1)` for subtraction. `A*B` multiplies elementwise; `A@B` contracts matrix dimensions.

For row normalization, compute $r_i=\sqrt{\sum_jX_{ij}^2}$ and $Y_{ij}=X_{ij}/r_i$. Specify how to handle zero rows. A view can share storage with its parent; modifying a slice may mutate the source. Use `.copy()` when independent ownership is required.

## Worked example

X=[[1,2,3],[4,5,6]] has shape (2,3). Its feature mean is [2.5,3.5,4.5], so centering yields two rows [−1.5,−1.5,−1.5] and [1.5,1.5,1.5]. Row means [2,5] require shape (2,1); a plain (2,) cannot broadcast against (2,3).

## Failure modes

A shape-compatible result can be conceptually wrong. Square batches conceal axis swaps, so prefer non-square test examples. Integer arrays can truncate assignments of floating-point results.

## Alternatives and trade-offs

Loops are useful reference implementations. Broadcasting is fast and compact but can allocate huge intermediates. Matrix products exploit optimized kernels; verify shapes and memory cost before replacing a clear implementation.

## Exercise answers

1. `(3,)`, `(100,)`, `(100, 1)` and `(100, 3)`. Only the last one, `X - X.mean(axis=0)`, removes the per-axis bias (the first is the per-axis mean itself). `(100, 3) - (100,)` raises `ValueError`, because trailing dimensions 3 and 100 are not equal and neither is 1; with 3 samples it would silently subtract per-sample means from the wrong axis.
2. `(8, 1, 6, 1)` with `(7, 1, 5)`: yes, result `(8, 7, 6, 5)` (compare right to left: 1 vs 5, 6 vs 1, 1 vs 7, 8 vs missing). `(3,)` with `(4,)`: no, 3 vs 4. `(5, 1)` with `(1, 4)`: yes, `(5, 4)` (an outer-product-style grid).
3. `a.sum(axis=0)` is `[3 5 7]`; the keepdims shape is `(2, 1)`; `a * a` is the elementwise square `[[0 1 4], [9 16 25]]`; `a @ a.T` is `[[5 14], [14 50]]`, the matrix of dot products between rows (5 = 0+1+4, 50 = 9+16+25).
4. `xy = np.stack([r*np.cos(th), r*np.sin(th)], axis=1)` with `th = np.deg2rad([0, 90, 180])` gives `[[2, 0], [~0, 3], [-1, ~0]]`. $\pi$ is not exactly representable, so $\cos(\pi/2)\approx6.1\times10^{-17}$, times $r=3$ gives $1.8\times10^{-16}$ (likewise $\sin\pi\approx1.2\times10^{-16}$). Never test such values with `==`; use `np.allclose`.
5. For `N = 5`, `X.mean(axis=1)` has shape `(5,)` and `(5,3) - (5,)` raises `ValueError`. For `N = 3` the shapes are compatible, so no error is raised, but each column is shifted by the mean of the corresponding row: a silent wrong answer. Fix: `Z = (X - X.mean(axis=0)) / X.std(axis=0)` (and use `keepdims=True` for clarity; guard against zero std). Test with a non-square batch.
6. Prints `[ 0. 99.  2.  3.  4.  5.]`. `b = a[1:4]` is a view, so `b[0] = 99` writes into `a`. `a[[1, 2, 3]]` is fancy indexing and returns a copy, so `c[1] = -1` leaves `a` unchanged.
7. `x` is `[2 2 3]`: an integer array silently truncates 2.7 to 2. `x /= 2` tries to store float results into an int array in place and raises `UFuncTypeError`; `x = x / 2` creates a new float array. Create with `np.array([1, 2, 3], dtype=float)`.
8. The broadcast version builds an `(N, N, 2)` temporary: $10^4\cdot10^4\cdot2\cdot8$ B $=1.6$ GB (plus the squared copy). The result alone is $(N,N)$: $0.8$ GB. The expansion needs only `(N, N)` arrays, but suffers catastrophic cancellation for close points (the difference of large numbers can even come out slightly negative before `sqrt`, so clip at 0). For N this large, also consider processing in blocks.
9. Reduce `axis=(0, 1, 2)` and keep channels: mean shape `(1, 1, 1, C)`. Reducing only axis 0 would give a separate mean per pixel location, not per channel, and would not mean 'this colour channel has zero mean'. With $\mu=\frac1M\sum_k x_k$ and $z_k=(x_k-\mu)/\sigma$: $\sum_k z_k=(\sum_kx_k-M\mu)/\sigma=0$.
10. A column vector transforms as $p'=Rp$. Row-stored points are $p^\top$, and $(Rp)^\top=p^\top R^\top$, so the batch is `P @ R.T`. For $R=\begin{bmatrix}0&-1&0\\1&0&0\\0&0&1\end{bmatrix}$: `[1,0,0] @ R.T` gives `[0, 1, 0]` (correct), while `[1,0,0] @ R` gives `[0, -1, 0]`, which is the inverse rotation.
11. Norms are `[5, 0, 1]` and the result should be `[[0.6, 0.8], [0, 0], [1, 0]]`. Problems: (1) `np.linalg.norm(X, axis=1)` has shape `(3,)`, which does not broadcast with `(3, 2)` - use `keepdims=True`; (2) the zero row gives $0/0=$ `nan` with a warning. Typical contract: leave zero rows as zeros (`np.where(r == 0, 1, r)`), or raise `ValueError`. State it in the docstring.
12. A good answer shows `np.convolve(x, np.ones(k)/k, mode='valid')` and `c = cumsum(concat([0], x)); (c[k:] - c[:-k]) / k` agree with the loop to about `1e-12`; the loop is $O(nk)$ in Python and slowest; `convolve` is fast for small `k`; cumsum is $O(n)$ for any `k` but accumulates round-off on long signals. `'valid'` mode returns `n-k+1` samples (no edge padding); say how you would handle the edges (shorter windows or padding).
