## Why this matters

Make array dimensions explicit before vectorizing computations. This lesson develops the core calculation before asking you to apply it in a new setting. Start with the diagnostic if you think you already know it; prior tool use is not evidence of understanding.

## Intuition

A batch of vectors is a table whose axes have meaning. NumPy can repeat compatible singleton dimensions without physically copying data, but it cannot know whether a dimension means sample, feature, or camera. Shape reasoning is therefore part of mathematical correctness.

![Broadcasting a (3,) mean row across a (4,3) data matrix to center each feature](/lesson-figures/PY04.svg)

*Figure: broadcasting reuses the mean row for every sample (the dashed copies cost no memory); shapes are compared from the right.*

Picture a spreadsheet of sensor readings: one row per time step, one column per sensor. "Subtract each sensor's average" means: compute one number per *column*, then subtract that column's number from every row. You never type the average four hundred times; you think of it as a single row that is laid across the whole sheet. Broadcasting is exactly that mental picture made precise: a size-1 (or missing) axis is a sheet that is pulled across the other axis. What NumPy cannot do is read your mind. If you hand it a list of per-row averages instead of per-column ones, it will either refuse (when the lengths differ) or happily subtract the wrong thing (when they coincide).

A robot example: a mobile base logs 5 lidar scans of 4 beams each, an array of shape $(5,4)$ in metres. A per-beam calibration offset is a $(4,)$ vector, one number for each beam, and subtracting it from the scans is a single line. A per-scan offset (say, the scan's own mean range) is a $(5,)$ vector, and it has to be given shape $(5,1)$ before it can be subtracted: the extra axis says "this number belongs to the row".

**Predict before you compute.** For `X` of shape $(6,3)$, which of `X - X.mean(axis=0)`, `X - X.mean(axis=1)` and `X - X.mean(axis=1, keepdims=True)` run, and what are the shapes? Then ask the harder question: if `X` had shape $(3,3)$, which of the three would run, and which would be correct?

Three intuitions are tempting and wrong. First, "two arrays combine if they have the same number of elements": shapes, not counts, decide. Second, "NumPy knows which axis is which": it only compares numbers, so a square batch hides an axis mix-up completely. Third, "a slice is a small copy": a slice is a *window onto the same memory*, so writing through it changes the parent, an aliasing effect, now with numbers.

**Answer to the prediction.** The first and the third run and give shape $(6,3)$; the second fails, because $3$ and $6$ are unequal and neither is 1. For shape $(3,3)$ all three run, but the second silently subtracts the mean of row $j$ from column $j$, which is wrong.

## Theory and derivation

### Shapes, axes and the row-sample convention

An `ndarray` of $N$ samples with $D$ features has shape $(N,D)$ under the **row-sample convention**: axis 0 indexes samples, axis 1 indexes features, and $X_{ij}$ is feature $j$ of sample $i$. A shape is a tuple of non-negative integers, one per axis, and the number of axes is `ndim`. The shape says nothing about meaning: a $(5,4)$ array can be 5 scans of 4 beams or 4 scans of 5 beams, and only the code's convention tells them apart. Two habits keep this safe. First, write the meaning of every axis in a comment or a variable name (`scans, beams = X.shape`). Second, test on non-square shapes, because a $(3,3)$ test cannot detect an axis swap (NumPy reference, "The N-dimensional array"; broadcasting rules in the NumPy user guide, "Broadcasting").

**Example.** A mobile base logs 5 lidar scans of 4 beams, ranges in metres, as `X` of shape $(5,4)$ with rows `[2.0, 3.1, 2.9, 4.0]`, `[2.2, 3.0, 3.1, 4.2]`, `[1.8, 3.2, 2.7, 3.8]`, `[2.0, 3.3, 3.0, 4.1]`, `[2.0, 3.4, 3.3, 3.9]`. `X.mean(axis=0)` is `[2.0, 3.2, 3.0, 4.0]` with shape $(4,)$, one mean range per beam, and `X - X.mean(axis=0)` has shape $(5,4)$ with entries such as $2.2-2.0=0.2$ and $3.0-3.2=-0.2$ in the second scan. `X.mean(axis=1, keepdims=True)` has shape $(5,1)$, one mean per scan. (NumPy 2.4.6.)

### Reductions along an axis, and keepdims

A reduction such as `sum`, `mean`, `std`, `max` collapses one or more axes: `X.mean(axis=k)` replaces axis $k$ by a single number computed over all its indices, so the result's shape is the shape of `X` with axis $k$ removed. For $X$ of shape $(N,D)$, `X.mean(axis=0)` is $\mu_j=\frac1N\sum_iX_{ij}$ with shape $(D,)$ (one value per feature), while `X.mean(axis=1)` is $\frac1D\sum_jX_{ij}$ with shape $(N,)$ (one value per sample). `axis` may be a tuple, which collapses several axes at once, and `keepdims=True` keeps each collapsed axis as a size-1 axis instead of deleting it. Keeping the axis is what makes the result broadcastable back against the original array: `(N,D)` minus `(N,1)` is legal and subtracts row means, whereas `(N,D)` minus `(N,)` aligns the $N$ with the *feature* axis. The population standard deviation `X.std(axis=0)` (`ddof=0`) is $\sigma_j=\sqrt{\frac1N\sum_i(X_{ij}-\mu_j)^2}$; with `ddof=1` the divisor is $N-1$. Standardising feature $j$ gives $Z_{ij}=(X_{ij}-\mu_j)/\sigma_j$, which has mean 0 and standard deviation 1 provided $\sigma_j>0$; a constant feature has $\sigma_j=0$ and needs an explicit policy.

**Example.** A tactile skin records 10 frames of a $3\times2$ taxel grid, `T` of shape $(10,3,2)$. `T.mean(axis=0)` has shape $(3,2)$ (the average image), `T.mean(axis=(1,2))` has shape $(10,)$ (one pressure per frame), and `T.mean(axis=(1,2), keepdims=True)` has shape $(10,1,1)$, so `T - T.mean(axis=(1,2), keepdims=True)` is again $(10,3,2)$ and each frame has mean 0.

### Broadcasting from the definition

Broadcasting is the rule that lets an operation such as `A - B` act on arrays of different shapes. Here it is built from a definition, so that nothing has to be memorised.

**Definition.** Let $A$ have shape $a=(a_1,\dots,a_m)$ and $B$ shape $b=(b_1,\dots,b_n)$, and let $N=\max(m,n)$. Pad the shorter shape with ones on the **left** until both have length $N$; call the padded shapes $a'$ and $b'$. The shapes are *compatible* when for every axis $t=1,\dots,N$: $a'_t=b'_t$, or $a'_t=1$, or $b'_t=1$. The result shape is $c_t=b'_t$ if $a'_t=1$ and $c_t=a'_t$ otherwise. The result of a binary elementwise function $f$ is
$$C[i_1,\dots,i_N]=f\big(A[\pi_A(i)],\,B[\pi_B(i)]\big),\qquad 0\le i_t<c_t,$$
where $\pi_A$ drops the padded coordinates and replaces $i_t$ by $0$ on every axis with $a'_t=1$ (and likewise for $B$). In words: "repeat every size-1 axis as often as needed". The rule compares shapes **from the right**, which is why $(N,D)-(D,)$ works and $(N,D)-(N,)$ does not (NumPy user guide, "Broadcasting", "General broadcasting rules").

**Proof.** (The rule is exactly the explicit loop, and needs no copy.) *Why this rule.* Each operand must supply a value for every output index $i$, on each axis $t$ either by following the coordinate $i_t$ or by being held at the constant $0$. An operand that follows $i_t$ must have extent exactly $c_t$ (a smaller extent would make the index invalid, a larger one would leave entries unused). An operand held at $0$ must have extent 1 (otherwise entries are again unused). So on every axis both extents must lie in $\{c_t,1\}$. Given $(a'_t,b'_t)$ such a $c_t$ exists exactly when $a'_t=b'_t$ (take $c_t$ equal to it), or one of them is 1 (take $c_t$ equal to the other); if $a'_t\ne b'_t$ and neither is 1, no value of $c_t$ has both in $\{c_t,1\}$. This is the compatibility condition, and $c_t$ is the extent that is not 1. *No copy is needed.* Let $A$ have strides $(\sigma_1,\dots,\sigma_m)$ in bytes. Define the **broadcast view** $\tilde A$ with shape $c$ and strides $\tilde\sigma_t=\sigma_{t-(N-m)}$ if $t>N-m$ and $a'_t>1$, and $\tilde\sigma_t=0$ otherwise. The byte offset of $\tilde A[i]$ is $\sum_t\tilde\sigma_ti_t=\sum_{t>N-m,\,a'_t>1}\sigma_{t-(N-m)}\,i_t$. The byte offset of $A[\pi_A(i)]$ is $\sum_{t>N-m}\sigma_{t-(N-m)}\bar i_t$, where $\bar i_t=i_t$ if $a'_t>1$ and $0$ if $a'_t=1$; the terms with $a'_t=1$ vanish, so the two sums are equal. Hence $\tilde A[i]$ reads the same bytes as $A[\pi_A(i)]$ and the loop over $i$ with the formula above can be run over the original data, with no repeated copies of the inputs. $\blacksquare$ (This follows the construction in the NumPy documentation of `numpy.broadcast_to` and the strides section of the ndarray reference.)

**Where it stops.** The rule is about shapes only. $(N,D)-(N,)$ with $N=D$ is legal and silently subtracts along the wrong axis (each *column* $j$ loses the value $m_j$ meant for row $j$). Dimensions of size 0 follow the same rule ($(0,)$ with $(1,)$ gives $(0,)$), and an in-place operation `A -= B` fails when the broadcast shape differs from $A$'s own shape, because the output cannot grow.

![Three shape pairs aligned on the right: (6,1,2) with (3,1) gives (6,3,2); (5,3) with (5,) fails because 3 and 5 differ; (3,3) with (3,) works but is read along columns.](/lesson-figures/PY04-2.svg)

*Figure: the rule axis by axis from the right. Dashed cells are padded ones; amber cells are size-1 axes that stretch; the red cell is a mismatch.*

**Example.** Three robots at $(0,0),(4,0),(0,3)$ m and four landmarks at $(1,1),(2,5),(6,2),(3,3)$ m. With `R` of shape $(3,2)$ and `L` of shape $(4,2)$, `R[:, None, :] - L[None, :, :]` has shapes $(3,1,2)$ and $(1,4,2)$, which broadcast to $(3,4,2)$. Taking the norm over the last axis gives the $(3,4)$ distance table; its entry $[1,2]$ is the distance from $(4,0)$ to $(6,2)$, $\sqrt8=2.828$ m, and the first row is `[1.414, 5.385, 6.325, 4.243]`. A double loop over the 12 pairs gives the same numbers, and `np.broadcast_to(R[:, None, :], (3, 4, 2)).strides` is `(16, 0, 8)`: the landmark axis has stride 0.

### Four views: broadcasting

**Algebra.** For $X\in\mathbb R^{N\times D}$ and $\mu\in\mathbb R^D$ the centred data is $C_{ij}=X_{ij}-\mu_j$ for all $i,j$, which is $X-\mathbf 1\mu^T$ with $\mathbf 1\in\mathbb R^N$ the vector of ones; broadcasting writes the outer product $\mathbf 1\mu^T$ implicitly. In general each operand is read at $\pi(i)$ as defined above.

**Geometry.** Think of $\mu$ as one row of tiles that is repeated down the $N$ rows (figure at the top of the lesson). A size-1 axis is a thin sheet that is pulled out to fill the axis; the pulling costs no memory because it is a stride of 0.

**Code.** The explicit loops of the definition and the broadcast agree:
```python
import numpy as np
from itertools import product
X = np.array([[2., 7., 1.], [4., 5., 3.], [6., 9., 5.], [8., 7., 7.]])
mu = X.mean(axis=0)                        # shape (3,): [5. 7. 4.]
C = np.empty_like(X)
for i, j in product(range(4), range(3)):   # the loops of the definition
    C[i, j] = X[i, j] - mu[j]
assert np.allclose(C, X - mu)
print((X - mu).shape, np.broadcast_to(mu, X.shape).strides)   # (4, 3) (0, 8)
```

**Physical meaning.** `X` holds gyroscope readings in rad/s, $N$ time steps by 3 axes, and `mu` is the bias estimated while the robot is stationary, one value per axis in rad/s. Subtracting it removes the same bias from every time step and keeps the unit. A bias that drifts in time would need its own $(N,3)$ array; broadcasting would then be the wrong model.

**Example.** For the numbers above, $\mu=(5,7,4)$ and the first row becomes $(2-5,7-7,1-4)=(-3,0,-3)$; every column of `X - mu` has mean 0, and the explicit loop touches $4\cdot3=12$ entries while the broadcast view stores only 3 numbers for $\mu$.

### Elementwise product versus matrix product

`A * B` is the elementwise (Hadamard) product $C_{ij}=A_{ij}B_{ij}$ after broadcasting; `A @ B` is the matrix product $C_{ij}=\sum_kA_{ik}B_{kj}$, which needs the inner dimensions to agree: $(n,k)@(k,m)\to(n,m)$. For arrays with more than two axes, `matmul` treats the last two axes as matrices and broadcasts the leading ones as a *batch*: $(10,3,4)@(4,2)$ gives $(10,3,2)$ (NumPy reference, `numpy.matmul`). Points are usually stored as rows, so a rotation that acts on column vectors, $p'=Rp$, becomes, after transposing both sides, $p'^T=p^TR^T$: for a point matrix $P$ with one point per row the rotated points are `P @ R.T`, not `P @ R`, which would rotate by the inverse angle (matrix product background in M03).

**Example.** Rotate the points $(2,0),(0,1),(1,1)$ by $30^\circ$ in the plane. With $R=\begin{pmatrix}\cos30^\circ&-\sin30^\circ\\\sin30^\circ&\cos30^\circ\end{pmatrix}$, `P @ R.T` gives `[[1.7321, 1.0], [-0.5, 0.866], [0.366, 1.366]]`, equal to `(R @ P.T).T`. `P @ R` gives `[[1.7321, -1.0], [0.5, 0.866], [1.366, 0.366]]`, the rotation by $-30^\circ$.

### Row normalisation and the zero row

To give each row unit Euclidean length compute $r_i=\sqrt{\sum_jX_{ij}^2}$, with shape $(N,1)$ if `keepdims=True`, and $Y_{ij}=X_{ij}/r_i$. Two things can go wrong. If the divisor is written `np.linalg.norm(X, axis=1)` without `keepdims`, its shape $(N,)$ is aligned with the feature axis. And if $r_i=0$ the division produces `nan` (or `inf`) and a warning. A contract must say what a zero row becomes; the common choices are "stays zero" (use `np.divide(X, r, out=np.zeros_like(X), where=r > 0)`), "raise", or "add a small $\varepsilon$ to $r_i$", which changes every output slightly. A view can share storage with its parent; modifying a slice may mutate the source. Use `.copy()` when independent ownership is required.

**Example.** For `Y = [[6, 8], [0, 0], [0, 5]]` the norms are $(10,0,5)$. The guarded division returns `[[0.6, 0.8], [0, 0], [0, 1]]`, while the naive `Y / np.linalg.norm(Y, axis=1)` raises `ValueError` for shapes $(3,2)$ and $(3,)$ (and would have produced `nan` in row 1 even with the right shape).

### Strides: why views, transposes and broadcasting are free

An `ndarray` is one flat block of memory plus a shape $(d_0,\dots,d_{N-1})$ and **strides** $(s_0,\dots,s_{N-1})$ in bytes: element $(n_0,\dots,n_{N-1})$ lives at byte offset $\sum_ks_kn_k$ from the start of the block (NumPy reference, "Internal memory layout of an ndarray"). For a C-ordered array $s_k=\text{itemsize}\cdot\prod_{j>k}d_j$; a `float64` array of shape $(2,3,4)$ has strides $(96,32,8)$. Almost every "free" operation is arithmetic on shape and strides only:

- **Transpose or `transpose(2,0,1)`** permutes shape and strides together: strides become $(8,96,32)$. No data moves.
- **Basic slicing** `a[:, ::2, 1:]` multiplies a stride by the step and shifts the start: shape $(2,2,3)$, strides $(96,64,8)$.
- **Broadcasting** gives a size-1 (or missing) axis stride $0$: the offset $0\cdot n_k$ is the same for every index, so the same bytes are read repeatedly. `np.broadcast_to(np.arange(4.), (1000, 4))` has strides $(0,8)$ and no copy (and is read-only). The memory bill appears only when an operation *writes* a result of the full broadcast shape, which is why $(N,1,2)-(1,N,2)$ allocates $N^2\cdot2$ numbers (Exercise 8).

**Proof.** (Slicing is stride arithmetic.) Let axis $k$ have length $d$, stride $s$, and let the array start at byte offset $o$. A slice `start:stop:step` with $\text{step}>0$ selects the indices $n=\text{start}+q\cdot\text{step}$ for $q=0,\dots,L-1$, where $L=\max\big(0,\lceil(\text{stop}-\text{start})/\text{step}\rceil\big)$ and `start`, `stop` have first been normalised for the axis length $d$ (negative values, missing values and clipping, as `slice.indices(d)` does). The byte offset of the element selected by $q$ is $o+s(\text{start}+q\,\text{step})=(o+s\cdot\text{start})+(s\cdot\text{step})\,q$, which is the offset formula for an axis of length $L$, stride $s'=s\cdot\text{step}$ and starting offset $o'=o+s\cdot\text{start}$. Nothing else about the array changes, so the slice is the same memory with new $(o',s',L)$. An integer index $n_k$ keeps one value, adds $s\,n_k$ to the offset and removes the axis. A negative step gives a negative $s'$ and the same formula. $\blacksquare$ For $a$ of shape $(2,3,4)$, `a[:, ::2, 1:]` has start offset $0+0+1\cdot8=8$ bytes, strides $(96,\,32\cdot2,\,8)=(96,64,8)$ and shape $(2,2,3)$, as listed above.

**When does `reshape` return a view?** (Proposition.) Splitting an axis is always possible. Merging two adjacent axes $k,k+1$ with $d_k,d_{k+1}\ge2$ into one axis of size $d_kd_{k+1}$ is possible without copying iff $s_k=d_{k+1}\,s_{k+1}$ (axes of size 1 are free). A general `reshape` applies this test to each group of old axes that merge into one new axis. **Proof.** The merged index is $m=n_kd_{k+1}+n_{k+1}$, and a single stride $s$ must satisfy $ms=n_ks_k+n_{k+1}s_{k+1}$ for all $0\le n_k<d_k$, $0\le n_{k+1}<d_{k+1}$. ($\Rightarrow$) Setting $n_k=0$ and $n_{k+1}=1$ (possible because $d_{k+1}\ge2$) gives $s=s_{k+1}$; then $n_k=1$, $n_{k+1}=0$ (possible because $d_k\ge2$) gives $d_{k+1}s_{k+1}=s_k$. ($\Leftarrow$) If $s_k=d_{k+1}s_{k+1}$, then $m\,s_{k+1}=n_kd_{k+1}s_{k+1}+n_{k+1}s_{k+1}=n_ks_k+n_{k+1}s_{k+1}$ for all $n_k,n_{k+1}$, so the stride $s=s_{k+1}$ works. $\blacksquare$ Check on $a$ of shape $(2,3,4)$, strides $(96,32,8)$: `a.reshape(6,4)` merges axes 0 and 1 and $96=3\cdot32$ holds, so it is a view. But `a[:, ::2, :]` has shape $(2,2,4)$ and strides $(96,64,8)$; merging its first two axes needs $96=2\cdot64$, which fails, so `.reshape(4,4)` silently copies. NumPy never tells you; use `np.shares_memory` when it matters.

**Example.** A camera driver hands over a $480\times640$ colour image as a `uint8` array of shape $(480,640,3)$ with strides $(1920,3,1)$. `img[::2, ::2]` has shape $(240,320,3)$ and strides $(3840,6,1)$: a half-resolution picture of the same bytes, no copy. `img[:, :, ::-1]` swaps the channel order (RGB to BGR) as strides $(1920,3,-1)$ from offset 2. `img.reshape(-1, 3)` merges axes 0 and 1 and $1920=640\cdot3$ holds, so it is a view of shape $(307200,3)$; `img[::2].reshape(-1, 3)` fails the criterion ($3840\ne640\cdot3$) and copies.

### Four views: strides and views

**Algebra.** The offset of element $(n_0,\dots,n_{N-1})$ is $o+\sum_ks_kn_k$. Transposition permutes $(d_k,s_k)$ together, a slice replaces $(o,s_k,d_k)$ by $(o+s_k\cdot\text{start},\,s_k\cdot\text{step},\,L)$, an integer index drops an axis, and broadcasting sets $s_k=0$. Everything else, including `reshape` of a non-mergeable array, needs a copy.

**Geometry.** The array is a block of cells in space (the block above) or, equivalently, a row of numbers in memory (the figure). The strides are the three step lengths that take you from a cell to its neighbour along each direction; a slice keeps a regular sub-lattice of cells.

**Code.**
```python
import numpy as np
a = np.arange(24, dtype=np.float64).reshape(2, 3, 4)
print(a.strides, a.T.strides)                 # (96, 32, 8) (8, 32, 96)
s = a[:, ::2, 1:]
off = s.__array_interface__["data"][0] - a.__array_interface__["data"][0]
print(s.shape, s.strides, off)                # (2, 2, 3) (96, 64, 8) 8
print(a[1, 2, 3], 1*96 + 2*32 + 3*8, np.shares_memory(a, s))   # 23.0 184 True
```

**Physical meaning.** A camera or depth sensor delivers rows padded to a convenient width, so the distance between row starts (the *step* or *pitch*, in bytes; the ROS `sensor_msgs/Image` message carries a `step` field for exactly this) can exceed width times bytes per pixel. A zero-copy NumPy view over the driver's buffer uses strides $(\text{step},3,1)$ rather than $(1920,3,1)$. Stride is also why a transpose or a crop of a map costs nothing, while a copy of a large point cloud costs memory bandwidth in MB/s.

**Example.** With $o=0$ and $a$ as above the element $a[0,2,1]$ lies at $0\cdot96+2\cdot32+1\cdot8=72$ bytes, flat index 9, inside the slice $a[:,::2,1:]$ (axis 1 index 2 is kept by `::2`, axis 2 index 1 is kept by `1:`); $a[0,1,1]$ lies at 40 bytes and is not in the slice.

### Advanced indexing: the shape of the result

Basic indexing (integers and slices alone, `newaxis`, `...`) returns views. As soon as an integer array or boolean array appears the result is an **advanced-indexing copy**. The shape rule (NumPy user guide, "Indexing on ndarrays", section "Combining advanced and basic indexing"): broadcast all advanced indices to a common shape $B$ (a plain integer counts as an advanced index once any array is present). If the advanced indices are all adjacent, $B$ replaces them in place; if they are separated by a slice, `...` or `newaxis`, $B$ comes **first** and the sliced dimensions follow, because there is no unambiguous place to put it. For $y$ of shape $(5,6,7)$, `y[:, [0,1], [1,2]]` has shape $(5,2)$, but `y[0, :, [1,2]]` has shape $(2,6)$, not $(6,2)$: the integer 0 and the list are separated by `:`. To get $(6,2)$ index in two steps, `y[0][:, [1,2]]`, or use a slice `y[0, :, 1:3]`. Since advanced indexing copies, `x[idx] = v` writes into `x` (it is a `__setitem__` call) while `x[idx][0] = v` modifies a temporary and is silently lost.

**Example.** For `z = np.zeros((3,4,5))`: `z[:, [0, 2], [1, 3]]` has shape $(3,2)$ (adjacent advanced indices, broadcast to $(2,)$, replace axes 1 and 2); `z[0, :, [1, 3]]` has shape $(2,4)$, because the integer 0 and the list are separated by a slice; `z[0][:, [1, 3]]` has shape $(4,2)$ (basic, then advanced). None of the three is a view.

### Dtypes, casting and overflow

Every `ndarray` has one **dtype**, a fixed-width type shared by all its elements (NumPy user guide, "Data types"). Three rules decide most surprises. First, assignment casts the right-hand side to the array's dtype silently: `labels = np.array([4, 5, 6]); labels[1] = 5.9` stores `5` (truncation toward zero) and `labels` stays an integer array. Second, in-place operators must keep the result in the array's own type: `labels /= 2` raises `UFuncTypeError` because the float64 result cannot be cast back to int64 under the default `same_kind` rule of the ufunc `casting` argument (NumPy reference, universal functions), whereas `labels = labels / 2` creates a new float64 array. Third, fixed-width integers **wrap around** modulo $2^{8k}$ without an error when they overflow: for `uint8` values the sum $250+10$ is $260\bmod256=4$. Reductions are kinder: `np.sum` of a `uint8` array accumulates in the platform integer by default (`numpy.sum`, parameter `dtype`), so `np.array([200, 100], dtype=np.uint8).sum()` is `300` of dtype `uint64`. For images the safe pattern is to widen before doing arithmetic and clip once at the end.

**Example.** A pixel value 250 with brightness 10 added: `x = np.array([250], dtype=np.uint8)`; `x + 10` is `[4]` (wrapped), while `np.clip(x.astype(np.int16) + 10, 0, 255)` is `[255]`, the saturated value you meant.

### Cancellation: when the fast formula is the wrong one

Goldberg ("What every computer scientist should know about floating-point arithmetic", section "Cancellation") separates two cases. *Benign* cancellation subtracts exactly known quantities and has tiny relative error. *Catastrophic* cancellation subtracts quantities that already carry rounding error, so the leading digits cancel and the error that was invisible before dominates; the cure is to rewrite the formula, for instance $x^2-y^2=(x-y)(x+y)$. The squared distance has the same structure: $\|a-b\|^2=\|a\|^2+\|b\|^2-2a\cdot b$ replaces a benign difference-then-square by a subtraction of three rounded numbers. With unit roundoff $u=2^{-53}\approx1.1\times10^{-16}$ each term carries absolute error up to about $u\|a\|^2$, so the computed value is $d^2+O(u(\|a\|^2+\|b\|^2))$ and its relative error is about $u\|a\|^2/d^2$. Adding the three terms gives an absolute error of order $u(\|a\|^2+\|b\|^2+2|a\cdot b|)\approx4u\|a\|^2$, so the relative error is about $4u\|a\|^2/d^2$; for points near $(c,c)$ ($\|a\|\approx\sqrt2\,c$) and $d=0.5$ this is $32\,u\,c^2$. This is a heuristic order-of-magnitude bound, not a rigorous one: the actual error can be smaller, and is exactly zero when every intermediate number is representable. It is trustworthy only if $d/\|a\|\gg\sqrt u\approx10^{-8}$: points that agree to eight digits are lost. The same mechanism makes the one-pass variance $\overline{x^2}-\bar x^2$ fail when $|\bar x|\gg\sigma$, while the two-pass form $\frac1N\sum(x-\bar x)^2$ (centre first) is benign. Rules of thumb: centre or difference first, clip a computed squared distance at 0, and remember that cumulative sums have the same weakness, since `np.sum` uses partial pairwise summation (documented in `numpy.sum`) but `np.cumsum` accumulates sequentially, so its error grows with the prefix length.

**Example.** Two landmarks 0.5 m apart near $a=(3.0\times10^7+0.123,\,2.0\times10^7+0.456)$ and $b=a+(0.3,0.4)$ in `float64`. `((a - b)**2).sum()` returns `0.24999999925494193`, while `a@a + b@b - 2*(a@b)` returns `0.0`: here $\|a\|^2\approx1.3\times10^{15}$ and adjacent doubles near it are $0.25$ apart (`np.spacing`), the same size as the answer. Subtracting the midpoint $m=(a+b)/2$ first gives back `0.24999999925494193` with the expansion.

![Relative error of the expanded squared distance for two points 0.5 apart as the coordinates grow from 1 to 1e9: the 90th percentile follows the bound 32 u c squared and reaches 100 percent near c = 1.7e7.](/lesson-figures/PY04-5.svg)

*Figure: measured (dots) against the bound $32\,u\,c^2$ derived above with $\|a\|\approx\sqrt2\,c$ and $d=0.5$; the expansion stops being usable where the bound reaches 1. The bound is a heuristic order of magnitude; the median error saturates at 100% (the expansion returns 0 or garbage).*

### How the pieces connect

Shapes and axes (what each number means) feed reductions (which axis disappears), and `keepdims` lets the result broadcast back. Broadcasting is a stride-0 view, which is the same mechanism that makes transposes and slices free, and the free operations are views of one buffer, so they are the aliasing story of Python objects, with numbers: a write through a view is visible everywhere. Advanced indexing and the cases where `reshape` needs a copy are exactly the places where this sharing stops. Matrix products (M03) are the one place where a *contraction* replaces elementwise reasoning. Finally, floating-point rounding decides which algebraically equal formulas are equally good, and centring first is the common cure.

## Worked example

### Case 1: centering a batch along the right axis

**Problem.** `X = [[1, 2, 3], [4, 5, 6]]` holds 2 samples of 3 features. Remove each feature's mean, then remove each sample's own mean, and say which row-mean expression is legal.

**Solution.**

1. `X` has shape $(2,3)$: axis 0 is the sample axis, axis 1 the feature axis (row-sample convention).
2. Feature means: `X.mean(axis=0)` reduces axis 0, $\mu_j=\frac12\sum_iX_{ij}$, so $\mu=(2.5,\,3.5,\,4.5)$ with shape $(3,)$.
3. Broadcast $(2,3)-(3,)$: aligned from the right, $3=3$, and the missing leading axis counts as 1, so the result has shape $(2,3)$ and each row loses $\mu$: row 0 is $(1-2.5,\,2-3.5,\,3-4.5)=(-1.5,-1.5,-1.5)$ and row 1 is $(1.5,1.5,1.5)$.
4. Sample means: `X.mean(axis=1)` is $(2,\,5)$ with shape $(2,)$. The subtraction $(2,3)-(2,)$ compares $3$ with $2$: unequal and neither is 1, so it raises `ValueError`.
5. With `keepdims=True` the means have shape $(2,1)$: $(2,3)-(2,1)$ is compatible (the size-1 axis stretches over the 3 columns) and gives rows $(1-2,2-2,3-2)=(-1,0,1)$ and $(4-5,5-5,6-5)=(-1,0,1)$.

![Top: the feature means (2.5, 3.5, 4.5) of shape (3,) subtract from each row of X to give rows of -1.5 and 1.5. Bottom: the row means (2, 5) of shape (2,1) give rows (-1, 0, 1).](/lesson-figures/PY04-4.svg)

*Figure: the two centerings of Case 1, with the shapes of the mean arrays written next to them; the dashed row is the stretched copy that costs no memory.*

**Check.** The column means of the first result and the row means of the second are all 0 in NumPy 2.4.6, and a double loop over the six entries reproduces both results.

**Takeaway.** The axis you reduce is the axis that disappears; `keepdims=True` keeps it as a size-1 axis so the mean broadcasts back.

### Case 2: standardising each colour channel of a small batch (harder)

**Problem.** A batch `B` of shape $(N,H,W,C)=(2,2,2,3)$ has $B[n,h,w,c]=g_c\,(3k+c)$ with $k=4n+2h+w$ the pixel number $0,\dots,7$ and channel gains $g=(1,\,2,\,0.5)$. Standardise each channel over all $N\cdot H\cdot W=8$ pixels, using the population standard deviation.

**Solution.**

1. Per-channel statistics collapse axes $0,1,2$ and keep axis 3: `B.mean(axis=(0,1,2), keepdims=True)` has shape $(1,1,1,3)$.
2. Channel 0 holds $0,3,\dots,21$, channel 1 holds $2,8,\dots,44$ and channel 2 holds $1,\,2.5,\dots,11.5$; the means are $\mu=(10.5,\,23,\,6.25)$.
3. The variance of $0,\dots,7$ is $(8^2-1)/12=5.25$. A channel with spacing $\delta$ between consecutive pixels has variance $\delta^2\cdot5.25$: $\delta=3,6,1.5$ gives $47.25,\,189,\,11.8125$ and $\sigma=(6.874,\,13.748,\,3.437)$.
4. Broadcast $(2,2,2,3)-(1,1,1,3)$ (the equal trailing 3, and ones stretching over $N,H,W$) and divide by the $(1,1,1,3)$ array $\sigma$: $Z=(B-\mu)/\sigma$ has shape $(2,2,2,3)$.
5. The first pixel is $B[0,0,0,:]=(0,2,1)$, so $Z[0,0,0,:]=\big(\tfrac{0-10.5}{6.874},\tfrac{2-23}{13.748},\tfrac{1-6.25}{3.437}\big)=(-1.528,-1.528,-1.528)$; all three equal because each channel's first value is its minimum, $1.528\sigma$ below the mean.

**Check.** A loop over the 8 pixels of each channel gives the same means and standard deviations; `Z.mean(axis=(0,1,2))` is $(0,0,0)$ and `Z.std(axis=(0,1,2))` is $(1,1,1)$ to 12 digits. Reducing only `axis=0` would give shape $(2,2,3)$, a statistic for every pixel position, which is not per-channel.

**Takeaway.** For per-channel statistics reduce every axis except the channel axis, and keep the reduced axes with `keepdims=True` so the result broadcasts.

### Case 3: which reshapes copy? (harder)

**Problem.** `a = np.zeros((3, 4, 5))` in `float64`. For `a.reshape(12, 5)`, `a[:, ::2].reshape(6, 5)`, `a[::2].reshape(8, 5)` and `a[::2].reshape(2, 20)`, decide view or copy with the merge criterion $s_k=d_{k+1}s_{k+1}$ and confirm.

**Solution.**

1. `a` has strides $(5\cdot4\cdot8,\,5\cdot8,\,8)=(160,40,8)$ bytes.
2. `a.reshape(12, 5)` merges axes 0 and 1 (sizes 3 and 4): the criterion is $s_0=d_1s_1$, $160=4\cdot40$. It holds, so the result is a view.
3. `a[:, ::2]` has shape $(3,2,5)$ and strides $(160,80,8)$ (the step 2 doubled $s_1$). Merging axes 0 and 1 needs $160=2\cdot80$: it holds, so `.reshape(6, 5)` is a view, even though `a[:, ::2]` is not contiguous.
4. `a[::2]` has shape $(2,4,5)$ and strides $(320,40,8)$. Merging axes 0 and 1 for `.reshape(8, 5)` needs $320=4\cdot40$, but $4\cdot40=160\ne320$: false, so it is a copy.
5. `.reshape(2, 20)` of the same array merges axes 1 and 2 instead: $s_1=d_2s_2$, $40=5\cdot8$ holds, so it is a view.

**Check.** `np.shares_memory(a, ...)` gives `True, True, False, True` for the four calls (NumPy 2.4.6).

**Takeaway.** Whether `reshape` copies depends on the strides of the array you hold, not on the shapes alone; test with `np.shares_memory` when it matters.

### From scratch: a tiny strided ndarray

The core ideas of this lesson, shape, strides, offset, slicing as stride arithmetic, transposition as permutation, broadcasting as stride 0, and the view-or-copy decision of `reshape`, fit in about 90 lines of plain Python. NumPy is used only in the tests. Strides here are in elements, not bytes (multiply by the itemsize to compare).

```python
import itertools
import numpy as np

def c_strides(shape):
    """Strides, in elements, of a C-ordered array: s_k = product of the sizes after axis k."""
    st, acc = [], 1
    for d in reversed(shape):
        st.append(acc)
        acc *= d
    return tuple(reversed(st))

def prod(xs):
    p = 1
    for x in xs:
        p *= x
    return p

class Tiny:
    """A tiny strided array: one flat Python list plus shape, strides (in elements) and an offset."""
    def __init__(self, data, shape, strides=None, offset=0):
        self.data, self.shape = data, tuple(shape)
        self.strides = c_strides(self.shape) if strides is None else tuple(strides)
        self.offset = offset

    def flat_index(self, idx):                     # offset + sum_k s_k * n_k
        return self.offset + sum(s * i for s, i in zip(self.strides, idx))

    def __getitem__(self, key):                    # basic indexing only: ints and slices
        key = key if isinstance(key, tuple) else (key,)
        key += (slice(None),) * (len(self.shape) - len(key))
        shape, strides, off = [], [], self.offset
        for k, d, s in zip(key, self.shape, self.strides):
            if isinstance(k, int):                 # an integer drops the axis and shifts the offset
                k = k + d if k < 0 else k
                if not 0 <= k < d:
                    raise IndexError("index out of range")
                off += s * k
            else:                                  # a slice shifts the offset, step scales the stride
                start, stop, step = k.indices(d)
                shape.append(len(range(start, stop, step)))
                strides.append(s * step)
                off += s * start
        return self.data[off] if not shape else Tiny(self.data, shape, strides, off)

    def transpose(self, *axes):
        axes = axes or tuple(reversed(range(len(self.shape))))
        return Tiny(self.data, [self.shape[a] for a in axes], [self.strides[a] for a in axes], self.offset)

    def broadcast_to(self, shape):                 # a size-1 or missing axis gets stride 0
        shape, pad = tuple(shape), len(shape) - len(self.shape)
        if pad < 0:
            raise ValueError("cannot broadcast to fewer dimensions")
        strides = [0] * pad
        for d, s, c in zip(self.shape, self.strides, shape[pad:]):
            if d == c:
                strides.append(s)
            elif d == 1:
                strides.append(0)
            else:
                raise ValueError(f"cannot broadcast {self.shape} to {shape}")
        return Tiny(self.data, shape, strides, self.offset)

    def flat(self):                                # elements in row-major order of the logical shape
        return [self.data[self.flat_index(i)] for i in itertools.product(*map(range, self.shape))]

    def is_contiguous(self):                       # ignoring axes of size 1
        want = c_strides(self.shape)
        return all(s == w for s, w, d in zip(self.strides, want, self.shape) if d > 1)

    def reshape(self, *shape):                     # view when contiguous, copy otherwise
        if prod(shape) != prod(self.shape):
            raise ValueError("size mismatch")
        if self.is_contiguous():
            return Tiny(self.data, shape, None, self.offset)
        return Tiny(self.flat(), shape)

    def sum(self, axis):
        out_shape = self.shape[:axis] + self.shape[axis + 1:]
        out = [0] * prod(out_shape)
        for idx in itertools.product(*map(range, self.shape)):
            j = 0                                   # C-order position in the output shape
            for k, (i, d) in enumerate(zip(idx, self.shape)):
                if k != axis:
                    j = j * d + i
            out[j] += self.data[self.flat_index(idx)]
        return Tiny(out, out_shape)

def broadcast_shape(a, b):
    n = max(len(a), len(b))
    a, b = (1,) * (n - len(a)) + tuple(a), (1,) * (n - len(b)) + tuple(b)
    out = []
    for x, y in zip(a, b):
        if x == y or y == 1:
            out.append(x)
        elif x == 1:
            out.append(y)
        else:
            raise ValueError(f"shapes {a} and {b} do not broadcast")
    return tuple(out)

def binary(op, A, B):
    shape = broadcast_shape(A.shape, B.shape)
    pairs = zip(A.broadcast_to(shape).flat(), B.broadcast_to(shape).flat())
    return Tiny([op(x, y) for x, y in pairs], shape)

# ---- tests against NumPy ----
def to_np(t):
    return np.array(t.flat(), dtype=float).reshape(t.shape)

rng = np.random.default_rng(0)

assert tuple(8 * s for s in a.strides) == a_np.strides == (160, 40, 8)

for key in [(slice(None), slice(None, None, 2)), (1,), (slice(None), 2, slice(1, 4)),
            (slice(None, None, -1), slice(1, None), slice(None, None, 2)), (2, 3, 4)]:

    else:

assert np.array_equal(to_np(a.transpose(2, 0, 1)), a_np.transpose(2, 0, 1))
assert a.transpose(2, 0, 1).strides == (1, 20, 5)

for sa, sb in [((3, 1, 2), (1, 4, 2)), ((5, 3), (3,)), ((4, 1), (1, 6)), ((2, 3, 1), (3, 5))]:
    A_np, B_np = rng.integers(0, 9, sa).astype(float), rng.integers(1, 9, sb).astype(float)
    A, B = Tiny(list(A_np.ravel()), sa), Tiny(list(B_np.ravel()), sb)
    assert to_np(binary(lambda x, y: x - y, A, B)).shape == np.broadcast_shapes(sa, sb)
    assert np.array_equal(to_np(binary(lambda x, y: x * y + 1, A, B)), A_np * B_np + 1)

    broadcast_shape((5, 3), (5,))
except ValueError:

    raise AssertionError("expected ValueError")
```

### What the library does differently

- **Speed and layout.** The loops above run in Python at roughly microseconds per element; NumPy runs them in compiled C. Its iterator can reorder axes to follow memory order (NumPy reference, "Iterating over arrays", `nditer`), and many ufunc loops use SIMD instructions (NumPy reference, "CPU/SIMD optimizations"); none of this changes the results, only the time and the cache behaviour.
- **Bytes and dtypes.** Strides are in bytes, every array has a dtype with its own promotion and casting rules (see the dtype subsection), and strides may be negative, which our `[::-1]` test already needs.
- **Reshape.** Our `reshape` returns a view only for contiguous data. NumPy applies the merge criterion axis by axis and also returns a view for non-contiguous inputs such as `a[:, :, 1:4].reshape(12, 3)`; the last two assertions of the test show the difference.
- **Safety.** In-place operations check memory overlap between inputs and output and make a temporary copy when needed (NumPy 1.13.0 release notes, "Ufunc behavior for overlapping inputs"), `broadcast_to` results are read-only, and errors name the shapes involved. `np.sum` uses pairwise summation (`numpy.sum`, notes), which our left-to-right sum does not (see the cancellation subsection).
- **Scope.** The library also has advanced indexing, boolean masks, `out=` arguments, memory orders (`order='F'`) and structured dtypes, none of which are needed to understand the central mechanism.

## Failure modes

- **Square batches hide axis mistakes.** With $N=D$, `X - X.mean(axis=1)` runs and subtracts the wrong numbers; a non-square test raises or changes the shape.
- **Views overwrite the parent.** `b = a[1:4]; b[0] = 99` changes `a`; use `.copy()` when you need your own data. Advanced indexing copies, so `x[idx][0] = v` is silently lost.
- **`reshape` may or may not copy**, depending on strides; do not rely on writes through a reshaped array.
- **`uint8` wraps**: $250+10$ gives 4. Widen the dtype, compute, then clip.
- **Integer arrays truncate** float assignments (`labels[1] = 5.9` stores 5), and `x /= 2` raises on an integer array.
- **Cancellation**: the expanded squared distance and the one-pass variance lose all digits when the data are far from the origin; centre first and clip at 0.
- **Zero rows** in row normalisation produce `nan` unless the contract says otherwise.

## Alternatives and trade-offs

Explicit loops are the reference you test against, and they are the clearest code when speed does not matter. Broadcasting is compact and fast but can allocate huge temporaries (the $(N,N,2)$ array of Exercise 8); `out=`, in-place operations or processing in blocks trade code clarity for memory. `A @ B` calls optimised kernels, but check the shapes and the memory of intermediates before replacing a clear implementation. `np.einsum` states the contraction axes explicitly, which helps with batched products, at the cost of readability for newcomers. For exactly reproducible results prefer the form with the smaller rounding error (centre first, then subtract), even if it costs one more pass over the data.

(b) `a.reshape(12, 5)`: merge axes 0,1, $120=3\cdot40$ holds, view. `a.transpose(2, 0, 1).reshape(5, 12)`: shape $(5,4,3)$ strides $(8,120,40)$; merging axes 1,2 needs $120=3\cdot40$, holds, view (strides $(8,40)$). `.reshape(20, 3)` of the same array must merge axes 0,1: $8\ne4\cdot120$, copy. `a[:, ::2, :].reshape(8, 5)`: shape $(4,2,5)$ strides $(120,80,8)$; $120\ne2\cdot80$, copy. `a[:, :, 1:4].reshape(12, 3)`: shape $(4,3,3)$ strides $(120,40,8)$; $120=3\cdot40$, view. `a[:, :, 1:4].reshape(4, 9)`: merging axes 1,2 needs $40=3\cdot8=24$, false, copy. `a[0].T.reshape(15)`: shape $(5,3)$ strides $(8,40)$; $8\ne3\cdot40$, copy. `np.shares_memory(a, ...)` confirms `True, True, False, False, True, False, False`. (c) The strides are $(8,0)$: the second axis repeats one number, so the 24 positions share 4 stored values. Writing to a position would change several logical elements at once, so NumPy marks the result read-only and `b[0, 0] = 1` raises `ValueError: assignment destination is read-only`; use `.copy()` first. (d) With $m=n_kd_{k+1}+n_{k+1}$, one stride $s$ for the merged axis must give $ms=n_ks_k+n_{k+1}s_{k+1}$ for all admissible $n_k,n_{k+1}$. Taking $n_k=0$ gives $s=s_{k+1}$ (for $d_{k+1}\ge2$). Substituting into $n_k=1$, $n_{k+1}=0$ gives $d_{k+1}s_{k+1}=s_k$. Conversely, if $s_k=d_{k+1}s_{k+1}$ then $ms_{k+1}=n_kd_{k+1}s_{k+1}+n_{k+1}s_{k+1}=n_ks_k+n_{k+1}s_{k+1}$ for all $n_k,n_{k+1}$, so one stride $s_{k+1}$ works.
14. `x[i]`: $(3,7,8,9)$. `x[:, i, i]`: adjacent, $(6,3,9)$. `x[i, :, i]`: separated, $(3,7,9)$. `x[1, :, i]`: the integer 1 is advanced, separated by the slice, $(3,7,9)$. `x[:, i, :, i]`: $(3,6,8)$. `x[:, 1, :, i]`: $(3,6,8)$. `x[..., i, 0]`: adjacent, $(6,7,3)$. `x[i[:,None], i[None,:]]`: broadcast to $(3,3)$ then the rest, $(3,3,8,9)$. For `y`: the integer 0 and the list are advanced, separated by `:`, so the broadcast shape $(2,)$ goes first: $(2,6)$. To get $(6,2)$: `y[0][:, [1,2]]` (basic then advanced) or `y[0, :, 1:3]` (slice); `y[0,:,[1,2]].T` also works (the values are equal). Only a pure slice (like `x[1:3]` or `y[0,:,1:3]`) is a view; every indexing with an array above is a copy (`np.shares_memory(x[:, i], x)` is `False`).
15. (a) `((a-b)**2).sum()` is `1.0`; the expansion gives `0.0` (wrong by 100%). (b) Near $2\times10^{16}$ doubles are spaced 4 apart (`np.spacing(2e16) == 4.0`), so $\|a\|^2=\|b\|^2\approx2\times10^{16}$ and $2a\cdot b$ are each rounded by up to 2, comparable to the true $d^2=1$. (c) The error is about $u(\|a\|^2+\|b\|^2+2a\cdot b)\approx4u\|a\|^2$; requiring it $\le0.01\,d^2$ gives $d/\|a\|\ge\sqrt{400u}\approx2.1\times10^{-7}$. Here $d/\|a\|=1/1.41\times10^8=7\times10^{-9}$, far too small. (d) With $m=(a+b)/2=(10^8+0.5,10^8)$, $a'=a-m=(-0.5,0)$ and $b'=b-m=(0.5,0)$ are exact, and the expansion gives exactly `1.0`. It is legitimate because distances are translation invariant, $\|(a-m)-(b-m)\|=\|a-b\|$, and after centering the norms are of the order of the spread, so $u\|a'\|^2$ is negligible. (This is the matrix-form analogue of Goldberg's rewriting $x^2-y^2=(x-y)(x+y)$.)
16. (a) Computed with NumPy 2.4.6 in `float64`: $c=10^4$: 1.25; $10^7$: 1.25; $10^8$: 2.0; $10^9$: 0.0; `np.var` is 1.25 every time. (b) In `float32` with $c=10^4$ the one-pass formula returns $-8.0$ (a negative variance!), `np.var` returns 1.25. (c) $\overline{(x-K)^2}=\overline{x^2}-2K\bar x+K^2$ and $\overline{(x-K)}^2=\bar x^2-2K\bar x+K^2$; subtracting leaves $\overline{x^2}-\bar x^2=\mathrm{Var}(x)$. Taking $K$ near $\bar x$ (for example the first sample) makes $x-K$ of the order of $\sigma$, so $\overline{x^2}$ and $\bar x^2$ are no longer huge numbers that cancel; with $K=x_0$ the float64 result for $c=10^8$ is exactly 1.25. (d) $\overline{x^2}$ and $\bar x^2$ each carry rounding error of order $u\,c^2$; when $\sigma^2\lesssim u\,c^2$ their rounded difference is dominated by error and may be negative.
17. (a) The final prefix sum is about $1.97\times10^8$, where `float32` numbers are 16 apart (`np.spacing(np.float32(1.97e8)) == 16`). Each prefix sum is rounded to that grid and the window sum is a difference of two of them, so errors of one to two spacings (tens) enter the sum and several units the mean, even though the true window mean is about 100. (b) Measured against the `float64` convolution: worst error 6.25 for the `float32` cumulative sum (about 0.003 in the first thousand windows, 5.6 in the last thousand, so it grows with the prefix length), $2.8\times10^{-14}$ for the `float64` cumulative sum, and $1.5\times10^{-5}$ for `float32` `np.convolve` (every window sums only 5 numbers). (c) Fixes: accumulate in `float64` (`np.cumsum(sig, dtype=np.float64)`, doubles the memory of the prefix array); or subtract the mean (or a running offset) first so the prefix sums stay small, or restart the cumulative sum in blocks, or use `np.convolve` / `sliding_window_view(...).mean(-1)` which costs $O(nk)$ instead of $O(n)$. The trade-off is memory and time against accuracy.
