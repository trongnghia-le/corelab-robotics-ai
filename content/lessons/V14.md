## Why this matters

A robot rarely trains a vision model from scratch. It starts from an encoder pretrained on millions of images, freezes or lightly tunes it, and attaches a small head for its own task: recognising grasp targets, classifying terrain, matching places. Whether that works depends on the embedding, the vector the encoder outputs, and on how different the robot's images are from the pretraining images. A representation that scores 95 % on the lab bench can fall to chance in a warehouse with different lighting. This lesson teaches how embeddings are shaped, how to evaluate them honestly, and how to tell a representation failure from a head failure.

## Intuition

An encoder $f_\theta$ maps an image $x$ to a vector $z=f_\theta(x)\in\mathbb R^d$. Two images that should be treated alike should land near each other; two that should be separated should land far apart. "Alike" is defined by the training signal: class labels (supervised), two augmentations of the same image (contrastive), or a missing patch to be predicted (masked modelling).

An embedding has no meaning on its own. It is only useful if a simple downstream model can read the task from it. So we judge it by a **probe**: freeze the encoder, fit something small (nearest class mean, k-NN or a linear classifier) on labelled embeddings, and measure accuracy on held-out data. If the held-out data come from a different distribution, the probe's gap between in-domain and shifted accuracy tells you how much of the representation was specific to the pretraining domain.

## Theory and derivation

### Cosine similarity and normalisation

$\cos(a,b)=\dfrac{a\cdot b}{\|a\|\,\|b\|}\in[-1,1]$. Most contrastive models L2-normalise embeddings, so only direction matters, and the dot product equals the cosine.

### InfoNCE (NT-Xent)

For an anchor $z_i$, one positive $z_i^+$ (another view of the same image) and negatives $\{z_j^-\}$, with temperature $\tau>0$:
$$\mathcal L_i=-\log\frac{\exp(\cos(z_i,z_i^+)/\tau)}{\exp(\cos(z_i,z_i^+)/\tau)+\sum_j\exp(\cos(z_i,z_j^-)/\tau)} .$$
It is a softmax cross-entropy that asks the positive to win among $1+K$ candidates. Facts that follow directly:

- With all similarities equal, the loss is $\log(1+K)$: the chance level. A collapsed encoder that maps everything to one vector sits exactly there.
- A small $\tau$ sharpens the softmax, so a hard negative with similarity near the positive's is punished harder; a large $\tau$ flattens it.
- More negatives per anchor (a larger batch) make the task harder and the loss higher at the same quality.

### Why pretraining transfers (and when it does not)

A deep encoder's early layers learn generic features (edges, textures); later layers become task-specific. CS231n's rule of thumb:

| New dataset | Similar to pretraining | Different from pretraining |
|---|---|---|
| Small | Train a linear probe on frozen features | Probe from earlier layers, or get more data |
| Large | Fine-tune the whole network at a low learning rate | Fine-tune, possibly most layers, or train longer |

### Shift and shortcuts

If pretraining labels or augmentations can be solved with a shortcut (background colour, a watermark), the embedding encodes the shortcut and the probe fails when it changes. A shift is detectable only on a **held-out domain**, a test set drawn from a different source, not on a random split of the training source.

## Worked example

### InfoNCE loss for one anchor

**Problem.** Anchor $a=(1,0)$, positive $p=(0.8,0.6)$, negatives $n_1=(0,1)$ and $n_2=(-1,0)$, temperature $\tau=0.5$. Find the InfoNCE loss of the anchor, compare it with chance, and find the loss when $\tau=0.1$.

**Solution.**

1. Cosine similarity needs unit norms. $\|p\|=\sqrt{0.64+0.36}=1$ and the other vectors are unit already, so cosines are dot products: $\cos(a,p)=0.8$, $\cos(a,n_1)=0$, $\cos(a,n_2)=-1$.
2. Logits are $\cos/\tau$: $0.8/0.5=1.6$, $0/0.5=0$, $-1/0.5=-2$.
3. Exponentials: $e^{1.6}=4.9530$, $e^{0}=1$, $e^{-2}=0.1353$. The denominator is $4.9530+1+0.1353=6.0883$.
4. The positive's softmax share is $4.9530/6.0883=0.8135$.
5. Loss $\mathcal L=-\ln0.8135=0.2064$.
6. With $\tau=0.1$ the logits are $8,\ 0,\ -10$; $e^{8}=2980.96$, $e^{0}=1$, $e^{-10}=0.0000454$; the sum is $2981.96$, the share is $0.99966$ and $\mathcal L=0.00034$.

**Check.** Chance with 3 candidates is $\ln(1+K)=\ln3=1.0986$ ($K=2$ negatives), and $0.206$ is well below it. A second form of the same loss, $\ln\bigl(1+\sum_je^{(s_j-s_+)/\tau}\bigr)=\ln(1+e^{-1.6}+e^{-3.6})=\ln(1+0.2019+0.0273)=\ln1.2292=0.2064$, agrees.

**Takeaway.** The same geometry looks far better solved at low temperature (0.00034 against 0.206), so losses are comparable only at equal $\tau$ and equal $K$.

## Reference implementation

The embeddings here are small vectors, so everything runs on the standard library. `rotate` stands in for a domain shift.

```python
import math

def dot(a, b): return sum(x*y for x, y in zip(a, b))
def norm(a): return math.sqrt(dot(a, a))
def normalize(a):
    n = norm(a)
    return [x/n for x in a]
def cosine(a, b): return dot(a, b)/(norm(a)*norm(b))

def info_nce(anchor, positive, negatives, tau=0.5):
    """-log softmax of the positive among {positive} + negatives, logits = cosine / tau."""
    logits = [cosine(anchor, positive)/tau] + [cosine(anchor, n)/tau for n in negatives]
    m = max(logits)
    log_z = m + math.log(sum(math.exp(l - m) for l in logits))
    return log_z - logits[0]

def class_means(X, y):
    out = {}
    for c in sorted(set(y)):
        pts = [normalize(x) for x, l in zip(X, y) if l == c]
        d = len(pts[0])
        out[c] = [sum(p[i] for p in pts)/len(pts) for i in range(d)]
    return out

def predict_nearest_mean(means, x):
    """Frozen-embedding classifier: label whose mean has the highest cosine with x."""
    return max(means, key=lambda c: cosine(means[c], x))

def accuracy(means, X, y):
    return sum(predict_nearest_mean(means, x) == l for x, l in zip(X, y))/len(y)

def rotate(X, deg):
    c, s = math.cos(math.radians(deg)), math.sin(math.radians(deg))
    return [[c*x - s*y, s*x + c*y] for x, y in X]

if __name__ == "__main__":
    # InfoNCE: anchor (1,0), positive cos 0.8, negatives cos 0 and -1, tau 0.5
    loss = info_nce([1, 0], [0.8, 0.6], [[0, 1], [-1, 0]], 0.5)
    expect = -math.log(math.exp(1.6)/(math.exp(1.6) + 1 + math.exp(-2)))
    assert abs(loss - expect) < 1e-12
    print("InfoNCE loss:", round(loss, 4))
    # a frozen classifier trained at 0 deg, tested after the domain is rotated
    A = [[1, 0.2], [0.9, -0.1], [1.1, 0.0]]; B = [[0.0, 1.0], [0.1, 1.2], [-0.1, 0.9]]
    X, y = A + B, [0]*3 + [1]*3
    means = class_means(X, y)
    for deg in (0, 30, 60, 90, 180):
        print("shift", deg, "deg accuracy", accuracy(means, rotate(X, deg), y))
    assert accuracy(means, X, y) == 1.0 and accuracy(means, rotate(X, 180), y) == 0.0
    print("self-test passed")
```

### Library track

Redo the batch loss and the probe with PyTorch and NumPy, and check them against the stdlib `info_nce_batch` and `shift_report` from the lab (put the reference and your lab functions above this code). It also trains a tiny linear encoder with SGD to see InfoNCE fall below its starting value.

```python
import math
import numpy as np
import torch
import torch.nn.functional as F

# --- batch InfoNCE with torch: logits = cosine / tau, positives on the diagonal ---
def info_nce_torch(Z1, Z2, tau=1.0):
    z1, z2 = F.normalize(Z1, dim=1), F.normalize(Z2, dim=1)
    sim = z1 @ z2.T / tau                   # sim[i, j] = cos(Z1[i], Z2[j]) / tau
    return F.cross_entropy(sim, torch.arange(len(Z1)))   # -log softmax of the diagonal

Z = torch.tensor([[1.0, 0.0], [0.0, 1.0]])
assert abs(info_nce_torch(Z, Z, 1.0).item() - math.log(1 + math.exp(-1))) < 1e-6   # = 0.3133
same = torch.tensor([[1.0, 2.0]] * 4)
assert abs(info_nce_torch(same, same, 0.3).item() - math.log(4)) < 1e-6              # collapse
torch.manual_seed(0)
Z1, Z2 = torch.randn(8, 16), torch.randn(8, 16)
# cross-check with the stdlib info_nce_batch from the lab (same maths, plain Python)
ref = info_nce_batch(Z1.tolist(), Z2.tolist(), 0.5)
assert abs(info_nce_torch(Z1, Z2, 0.5).item() - ref) < 1e-5

# --- the nearest-mean probe, vectorised with numpy; accuracy must equal the stdlib report ---
A = [[1, 0.2], [0.9, -0.1], [1.1, 0.0]]; B = [[0.0, 1.0], [0.1, 1.2], [-0.1, 0.9]]
X, y = np.array(A + B), np.array([0]*3 + [1]*3)
U = X / np.linalg.norm(X, axis=1, keepdims=True)
M = np.stack([U[y == c].mean(0) for c in (0, 1)])           # class means of unit vectors
def acc_at(deg):
    c, s = np.cos(np.radians(deg)), np.sin(np.radians(deg))
    Xr = X @ np.array([[c, s], [-s, c]])                    # rows rotated by +deg
    cos = (Xr @ M.T) / (np.linalg.norm(Xr, axis=1)[:, None] * np.linalg.norm(M, axis=1))
    return float((cos.argmax(1) == y).mean())
rep = [(d, acc_at(d)) for d in (0, 90, 180)]
assert rep == [(0, 1.0), (90, 0.5), (180, 0.0)], rep

# --- a trainable check: SGD on a linear encoder lowers InfoNCE below log(K+1) on noisy views ---
torch.manual_seed(1)
base = torch.randn(64, 8)
enc = torch.nn.Linear(8, 4, bias=False)
opt = torch.optim.SGD(enc.parameters(), lr=0.5)
start = info_nce_torch(enc(base + 0.1 * torch.randn_like(base)), enc(base + 0.1 * torch.randn_like(base)), 0.5).item()
for _ in range(200):
    v1, v2 = base + 0.1 * torch.randn_like(base), base + 0.1 * torch.randn_like(base)
    loss = info_nce_torch(enc(v1), enc(v2), 0.5)
    opt.zero_grad(); loss.backward(); opt.step()
print("loss start/end:", round(start, 3), round(loss.item(), 3), "chance:", round(math.log(64), 3))
assert loss.item() < start
print("library track passed")
```

For real images, replace `base` with features from a pretrained `torchvision` model and keep the same loss and probe; that part is not run here.

## Verification

- Sanity: InfoNCE with identical logits must equal $\log(1+K)$; a trained encoder must be below it on held-out pairs.
- Report the gap `in-domain accuracy - shifted accuracy`, not just the shifted number, and include the majority-class baseline.
- Test on an actually different source, not a re-split. Check the class balance in each split.
- Boundary case: an extreme shift (here 180 degrees) should drive a frozen probe to or below chance; if it does not, the shift is not hurting what you think.

## Failure modes

| Mistake | Symptom |
|---|---|
| Evaluating on a random split of the pretraining domain | Optimistic accuracy; shift invisible |
| Forgetting to normalise before a dot product | Large-norm images dominate; wrong neighbours |
| Collapse (everything maps to one vector) | InfoNCE stuck at $\log(1+K)$ |
| Shortcut features (background, watermark) | High in-domain, near-chance accuracy when the shortcut changes |
| Fine-tuning a big network on 300 images with a large learning rate | Pretrained features destroyed, test accuracy drops |
| Comparing encoders with different probe budgets | Differences reflect the head, not the representation |

## Alternatives and trade-offs

- **Frozen probe**: cheap, hard to overfit, reveals representation quality; limited by what the encoder already knows.
- **Partial fine-tuning**: adapts later layers; needs enough data and a small learning rate.
- **Full fine-tuning**: best with large target data; risks forgetting.
- **Supervised vs contrastive vs masked pretraining**: supervised is strongest when labels match your task; contrastive needs good augmentations and large batches; masked modelling captures local structure.
- **Training from scratch**: only reasonable with large, specific data.

## Transfer and retention

The held-out-domain habit applies to every learned component, from grasp detectors to RL policies (sim-to-real). Embeddings are the shared interface for retrieval and place recognition (V17), vision transformers (V15) and foundation models (V18). Prompts for retention: Why does the loss equal $\log(1+K)$ at collapse? Which part of the table would you choose for 300 images of a very different domain? What does a probe measure that the pretraining loss does not?

## Exercise answers

1. Small and fairly similar, so train only a linear probe (or small head) on frozen features. Fine-tuning all layers on 300 images overfits and destroys generic features.
2. Random features of a decent architecture already preserve a lot of local structure, so a simple probe on them can beat chance by a wide margin. Always report an untrained-encoder and majority-class baseline so pretrained gains are measured relative to them.
3. $a\cdot b=24$, $\|a\|=\|b\|=5$, so $\cos=24/25=0.96$.
4. All logits equal, so each candidate has probability $1/4$ and the loss is $\ln4=1.386$ for any $\tau$. A collapsed encoder makes all cosines 1 (identical vectors), so the logits are equal.
5. Logits $0.8,0,-1$: exponentials $2.2255,1,0.3679$, sum $3.5934$; share $0.6193$; loss $0.4791$. A larger $\tau$ lowers the positive's lead, so the loss is higher; the gradient is spread more evenly across negatives rather than focused on hard ones.
6. It uses the raw dot product, but class means of unit vectors have different lengths (a scattered class has a short mean). Example: $m_0=(1,0)$, $m_1=(0.2,0.2)$, $x=(1,1)$: dot products $1$ vs $0.4$ pick class 0, while cosines $0.707$ vs $1.0$ pick class 1, which is the direction-correct answer. Fix: use `cosine`, as `predict_nearest_mean` does.
7. Fit the same head on a small labelled sample from the shifted camera (or train on camera B and test on A): if shifted accuracy jumps with few labels the head was fine and the representation or domain differed; also compare with an untrained-encoder baseline on both sets.
8. Pretraining restricts the solution to features that explain the unlabelled data, which regularises. It can hurt when those features throw away what the task needs, for example an encoder pretrained with colour-jitter augmentations that discards colour, then used to sort red and green parcels.
9. Euclidean distance: $\|x-m\|^2=1-2x\cdot m+\|m\|^2$. The argmin equals the argmax of $x\cdot m$ only if $\|m\|^2$ is the same for all classes. Counterexample: $m_0=(1,0)$ (norm 1), $m_1=(0.2,0.2)$, $x=(1,1)/\sqrt2$: dot $0.707$ vs $0.283$ picks class 0, distance$^2$ $=1-1.414+1=0.586$ vs $1-0.566+0.08=0.514$ picks class 1.
10. A good answer names concrete sets (e.g. training on bench-top images, testing on warehouse images), a majority-class and untrained-encoder baseline, the metric with a confidence interval or repeated seeds, an extreme shift (night, a different lens), and a rejection rule such as "shifted accuracy within 5 points of the baseline".
