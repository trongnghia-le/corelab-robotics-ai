## Why this matters

The symbolic planner of E05 happily outputs `pick(box)`, `place(box,S)` because the preconditions hold in the model. The arm may not be able to get there: the box is too close to the base for the elbow limit, or the slot is beyond maximum reach. The physical world adds constraints that the symbols never mentioned. TAMP is the discipline of combining both: search over action sequences, check and choose continuous values (base poses, grasp poses, paths) so the sequence can be executed, and use failures to guide the search.

It builds on E05 (operators, preconditions, plans) and R05 (inverse kinematics: the ring, branches, joint limits). Everything in this lesson reuses those pieces.

## Intuition

Think of the symbolic planner as proposing and the geometric layer as disposing. Each symbolic action leaves some continuous *parameters* open: where should the base stand, which grasp pose, which path? A symbolic action is **feasible** only if a choice of parameters exists that satisfies the geometric constraints. The planner explores candidate plans; for each candidate the geometry checks (or tries to find) parameters, and reports a reason when it fails.

## Theory and derivation

### Two layers

- **Task layer (symbolic).** States, operators with preconditions and effects as in E05; actions such as `move_base(b)`, `pick(o)`, `place(o,s)`.
- **Motion layer (geometric).** For each action a continuous problem: find parameters $\theta$ (base pose, grasp pose, joint configuration) with constraints $g(\theta)\le0$: reachability, joint limits, collision-free path, force or stability limits.

The coupling is that each symbolic action instance is feasible only if its continuous problem has a solution given the *current* continuous state (where the base is, what is held).

### Necessary geometric conditions for a planar 2R arm

With the arm base at $b$ and a target point $p$, let $r=\lVert p-b\rVert$. The conditions below use the conventions of R05 (relative joint angles):

1. **Reach ring**: $|l_1-l_2|\le r\le l_1+l_2$. Outside it there is no IK solution.
2. **Joint limits**: from $r^2=l_1^2+l_2^2+2l_1l_2\cos q_2$, an elbow limit $|q_2|\le q_{2,\max}$ with $q_{2,\max}<\pi$ raises the *inner* radius:
$$r_{\min}=\sqrt{l_1^2+l_2^2+2l_1l_2\cos q_{2,\max}}\ >\ |l_1-l_2|.$$
3. **Verification**: for each candidate $(q_1,q_2)$ check the forward-kinematics residual.

These are *necessary* conditions for a pick. They are not sufficient: orientation of the gripper, collisions along the path, and stability can still fail. Reachability therefore plays the same role as the delete relaxation of E05: failure proves infeasibility of that action instance, success does not prove executability.

### Generate and test

1. The symbolic planner generates candidate plans in increasing cost.
2. A geometric checker walks through each plan, tracking continuous state (here, the current base), and tests each pick and place. It returns *which* step failed and *why*.
3. The first plan with no failures is executed (after full motion planning).
4. If every candidate fails, the task is infeasible for the discretisation of continuous choices used (here: the base poses offered). A larger or sampled set of base poses may repair it.

If the number of base poses is $K$, the candidate plans for one object that place the base up to twice number $K^2$ in this lesson's generator (no move: 1; one move before pick or before place: $2(K-1)$; two moves: $(K-1)^2$). With several objects the count multiplies, so waiting for the geometric layer to reject each one is wasteful.

### Feeding failures back

The efficient approach pushes geometry into the symbolic layer. Each failed check yields a *constraint*: "`pick(box)` is not feasible from `B0`". Adding a symbolic precondition `base_ok(box, b)` (computed by a geometric *semantic attachment* or a *stream*, as in PDDLStream) lets the planner avoid the whole family of plans containing it. Failures can also be learned as nogoods that exclude a sub-plan.

## Worked example

Arm: $l_1=0.8$, $l_2=0.5$ (ring $0.3$ to $1.3$), elbow limit $|q_2|\le2.6$ rad, so $r_{\min}=\sqrt{0.89+0.8\cos2.6}=0.452$. Bases: $B_0=(0,0)$, $B_1=(0.9,0)$. Box at $(0.2,0.1)$, slot $S=(1.3,-0.4)$. Task: put the box in $S$; the robot starts at $B_0$.

**Step 1, symbolic plan.** The shortest plan is `pick(box)`, `place(box,S)`: two steps, all symbolic preconditions hold.

**Step 2, geometry from $B_0$.** Pick: $r=\lVert(0.2,0.1)\rVert=0.224<0.452$ (inside the hole): rejected, reason inside_min_reach_or_joint_limits. Place: $r=\lVert(1.3,-0.4)\rVert=1.360>1.3$: rejected, reason beyond_max_reach. Two independent reasons.

**Step 3, next candidate.** `move_base(B1)`, `pick(box)`, `place(box,S)`. From $B_1$: pick target relative to the base is $(-0.7,0.1)$, $r=0.707$; place target is $(0.4,-0.4)$, $r=0.566$. Both lie in $[0.452,1.3]$.

**Step 4, IK and verification.** For the pick: $c=(0.5-0.89)/0.8=-0.4875$, $q_2=\pm2.080$, within $\pm2.6$; $q_1=-2.618$ or $2.334$. For the place: $c=(0.32-0.89)/0.8=-0.7125$, $q_2=\pm2.364$, within the limit; $q_1=-1.454$ or $-0.116$. Forward kinematics reproduces both targets with residual below $10^{-9}$.

**Step 5, result.** The plan with the base move is accepted after one rejection.

**Step 6, a limit-only rejection.** A target at distance $0.4$ is inside the plain ring ($0.3\le0.4$) yet needs $q_2=\pm\arccos(-0.9125)=\pm2.72>2.6$, so the elbow limit rejects it.

**Step 7, an impossible task.** If the box is at $(3,0)$, the distance from $B_0$ is 3 and from $B_1$ is 2.1, both above 1.3: all four candidates are rejected and the answer is "no plan with these base poses", with reasons.

## Reference implementation

Planar 2R IK with limits, reachability reasons, a plan checker and generate-and-test TAMP for a mobile-base pick-and-place.

```python
import math

L1, L2 = 0.8, 0.5
Q1_LIM, Q2_LIM = (-math.pi, math.pi), (-2.6, 2.6)        # radians; relative joint angles (as in R05)
BASES = {"B0": (0.0, 0.0), "B1": (0.9, 0.0)}             # where the mobile base can park
OBJECTS = {"box": (0.2, 0.1)}
SLOTS = {"S": (1.3, -0.4)}

def fk(q1, q2, l1=L1, l2=L2):
    return (l1 * math.cos(q1) + l2 * math.cos(q1 + q2), l1 * math.sin(q1) + l2 * math.sin(q1 + q2))

def wrap(a):
    return (a + math.pi) % (2 * math.pi) - math.pi

def ik_solutions(target, l1=L1, l2=L2, q1_lim=Q1_LIM, q2_lim=Q2_LIM, tol=1e-9):
    """All planar-2R solutions (elbow up/down) for a target in the arm frame that satisfy the joint limits."""
    x, y = target; r2 = x * x + y * y
    if not (abs(l1 - l2) - tol <= math.sqrt(r2) <= l1 + l2 + tol):
        return []                                                   # outside the ring
    c = max(-1.0, min(1.0, (r2 - l1 * l1 - l2 * l2) / (2 * l1 * l2)))   # clamp only AFTER the ring test
    sols = []
    for q2 in {math.acos(c), -math.acos(c)}:
        q1 = wrap(math.atan2(y, x) - math.atan2(l2 * math.sin(q2), l1 + l2 * math.cos(q2)))
        if q1_lim[0] <= q1 <= q1_lim[1] and q2_lim[0] <= q2 <= q2_lim[1]:
            fx, fy = fk(q1, q2, l1, l2)
            if math.hypot(fx - x, fy - y) < 1e-6:                   # verify by forward kinematics
                sols.append((q1, q2))
    return sorted(sols)

def reachable_from(base, point):
    """Can the arm mounted at `base` reach the world point? Returns (bool, reason)."""
    rel = (point[0] - base[0], point[1] - base[1])
    r = math.hypot(*rel)
    if r > L1 + L2 + 1e-9:
        return False, "beyond_max_reach"
    if not ik_solutions(rel):
        return False, "inside_min_reach_or_joint_limits"
    return True, "ok"

def candidate_plans(obj, slot, start_base, bases):
    """All symbolic plans for 'move obj to slot', shortest first. A plan is a list of steps
    ('move_base', b), ('pick', obj), ('place', obj, slot)."""
    names = sorted(bases); plans = []
    plans.append([("pick", obj), ("place", obj, slot)])
    for b in names:
        if b != start_base:
            plans.append([("move_base", b), ("pick", obj), ("place", obj, slot)])
            plans.append([("pick", obj), ("move_base", b), ("place", obj, slot)])
    for b1 in names:
        for b2 in names:
            if b1 != start_base and b2 != b1:
                plans.append([("move_base", b1), ("pick", obj), ("move_base", b2), ("place", obj, slot)])
    return sorted(plans, key=len)

def check_plan(plan, start_base, bases, objects, slots):
    """Geometric check of a symbolic plan. Return (ok, failures) where failures lists
    (step_index, step, reason) for every step whose target is unreachable from the current base."""
    base = start_base; fails = []
    for i, step in enumerate(plan):
        if step[0] == "move_base":
            base = step[1]
        else:
            point = objects[step[1]] if step[0] == "pick" else slots[step[2]]
            ok, reason = reachable_from(bases[base], point)
            if not ok:
                fails.append((i, step, reason))
    return (not fails), fails

def tamp(obj, slot, start_base, bases, objects, slots):
    """Generate-and-test TAMP: return (first geometrically feasible plan or None, rejected candidates)."""
    rejected = []
    for plan in candidate_plans(obj, slot, start_base, bases):
        ok, fails = check_plan(plan, start_base, bases, objects, slots)
        if ok:
            return plan, rejected
        rejected.append((plan, fails))
    return None, rejected

if __name__ == "__main__":
    plan, rej = tamp("box", "S", "B0", BASES, OBJECTS, SLOTS)
    print("chosen plan:", plan)
    for p, f in rej:
        print("rejected", [s[0] if s[0] != "move_base" else "move_base(%s)" % s[1] for s in p], "->", [(i, r) for i, _, r in f])
    print("IK of (0.9, -0.6):", [tuple(round(v, 4) for v in s) for s in ik_solutions((0.9, -0.6))])
    far = {"box": (3.0, 0.0)}
    print("box at (3,0):", tamp("box", "S", "B0", BASES, far, SLOTS)[0])
    assert plan == [("move_base", "B1"), ("pick", "box"), ("place", "box", "S")]
    print("self-test passed")
```

Expected: chosen plan `move_base(B1)`, `pick(box)`, `place(box,S)` after one rejected candidate with two reasons; the IK of $(0.9,-0.6)$ equals the R05 example; no plan for the object at $(3,0)$.

The script solves the same IK problems numerically with `scipy.optimize.least_squares` from 40 random starts (joint limits as bounds) and compares the branches with your analytic `ik_solutions`, then evaluates the reach annulus on a grid of base positions to get the area from which both box and slot are reachable (project exercise 10).

```python
import numpy as np
from scipy.optimize import least_squares
from lab_e06 import ik_solutions, fk, reachable_from, L1, L2

rng = np.random.default_rng(0)

# 1. independent IK check: numerical least squares from many random starts, joint limits as bounds.
def ik_numeric(target, tries=40):
    found = []
    for _ in range(tries):
        x0 = rng.uniform([-np.pi, -2.6], [np.pi, 2.6])
        res = least_squares(lambda q: np.array(fk(*q)) - target, x0,
                            bounds=([-np.pi, -2.6], [np.pi, 2.6]))
        if res.cost < 1e-16 and not any(np.allclose(res.x, f, atol=1e-5) for f in found):
            found.append(res.x)
    return sorted(map(tuple, found))

for target in [(0.9, -0.6), (-0.7, 0.1), (0.4, -0.4), (0.4, 0.0), (1.4, 0.0)]:
    mine = ik_solutions(target); other = ik_numeric(np.array(target))
    assert len(mine) == len(other), (target, mine, other)
    assert all(np.allclose(a, b, atol=1e-4) for a, b in zip(mine, other))
print("analytic IK matches least_squares on 5 targets (including (0.4, 0): no solution, limit)")

# 2. vectorised reachability over a grid of base positions -> area where BOTH box and slot are reachable
def reach_mask(bx, by, point, rmin=np.sqrt(L1**2 + L2**2 + 2 * L1 * L2 * np.cos(2.6)), rmax=L1 + L2):
    r = np.hypot(point[0] - bx, point[1] - by)
    return (r >= rmin) & (r <= rmax)

xs = np.linspace(-2, 3.5, 1101); ys = np.linspace(-2, 2, 801)
BX, BY = np.meshgrid(xs, ys)
both = reach_mask(BX, BY, (0.2, 0.1)) & reach_mask(BX, BY, (1.3, -0.4))
area = both.sum() * (xs[1] - xs[0]) * (ys[1] - ys[0])
print("area of base positions serving both box and slot: %.3f m^2" % area)
assert 1.4 < area < 1.65
# the closed-form radius agrees with the pure-Python test at random bases
for bx, by in rng.uniform([-1, -1], [2, 1], (200, 2)):
    assert bool(reach_mask(bx, by, (0.2, 0.1))) == reachable_from((bx, by), (0.2, 0.1))[0]
print("slot reachable from B0, B1:", bool(reach_mask(0.0, 0.0, (1.3, -0.4))), bool(reach_mask(0.9, 0.0, (1.3, -0.4))))
```

Expected: the analytic and numerical IK agree on all five targets, including the limit-only rejection at $(0.4,0)$, and the area is about 1.52 m$^2$. PDDLStream would plug the same feasibility test in as a stream sampler (not run here).

## Verification

- Verify every IK answer by forward kinematics and check angle limits on each branch.
- Test ring edges, the inner hole, and a point blocked only by the joint limit.
- Check that every step of an accepted plan was tested with the base position at that step.
- Compare the geometric rejections with a brute-force joint-space sample of the arm: no sampled configuration should reach a rejected point.

## Failure modes

- **World versus arm frame** (exercise 5): forgetting to subtract the base rejects a feasible pick; here $0.224$ versus $0.707$.
- **Using only the final pose**: checking the place but not the pick accepts an impossible plan.
- **Ring test only**: a target at $r=0.4$ passes the ring but needs $|q_2|=2.72>2.6$.
- **Clamping before the ring test**: `acos` of a clamped cosine makes unreachable targets look reachable.
- **Treating reachability as executability**: collisions, wrist orientation and holding the object are still unchecked.
- **Infeasible reported as impossible**: with a finite base list the correct statement is "no plan with these base poses".
- **Stale continuous state**: after `move_base` the checker must use the new base.

## Alternatives and trade-offs

| Approach | Strength | Weakness |
| --- | --- | --- |
| Generate-and-test (this lesson) | Simple, modular | Wastes work on many infeasible candidates |
| Geometric predicates in the symbolic domain | Prunes early | Needs precomputation per object/base pair |
| Streams / PDDLStream | Lazily samples continuous values | More machinery; sampler design |

Use generate-and-test to learn the structure and for tiny problems; use streams or predicates when there are many objects.

The skills of E04 are the executable units; the operators of E05 are their abstractions; the IK of R05 supplies the first feasibility test. ## Exercise answers

1. Kinematics: the object is beyond the reach or inside the inner hole of the arm, or needs a joint outside its limits. Collisions: a straight path to the object passes through another object or the table edge, even though each pose is reachable. A good answer notes that the symbolic model has no geometry.
2. Max $=0.6+0.4=1.0$, min $=|0.6-0.4|=0.2$.
3. $r=\sqrt{0.25+0.25}=0.7071$, within $[0.2,1.0]$: reachable (two elbow branches).
4. $r_{\min}=\sqrt{l_1^2+l_2^2+2l_1l_2\cos2.6}$ with $\cos2.6=-0.8569$: $\sqrt{0.89-0.6855}=\sqrt{0.2045}=0.4522$. At $r=0.40$: ring test passes ($0.3\le0.4$) but $c=(0.16-0.89)/0.8=-0.9125$, so $|q_2|=2.72>2.6$: not reachable. The ring ignores limits.
5. `ik_solutions` expects a target in the arm frame, but the point is in world coordinates; the base offset must be subtracted: `ik_solutions((point[0]-base[0], point[1]-base[1]))`. With base $B_1=(0.9,0)$ the world point $(0.2,0.1)$ has $r=0.224$ (rejected) versus the correct arm-frame $r=0.707$ (accepted).
6. Box at $(0.9,0)$: candidates in order: (1) `pick, place`: pick from $B_0$ has $r=0.9$ fine, place $S$ has $r=1.36>1.3$: rejected. (2) `move_base(B1), pick, place`: pick from $B_1$ has $r=0$ (inside the hole): rejected. (3) `pick, move_base(B1), place`: pick from $B_0$ ok, place from $B_1$ ok ($r=0.566$): returned.
7. Add `base_ok(o,b)` to the preconditions of `pick(o)` (and a place version). A geometric module computes it by running the reachability/IK test for each object/base pair, either upfront for all pairs or lazily when the planner asks (a stream). The symbolic planner then never proposes `pick(box)` from $B_0$.
8. Necessary: if any joint configuration reaches the pose, then the ring and the limits hold, so failing them proves infeasibility. Not sufficient: a configuration reaching the point may collide with the table or another object, or lead to a wrong gripper orientation. Like the delete relaxation, it is an optimistic relaxation (it drops constraints): failure proves impossibility, success does not prove feasibility.
9. The base must be in both annuli: distances from the base to the box and to the slot both in $[0.452,1.3]$. The midpoint $(0.75,-0.15)$ has distance $0.604$ to each (the box-slot distance is $1.208$): serves both. A finite list like $\{B_0,B_1\}$ can miss such points: $B_1$ happened to work, but with other positions of box and slot none of the listed bases may lie in the intersection while a sampled continuous base would.
10. A good project reports an area of about $1.5\ \text{m}^2$ (a 400 000-sample Monte Carlo and a fine grid both give $\approx1.52$ for these box and slot positions), the checker with the obstacle rejecting the straight tool path although the pose is reachable, a boundary case at $r=1.3$ (accepted within the tolerance), and rejects "reachability implies executability" by a reachable pose whose path is blocked.
