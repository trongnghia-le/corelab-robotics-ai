## Why this matters

A robot's camera delivers hundreds of thousands of pixels per frame, and you want a network that finds obstacles, signs or graspable objects in them. A fully connected layer on a $224\times224\times3$ image has 150,528 inputs; connecting them even to 1,000 units costs 150 million weights, and it would have to relearn what a cup looks like at every position. Convolution solves both problems by using a small filter with the same weights everywhere. The practical questions are numerical: what size is the output, how many weights and multiplications does this layer cost, and how much of the image can a given unit actually see? If the receptive field is 19 pixels, no unit can recognise a 60-pixel object by looking at it directly. These are the questions you answer when sizing a network for a robot's embedded computer. The lesson builds on backpropagation (ML05) and image filtering (V02): a convolutional layer is a filter whose weights are learned.

## Intuition

Take the sliding window of V02 and make the kernel weights trainable. One kernel is one feature detector (an edge, a blob); the layer applies $C_\text{out}$ kernels and produces a stack of **feature maps**. Each output value depends only on a small neighbourhood (local connectivity), and the same kernel is reused at every position (weight sharing). Stacking layers lets later units combine earlier features, so their **receptive field** (the input region that can influence them) grows with depth. Stride and pooling make the grid coarser, which makes later receptive fields grow faster.

## Theory and derivation

### Output size

For input length $n$, kernel $k$, stride $s$, padding $p$ on each side and dilation $d$ (spacing between kernel taps; $d=1$ is ordinary):
$$n_\text{out}=\left\lfloor\frac{n+2p-d(k-1)-1}{s}\right\rfloor+1 .$$
Examples: $n=224,k=7,s=2,p=3$ gives $\lfloor 223/2\rfloor+1=112$; $n=7,k=3,s=2,p=0$ gives $3$; $n=8$ with the same settings also gives $3$ (the last column is never covered). "Same" padding for odd $k$, stride 1, is $p=(k-1)/2$.

### Parameters and compute

A layer with $C_\text{in}$ input channels, $C_\text{out}$ output channels and a $k\times k$ kernel has
$$P=(k^2C_\text{in}+1)\,C_\text{out}$$
parameters (the $+1$ is the bias), independent of image size. It performs
$$\text{MACs}=H_\text{out}W_\text{out}\;C_\text{out}\;k^2C_\text{in}$$
multiply-accumulates. A fully connected layer between the same input and output tensors would have $(H_\text{in}W_\text{in}C_\text{in}+1)\,H_\text{out}W_\text{out}C_\text{out}$ parameters.

### Receptive field and jump

Track two numbers going through the layers: the **receptive field** $r$ (input pixels that influence one unit) and the **jump** $j$ (input pixels between adjacent units). Start with $r_0=1$, $j_0=1$. A layer with kernel $k$, stride $s$, dilation $d$ updates
$$r\leftarrow r+d(k-1)\,j,\qquad j\leftarrow j\,s .$$
The update uses the jump *before* the layer: a $3\times3$ convolution after a stride-2 layer reaches two feature-map pixels on each side, which is four input pixels. Pooling counts as a layer with its window as $k$ and its stride as $s$. Padding does not change the receptive field (it adds zeros). The *effective* receptive field is smaller: contributions fall off roughly like a Gaussian from the centre.

### Why stacks of small kernels

Three $3\times3$ stride-1 layers have receptive field $1+2+2+2=7$, the same as one $7\times7$. With $C$ channels in and out, parameters are $3\cdot9C^2=27C^2$ against $49C^2$, and there are two more nonlinearities in between. This is why $3\times3$ is the workhorse size, with $1\times1$ convolutions used to change the number of channels cheaply.

### Weight sharing and gradients

For one channel, $y_{ij}=\sum_{a,b}K_{ab}\,x_{si+a,\;sj+b}$ (after padding). With a loss $L$ and upstream gradient $g_{ij}=\partial L/\partial y_{ij}$, each kernel entry is used at every output position, so by the chain rule its gradient is the sum over positions:
$$\frac{\partial L}{\partial K_{ab}}=\sum_{i,j}g_{ij}\,x_{si+a,\;sj+b},$$
that is, a correlation of the input with the upstream gradient. The input gradient is the "full" convolution of $g$ with the flipped kernel. Sharing means the kernel receives a signal from every position, which is why it learns from few parameters, and means its gradient is a *sum* over $H_\text{out}W_\text{out}$ terms (watch the scale: it grows with image size unless the loss averages).

### Equivariance, invariance and pooling

If the input is shifted by one pixel, the output of a convolution (away from the borders) shifts by one pixel: **translation equivariance**. A classification network needs (approximate) *invariance*, obtained with pooling, strides and finally a global pooling or dense layer. Equivariance does not cover rotation or scale; those must be learned from data or built in with augmentation.

## Worked example

### Output sizes of a small CNN

**Problem.** A $32\times32\times3$ input goes through (1) conv $3\times3$, 16 channels, stride $s=1$, padding $p=1$; (2) conv $3\times3$, 32 channels, $s=2$, $p=1$; (3) conv $3\times3$, 32 channels, $s=1$, $p=1$; (4) max-pool $2\times2$, $s=2$; (5) conv $3\times3$, 64 channels, $s=1$, $p=1$. Find the spatial size after every layer and the output shape.

**Solution.**
1. Use the output-size formula $n_\text{out}=\lfloor(n_\text{in}+2p-k)/s\rfloor+1$.
2. Layer 1: $\lfloor(32+2-3)/1\rfloor+1=31+1=32$.
3. Layer 2: $\lfloor(32+2-3)/2\rfloor+1=\lfloor15.5\rfloor+1=15+1=16$; the stride 2 halves the size.
4. Layer 3: $\lfloor(16+2-3)/1\rfloor+1=16$ (size preserved by $p=1$, $k=3$, $s=1$).
5. Layer 4 (no padding): $\lfloor(16-2)/2\rfloor+1=7+1=8$.
6. Layer 5: $\lfloor(8+2-3)/1\rfloor+1=8$.
7. The channel count is set by the last conv (64), so the output is $8\times8\times64$.

**Check.** Total downsampling is $2\cdot2=4$ (one stride-2 conv, one stride-2 pool) and $32/4=8$.

**Takeaway.** Only strides and pooling shrink the map; a $3\times3$ conv with $p=1$, $s=1$ keeps the size.

### Receptive field of the same network

**Problem.** For the five layers of the previous case (kernels $3,3,3,2,3$ and strides $1,2,1,2,1$), find the receptive field $r$ and the jump $j$ (input-pixel distance between neighbouring units) after each layer.

**Solution.**
1. Use the recursion $r_\text{out}=r_\text{in}+(k-1)\,j_\text{in}$ and $j_\text{out}=j_\text{in}\,s$, starting from $(r,j)=(1,1)$ at the input.
2. Layer 1 ($k=3$, $s=1$): $r=1+2\cdot1=3$, $j=1$.
3. Layer 2 ($k=3$, $s=2$): $r=3+2\cdot1=5$, $j=1\cdot2=2$.
4. Layer 3 ($k=3$, $s=1$): $r=5+2\cdot2=9$, $j=2$.
5. Layer 4 (pool $k=2$, $s=2$): $r=9+1\cdot2=11$, $j=2\cdot2=4$.
6. Layer 5 ($k=3$, $s=1$): $r=11+2\cdot4=19$, $j=4$.
7. Each final unit therefore sees a $19\times19$ window of the $32\times32$ input, and neighbouring units are 4 pixels apart.

**Check.** The jump 4 matches the total downsampling $32/8=4$ from the previous case, and $19\le32$, so the window fits inside the (padded) input.

**Takeaway.** Strides multiply the jump, and later layers add $(k-1)$ times the current jump, so the receptive field grows fastest after downsampling.

### Parameters and MACs, convolution versus dense

**Problem.** For the network of the first case, count the parameters (weights plus biases) of the conv layers 1, 2, 3 and 5 and their total; count the multiply-accumulates (MACs) of layer 1; and compare layer 1 with a dense layer mapping the $32\times32\times3$ input (3072 values) to a $32\times32\times16$ output (16,384 values).

**Solution.**
1. A conv layer has $(k^2C_\text{in}+1)\,C_\text{out}$ parameters (one bias per output channel).
2. Layer 1: $k^2C_\text{in}=9\cdot3=27$, so $(27+1)\cdot16=448$.
3. Layer 2: $9\cdot16=144$, so $(144+1)\cdot32=4640$.
4. Layer 3: $9\cdot32=288$, so $(288+1)\cdot32=9248$.
5. Layer 5: $9\cdot32=288$, so $(288+1)\cdot64=18{,}496$. The pooling layer has no parameters.
6. Total: $448+4640+9248+18{,}496=32{,}832$.
7. MACs of layer 1: each of the $32\cdot32\cdot16$ outputs needs 27 multiplications, so $32\cdot32\cdot16\cdot27=16{,}384\cdot27=442{,}368$.
8. A dense layer needs one weight per input-output pair plus one bias per output: $(3072+1)\cdot16{,}384=50{,}348{,}032$ weights, about $112{,}000$ times the 448 of the convolution.

**Check.** $50{,}348{,}032/448=112{,}384$. The convolution reuses the same $27+1$ numbers per filter at all $32\cdot32$ positions, which explains the gap.

**Takeaway.** Weight sharing and locality make a convolution thousands of times smaller than a dense layer with the same input and output sizes, while the MAC count still scales with the output area.

### Gradient of a 1-D convolution by hand

**Problem.** A valid, stride-1 correlation $y_i=\sum_mw_mx_{i+m}$ has input $x=[1,2,3,4]$ and kernel $w=[1,-1]$. Find $y$. For an upstream gradient $g=\partial L/\partial y=[1,2,3]$ find $\partial L/\partial w$ and $\partial L/\partial x$.

**Solution.**
1. Output: $y_0=1\cdot1-1\cdot2=-1$, $y_1=2-3=-1$, $y_2=3-4=-1$, so $y=[-1,-1,-1]$.
2. Weight gradient: $\partial L/\partial w_m=\sum_ig_ix_{i+m}$ (the same input windows, weighted by $g$).
3. $\partial L/\partial w_0=1\cdot1+2\cdot2+3\cdot3=14$.
4. $\partial L/\partial w_1=1\cdot2+2\cdot3+3\cdot4=20$.
5. Input gradient: $\partial L/\partial x_n=\sum_ig_i\,w_{n-i}$ (full convolution of $g$ with the kernel), where $x_n$ appears in outputs $i=n-m$.
6. $x_0$: $g_0w_0=1$. $x_1$: $g_0w_1+g_1w_0=-1+2=1$. $x_2$: $g_1w_1+g_2w_0=-2+3=1$. $x_3$: $g_2w_1=-3$.
7. Hence $\partial L/\partial x=[1,1,1,-3]$.

**Check.** Perturb $w_0$ by $\varepsilon$: every $y_i$ changes by $\varepsilon x_i$, so, to first order, $L$ changes by $\varepsilon(1\cdot1+2\cdot2+3\cdot3)=14\varepsilon$ (the gradient of $L$ with respect to $y$ is $g$). Also $\sum_n\partial L/\partial x_n=0=(w_0+w_1)\sum_ig_i$, since $w_0+w_1=0$.

**Takeaway.** The weight gradient correlates the input with the upstream gradient, and the input gradient convolves the upstream gradient with the kernel (flipped); both are again convolutions.

## Reference implementation

Calculators for output size, receptive field and cost, using the worked example.

```python
def conv_out_size(n, k, s=1, p=0, d=1):
    return (n + 2 * p - d * (k - 1) - 1) // s + 1

def receptive_field(layers):
    """layers: (k, s) or (k, s, d) per layer. Returns (receptive field, jump)."""
    r, j = 1, 1
    for layer in layers:
        k, s = layer[0], layer[1]
        d = layer[2] if len(layer) > 2 else 1
        r += d * (k - 1) * j
        j *= s
    return r, j

def conv_params(cin, cout, k):
    return (k * k * cin + 1) * cout

def conv_macs(h, w, cin, cout, k, s=1, p=0):
    return conv_out_size(h, k, s, p) * conv_out_size(w, k, s, p) * cout * k * k * cin

assert conv_out_size(224, 7, 2, 3) == 112
assert conv_out_size(7, 3, 2) == 3 and conv_out_size(8, 3, 2) == 3
assert conv_out_size(10, 3, 1, 0, 2) == 6                      # dilation 2: effective kernel 5
stack = [(3, 1), (3, 2), (3, 1), (2, 2), (3, 1)]
assert receptive_field(stack) == (19, 4)
assert receptive_field([(3, 1)] * 3) == (7, 1)
sizes, n = [], 32
for k, s, p in [(3, 1, 1), (3, 2, 1), (3, 1, 1), (2, 2, 0), (3, 1, 1)]:
    n = conv_out_size(n, k, s, p); sizes.append(n)
assert sizes == [32, 16, 16, 8, 8]
chans = [(3, 16), (16, 32), (32, 32), (32, 64)]
assert sum(conv_params(a, b, 3) for a, b in chans) == 32832
assert conv_macs(32, 32, 3, 16, 3, 1, 1) == 442368
print("reference checks passed")
```

import torch, torch.nn as nn
from v06_lab import conv_out_size, receptive_field, conv_params, conv_macs, conv2d_single, kernel_grad  # your lab

torch.manual_seed(0)
net = nn.Sequential(
    nn.Conv2d(3, 16, 3, 1, 1), nn.Conv2d(16, 32, 3, 2, 1), nn.Conv2d(32, 32, 3, 1, 1),
    nn.MaxPool2d(2, 2), nn.Conv2d(32, 64, 3, 1, 1))

# 1. sizes and parameter counts of the worked example
x = torch.zeros(1, 3, 32, 32)
assert net(x).shape == (1, 64, 8, 8)
assert sum(p.numel() for p in net.parameters()) == 32832

# 2. receptive field measured by autograd: gradient of one output unit w.r.t. the input
for m in net:
    if isinstance(m, nn.Conv2d):
        nn.init.constant_(m.weight, 0.1); nn.init.zeros_(m.bias)   # no dead units, no ReLU
# (max pooling passes gradient to one element of each window only, so measure with average pooling,
#  which touches every pixel the unit can see)
probe = nn.Sequential(*[nn.AvgPool2d(2, 2) if isinstance(m, nn.MaxPool2d) else m for m in net])
x = torch.ones(1, 3, 32, 32, requires_grad=True)
probe(x)[0, 0, 4, 4].backward()

print("measured receptive field (rows, cols):", extent)       # border clipping cannot occur here
assert extent == [19, 19] and receptive_field([(3, 1), (3, 2), (3, 1), (2, 2), (3, 1)]) == (19, 4)

# 3. kernel gradient: your kernel_grad against autograd for a stride-2, padded convolution

(G * out).sum().backward()

assert torch.allclose(out, torch.tensor(conv2d_single(img.tolist(), K.tolist(), 2, 1), dtype=torch.float64))

opt = torch.optim.SGD(conv.parameters(), lr=0.1)
for step in range(500):

    target = torch.nn.functional.conv2d(batch, sobel[None, None], padding=1)
    loss = ((conv(batch) - target) ** 2).mean()

Max pooling routes the gradient to one element per window, which is why the probe swaps in average pooling: the receptive field counts every pixel that *can* influence the unit, not the ones a particular input happens to select.

## Verification

Check sizes against a framework you trust (or against the formula in a unit test for several $n,k,s,p$, including cases where the last column is skipped). Check parameter counts with `sum(p.numel())` in PyTorch if you have it. Check the receptive field empirically: perturb one input pixel and see which output units change (the set must lie inside the computed window), or backpropagate from one output unit and see where the gradient is non-zero. Check gradients with centred finite differences (a relative error of about $10^{-6}$ is good). Check equivariance by shifting the input.

## Failure modes

- **Float division in the size formula.** `/` instead of `//` returns 3.5 for $n=8$ (Exercise 6); frameworks silently floor.
- **Forgetting the jump.** Using $r\leftarrow r+(k-1)$ for every layer gives $r=10$ for the worked stack instead of 19.
- **Counting parameters of a dense layer instead.** 50 million rather than 448.
- **Ignoring the bias.** 432 instead of 448 for the first layer; usually harmless, but it breaks exact tests.
- **Believing equivariance is invariance.** Convolution moves the response when the object moves; a classifier needs pooling or global aggregation.
- **Flipped kernel.** Deep-learning "convolution" is correlation; loading weights trained elsewhere into a true-convolution routine mirrors every filter.
- **Receptive field smaller than the object.** The network cannot decide from local evidence alone; add depth, stride, dilation or global pooling.
- **Exploding gradient sum.** Without averaging over positions the kernel gradient grows with the image size.

## Alternatives and trade-offs

| Choice | Benefit | Cost |
|---|---|---|
| Stride 2 convolution | Cheap downsampling, bigger receptive field | Aliasing (V02), lost detail |
| Max pooling | Local invariance, no parameters | Throws away position |
| Dilated convolution | Large receptive field at full resolution | Gridding artefacts |
| $1\times1$ convolution | Channel mixing at $1/9$ the cost of $3\times3$ | No spatial context |
| Depthwise separable convolution | Roughly $k^2$ times fewer MACs | Less expressive per layer |
| Dense layer | Global context | Parameters scale with image size |
| Vision transformer | Global attention | Data and compute hungry |

For embedded robots, count MACs and memory for activations (a $64\times112\times112$ float32 map is 3.2 MB), not just parameters. For a first model start from a reference architecture (ResNet-18-class or a mobile network) and reduce it rather than inventing one.

## Transfer and retention

The same size and receptive-field arithmetic returns in classification (V07), detection (V08, where anchor sizes must match the receptive field) and segmentation (V10, where upsampling restores resolution). The kernel gradient is backpropagation (ML05) with sharing: any parameter used in many places receives the sum of its contributions, as in recurrent networks and in the Jacobians of kinematic chains. ## Exercise answers

1. Sparse connectivity: each output depends on a small neighbourhood, so a layer needs $k^2C_\text{in}C_\text{out}$ weights instead of one per input-output pair. Parameter sharing: the same kernel at every position, so a feature learned once is detected everywhere, and the parameter count does not depend on the image size. Shifting the input shifts the output (equivariance), but the output values move rather than stay, so the layer is not invariant; invariance comes later from pooling or global aggregation.
2. $\lfloor(224+6-7)/2\rfloor+1=\lfloor111.5\rfloor+1=112$. For $n=8$: $\lfloor(8-3)/2\rfloor+1=\lfloor2.5\rfloor+1=3$.
3. $(9\cdot64+1)\cdot128=577\cdot128=73{,}856$.
4. Output $56\times56$: $56\cdot56\cdot128\cdot9\cdot64=231{,}211{,}008$ MACs (about 0.23 GMACs).
5. $r$: $1+2=3$, $3+2=5$, $5+2=7$: equal to $7$. Parameters (no bias): $3\cdot9\cdot64^2=110{,}592$ versus $49\cdot64^2=200{,}704$, about 55%. Also two extra nonlinearities.
6. It returns `3.5`; the correct answer is `3` (use `//`, and decide explicitly whether leftover columns are dropped).
7. $(1,1)\to(3,1)\to(5,2)\to(9,4)\to(17,4)$: receptive field $17$, jump $4$.
8. $y_i=\sum_aw_ax_{i+a}$ (stride 1). $\partial L/\partial w_a=\sum_ig_ix_{i+a}$: $w_0$: $1\cdot1+2\cdot2+3\cdot3=14$; $w_1$: $1\cdot2+2\cdot3+3\cdot4=20$. With stride $s$ replace $x_{i+a}$ by $x_{si+a}$. Input gradient: $\partial L/\partial x_j=\sum_ig_iw_{j-i}$ for valid indices: $[1\cdot1,\;1\cdot(-1)+2\cdot1,\;2\cdot(-1)+3\cdot1,\;3\cdot(-1)]=[1,1,1,-3]$.
9. A good design: first conv $3\times3$ stride 2 (8 channels) $\to48\times48$; conv $3\times3$ s2 (16) $\to24$; conv s2 (32) $\to12$; conv s2 (64) $\to6$; global average pool; dense. Receptive field: $3,\,7,\,15,\,31$ (with extra stride-1 $3\times3$ layers it exceeds 40). MACs about $48^2\cdot8\cdot9+24^2\cdot16\cdot72+12^2\cdot32\cdot144+6^2\cdot64\cdot288=0.17+0.66+0.66+0.66\approx2.2$ M per frame, i.e. $44$ M MACs/s at 20 fps: under the 100 M budget with margin for extra layers. Parameters: about $24$ k. A good answer states the assumptions and where most MACs go (middle layers).
10. Learned kernel converges to the Sobel-$x$ kernel (up to tolerance); the loss falls roughly geometrically with a suitable step size (with a mean-over-positions loss, 8x8 random images and step size $\eta=0.1$ to $0.2$ it reaches the Sobel kernel to two decimals within 500 steps; $\eta=1$ diverges). The result does not depend on image size because the kernel is shared; use mean rather than sum over positions so the step size stays valid.
