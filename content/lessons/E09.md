## Why this matters

A policy for "put the red cup on the plate" needs to reason about *the cup* and *the plate*, not about 224x224x3 numbers. A single global feature vector blends all objects together, so one change (a cup moves) alters the whole vector. Object-centric representations break the scene into a set of vectors, one per entity, plus relations between them. This makes it possible to reuse knowledge across scenes with different numbers of objects, to track an object while it is hidden, and to plan about what moves when one object is pushed.

It is also a place where claims are easy to over-state. "The model has slots" does not mean each slot holds one object. This lesson shows the mechanism, a way to measure whether it works, and a tracking test for identity through occlusion.

## Intuition

Look at a table with three cups. Humans do not describe it as one blob; they say "three cups, the left one is full". An object-centric model keeps $K$ slot vectors $s_1,\dots,s_K\in\mathbb R^d$, each intended to bind to one object, and a separate structure for relations (for example distances or "on top of").

![Left: image features compete for K slots; each input feature distributes its attention across slots by a softmax over slots. Right: two crossing tracks; a position-only matcher swaps identities after the crossing, a velocity-aware matcher does not.](/lesson-figures/E09.svg)

*Left: slot attention normalises over slots, so slots compete for features. Right: identity through a crossing needs motion information, not just nearest position.*

Three properties define the interface.

1. **Set structure**: slots have no natural order. Slot 3 in one image can be the cup that was slot 1 in another.
2. **Binding**: features of one object (colour, shape, position) must end up together in one slot and not leak into others. This is the *binding problem*.
3. **Persistence**: an object that is occluded keeps its identity; a representation should say "the red cup still exists behind the box".

## Theory and derivation

### Permutation structure

If $S=(s_1,\dots,s_K)$ is the slot set, a downstream function $g$ should satisfy $g(PS)=g(S)$ (invariant, e.g. "is any cup full?") or $g(PS)=P\,g(S)$ (equivariant, e.g. per-object predictions) for every permutation matrix $P$. A model that compares slot $i$ to ground-truth object $i$ is therefore wrong: there are $K!$ equally valid orderings and we must compare under the best one.

### Slot attention

Let inputs be $X\in\mathbb R^{N\times d}$ (image-feature vectors) and slots $S\in\mathbb R^{K\times d}$. With query and key projections $q,k$,
$$M_{ij}=\frac{k(x_i)\cdot q(s_j)}{\sqrt d},\qquad A_{ij}=\frac{e^{M_{ij}}}{\sum_{j'}e^{M_{ij'}}},\qquad W_{ij}=\frac{A_{ij}}{\sum_{i'}A_{i'j}} .$$
The first normalisation (**over slots $j$**) makes each input feature divide its attention among slots: slots *compete* for features. The second normalisation (over inputs $i$) turns the attention into a weighted mean. The update of slot $j$ is $u_j=\sum_iW_{ij}\,v(x_i)$, followed by a GRU and MLP update; the procedure repeats for a few iterations. The slots start as samples from a shared learned Gaussian, which is what lets the same model use any $K$.

### Evaluating slots

Segmentation quality of slot masks versus true objects is measured with a permutation-invariant score such as foreground adjusted Rand index (FG-ARI) or by Hungarian matching on mask IoU. For $K$ slots and $M$ objects the matching minimises total cost $\sum_m c(m,\sigma(m))$ over injections $\sigma$; brute force over permutations is fine for a handful of objects, otherwise use the Hungarian algorithm in $O(K^3)$.

### Relations and compositionality

A relation network scores pairs $(s_i,s_j)$, for instance "left of" with $f(s_i,s_j)$. Compositionality means that a rule learned about pairs works for any number of objects and unseen combinations: after learning "red cup on plate" and "blue block on tray", the model should evaluate "blue block on plate". The test is to hold out *combinations*, not individual objects.

### Identity through occlusion

Tracking is data association: predict where each tracked object should be, match predictions to detections, update matched tracks, and let unmatched tracks *coast*. With a constant-velocity prediction $\hat p_{t+1}=p_t+v_t$, a track that is occluded for $m$ frames is carried to $p_t+(m+1)v_t$ and re-associated when it reappears. Position-only prediction fails when two objects cross, because the nearest detection to the old position is the other object.

## Worked example

### One slot-attention update by hand and an occluded track

**Problem.** Slot attention with $d=2$ has two slots $s_1=(1,0)$, $s_2=(0,1)$ and three input features $x_1=(2,0)$, $x_2=(0,2)$, $x_3=(1,1)$; identity projections are used, so $k(x)=x$, $q(s)=s$, $v(x)=x$, and the scale is $1/\sqrt2=0.7071$. Find the attention $A$, the weights $W$ and the updated slots $u_1,u_2$. Then two objects move along a line: object A at $(t,0)$ and object B at $(5-t,0.2)$, with tracks initialised at $(0,0)$ and $(5,0.2)$. Frames $t=1,\dots,5$ give unordered detections, and at $t=3$ A is hidden, so only B at $(2,0.2)$ is detected. Find the number of identity errors (a detection given the wrong track label) of (i) a position-only matcher, which predicts each track at its last position, and (ii) a constant-velocity matcher. In both, the detections of a frame are assigned to tracks so that the total squared distance is minimal and an unmatched track coasts on its prediction.

**Solution.**

1. **Logits.** $M_{ij}=x_i\cdot s_j/\sqrt2$. For $x_1$: $(2\cdot1+0,\ 0)/\sqrt2=(1.414,\,0)$. For $x_2$: $(0,\,1.414)$. For $x_3$: $(1,\,1)/\sqrt2=(0.707,\,0.707)$.
2. **Softmax over slots (competition).** For $x_1$: $e^{1.414}=4.113$ and $e^0=1$, sum $5.113$, so $A_{1\cdot}=(4.113,1)/5.113=(0.804,\,0.196)$. For $x_2$ the roles swap: $(0.196,\,0.804)$. For $x_3$ the two logits are equal, so $(0.5,\,0.5)$.
3. **Normalise over inputs for each slot.** Column of slot 1: $(0.804,\,0.196,\,0.5)$, sum $1.5$, so $W_{\cdot1}=(0.804,0.196,0.5)/1.5=(0.5363,\,0.1304,\,0.3333)$. The column of slot 2 is $(0.196,0.804,0.5)$ with the same sum $1.5$, so $W_{\cdot2}=(0.1304,\,0.5363,\,0.3333)$.
4. **Update.** $u_1=\sum_iW_{i1}x_i=0.5363\,(2,0)+0.1304\,(0,2)+0.3333\,(1,1)=(1.0726+0.3333,\ 0.2608+0.3333)=(1.406,\,0.594)$. By the symmetry of the setup (swap the two coordinates and the two slots), $u_2=(0.594,\,1.406)$. Slot 1 moved toward the feature it competes best for ($x_1$), slot 2 toward $x_2$, and the ambiguous $x_3$ is shared equally.
5. **Positions per frame.** A is at $(1,0),(2,0),(3,0)$ hidden, $(4,0),(5,0)$ and B at $(4,0.2),(3,0.2),(2,0.2),(1,0.2),(0,0.2)$ for $t=1,\dots,5$. For $t=1,2$ both matchers assign correctly (each detection is nearest to its own track).
6. **Position-only matcher (i).** At $t=3$ the predictions are the last positions: A $(2,0)$, B $(3,0.2)$. The only detection $(2,0.2)$ has squared distance $0.04$ to A and $1$ to B, so B's detection is labelled A: 1 error, and track B coasts at $(3,0.2)$. At $t=4$ track A is at $(2,0.2)$, track B at $(3,0.2)$, the detections are $(4,0)$ (really A) and $(1,0.2)$ (really B). Giving $(1,0.2)$ to track A and $(4,0)$ to track B costs $1+1.04=2.04$; the other assignment costs $4.04+4=8.04$. The swapped one wins: 2 errors. At $t=5$ track A is at $(1,0.2)$ and track B at $(4,0)$; the detections are $(5,0)$ (A) and $(0,0.2)$ (B). Track A takes $(0,0.2)$ and track B takes $(5,0)$ at cost $1+1=2$, against $16.04+16.04$: 2 errors again. Total $1+2+2=\mathbf5$ identity errors.
7. **Constant-velocity matcher (ii).** After $t=2$ the velocities are A $(2,0)-(1,0)=(1,0)$ and B $(3,0.2)-(4,0.2)=(-1,0)$. At $t=3$ the predictions are A $(3,0)$ and B $(2,0.2)$. The detection $(2,0.2)$ is at distance $0$ from B and $\sqrt{1.04}$ from A, so it goes to B; A coasts to $(3,0)$ and keeps velocity $(1,0)$. At $t=4$ the predictions are A $(4,0)$ and B $(1,0.2)$, which match the detections exactly, and the same holds at $t=5$. Total **0** identity errors.

**Check.** A numpy computation gives $A=\begin{pmatrix}0.8044&0.1956\\0.1956&0.8044\\0.5&0.5\end{pmatrix}$, $W_{\cdot1}=(0.5363,0.1304,0.3333)$ and $u_1=(1.4059,0.5941)$. Also $u_1+u_2=(2,2)$, as it must be: each input gives total weight $2/3$ to the slots ($A_{i1}+A_{i2}=1$ divided by the column sum $1.5$), and $\tfrac23[(2,0)+(0,2)+(1,1)]=(2,2)$. A simulation of both matchers on the frames above returns 5 and 0 identity errors.

**Takeaway.** The softmax over slots makes slots compete for features, and the normalisation over inputs turns attention into a weighted mean. In tracking, a motion model keeps identities through an occlusion that a position-only matcher cannot survive.

## Reference implementation

```python
import math
from itertools import permutations

def slot_attention_step(slots, inputs):
    """One slot-attention update with identity projections; softmax over slots,
    then weighted mean over inputs. slots: K x d, inputs: N x d (lists)."""
    d = len(slots[0]); sc = 1 / math.sqrt(d); K = len(slots)
    A = []
    for x in inputs:
        logits = [sc * sum(a * b for a, b in zip(x, s)) for s in slots]
        m = max(logits); e = [math.exp(l - m) for l in logits]; z = sum(e)
        A.append([v / z for v in e])
    new = []
    for j in range(K):
        col = [A[i][j] for i in range(len(inputs))]; z = sum(col)
        w = [c / z for c in col]
        new.append([sum(w[i] * inputs[i][t] for i in range(len(inputs))) for t in range(d)])
    return A, new

def best_matching(cost):
    """cost[m][k] = cost of matching object m to slot k. Brute-force assignment."""
    n, K = len(cost), len(cost[0])
    return min(permutations(range(K), n), key=lambda p: sum(cost[m][p[m]] for m in range(n)))

if __name__ == "__main__":
    A, new = slot_attention_step([(1, 0), (0, 1)], [(2, 0), (0, 2), (1, 1)])
    print([round(v, 3) for v in new[0]], [round(v, 3) for v in new[1]])
    iou = [[0.9, 0.1, 0.0], [0.05, 0.1, 0.8], [0.0, 0.7, 0.1]]
    perm = best_matching([[1 - v for v in r] for r in iou])
    print(perm, sum(iou[m][perm[m]] for m in range(3)) / 3)
    # --- self-test ---
    assert abs(new[0][0] - 1.4059) < 1e-3 and abs(new[0][1] - 0.5941) < 1e-3
    assert abs(A[2][0] - 0.5) < 1e-12
    assert perm == (0, 2, 1)
    print("self-test passed")
```

```python
from typing import List, Tuple
Pt = Tuple[float, float]

    raise NotImplementedError

def match(preds: List[Pt], dets: List[Pt]) -> List[int]:
    """Assign each detection a DISTINCT track index (len(dets) <= len(preds)) so the
    total squared distance is minimal. result[j] is the track index of detection j.
    Brute force over permutations; the first minimum wins."""
    raise NotImplementedError

def track(init: List[Pt], frames: List[List[Pt]], use_velocity: bool):

    detection (vel = new_pos - old_pos), let unmatched tracks coast on their prediction.
    Return hist[t][j] = track index assigned to detection j of frame t."""
    raise NotImplementedError

def id_errors(hist, truth) -> int:
    """Number of detections whose assigned track differs from truth[t][j]."""
    raise NotImplementedError
```

### Library track

Redo the lab with NumPy and SciPy: a vectorised slot-attention step (`scipy.special.softmax` over the slot axis), Hungarian matching of slot masks with `scipy.optimize.linear_sum_assignment` checked against brute force, and the tracker of the lab with a rectangular cost matrix (fewer detections than tracks).
```python
import itertools, time
import numpy as np
from scipy.optimize import linear_sum_assignment
from scipy.special import softmax

# 1) Slot attention step with NumPy: softmax over slots, then weighted mean over inputs.
slots = np.array([[1, 0], [0, 1]], float)
X = np.array([[2, 0], [0, 2], [1, 1]], float)
A = softmax(X @ slots.T / np.sqrt(2), axis=1)       # axis=1: each input divides attention over slots
W = A / A.sum(axis=0, keepdims=True)                # normalise over inputs
new = W.T @ X
print(new.round(3))
assert np.allclose(new, [[1.4059, 0.5941], [0.5941, 1.4059]], atol=1e-3)

# 2) Hungarian matching on the IoU matrix; compare with brute force.
iou = np.array([[0.9, 0.1, 0.0], [0.05, 0.1, 0.8], [0.0, 0.7, 0.1]])
r, c = linear_sum_assignment(-iou)                  # maximise IoU
print("assignment", c.tolist(), "mean IoU", round(iou[r, c].mean(), 3), "diagonal", round(np.trace(iou) / 3, 3))
brute = max(itertools.permutations(range(3)), key=lambda p: sum(iou[m, p[m]] for m in range(3)))
assert c.tolist() == list(brute) == [0, 2, 1]

# 3) Tracker with linear_sum_assignment (rectangular cost: fewer detections than tracks is allowed).
def track(init, frames, use_velocity):
    pos = np.array(init, float); vel = np.zeros_like(pos); hist = []
    for dets in frames:
        dets = np.array(dets, float)
        pred = pos + vel if use_velocity else pos
        cost = ((dets[:, None, :] - pred[None, :, :]) ** 2).sum(-1)     # (n_dets, n_tracks)
        di, ti = linear_sum_assignment(cost)
        hist.append([int(t) for t in ti[np.argsort(di)]])
        newpos = pred.copy()                        # unmatched tracks coast on their prediction
        newpos[ti] = dets[di]
        vel = np.where(np.isin(np.arange(len(pos)), ti)[:, None], newpos - pos, vel)
        pos = newpos
    return hist
frames, truth = [], []
for t in range(1, 6):
    d = [((5.0 - t, 0.2), 1), ((float(t), 0.0), 0)]
    if t == 3: d = [d[0]]
    frames.append([p for p, _ in d]); truth.append([i for _, i in d])
errs = lambda h: sum(a != b for hr, tr in zip(h, truth) for a, b in zip(hr, tr))
e_pos, e_vel = errs(track([(0, 0), (5, 0.2)], frames, False)), errs(track([(0, 0), (5, 0.2)], frames, True))
print("identity errors: position-only", e_pos, " constant velocity", e_vel)
assert (e_pos, e_vel) == (5, 0)

# 4) Timing: brute force vs Hungarian for 8 objects.
cost = np.random.default_rng(0).random((8, 8))
t0 = time.perf_counter(); b = min(itertools.permutations(range(8)), key=lambda p: sum(cost[i, p[i]] for i in range(8))); t1 = time.perf_counter()
r, c = linear_sum_assignment(cost); t2 = time.perf_counter()
print(f"brute force {t1 - t0:.3f}s  hungarian {t2 - t1:.5f}s")
assert abs(cost[r, c].sum() - sum(cost[i, b[i]] for i in range(8))) < 1e-12
print("library track passed")
```

## Verification

- **Hand check one frame** of association: compute the cost matrix yourself and confirm the code's choice.
- **Permutation test:** shuffle detection order; the assigned identities of detections must follow the shuffle, never change.
- **Baseline:** report the position-only matcher; a gain is only meaningful relative to it.
- **Occlusion sweep:** vary the occlusion length from 1 to 10 frames and plot errors; identity survival time is the main result.
- **Counterexample:** include a scenario where your method must fail (a hidden reversal) so the evaluation can reject the claim.

## Failure modes

| Mistake | Wrong value or symptom |
|---|---|
| Comparing slot $i$ with object $i$ | IoU 0.12 instead of about 0.8 after matching |
| Softmax over inputs instead of slots | slots do not compete; several slots copy the same object |
| Position-only association at a crossing | 5 identity errors instead of 0 in the example |
| Gating omitted | a distant clutter detection steals a track after a long occlusion |
| Evaluating only on training object counts | fails with more objects than seen in training |
| Treating slot count $K$ as the object count | extra slots bind to background or split an object |

## Alternatives and trade-offs

- **Global feature vector**: simplest and strong for classification, hard for manipulation and counting.
- **Explicit detectors/segmenters plus tracking** (the classical stack): reliable with labels, needs supervision per category.
- **Slot-based unsupervised discovery**: no object labels, but fragile on real textured scenes and sensitive to $K$ and initialisation.
- **Foundation segmentation models plus tracking**: strong masks from large pretraining, no learned binding, treat identity as a separate tracking problem.
- **Greedy versus optimal association**: greedy is $O(n^2)$ and can cascade errors; Hungarian is optimal for the cost but cannot fix a wrong motion model.

## Exercise answers

1. Concatenation fixes an order: permuting objects changes the input, so the classifier output can change although the scene is the same. Fixes: sum/mean/max pooling over objects, a set transformer, or sorting by a canonical key (weaker).
2. Remove the softmax over slots (use per-slot normalisation only). Then every slot can attend to the same features; slots become nearly identical and no longer separate objects.
3. Logits $(3/\sqrt2,0)=(2.121,0)$; $e^{2.121}=8.34$; $A=(0.893,0.107)$. Scaled by 4: logits $(8.485,0)$, $e^{8.485}=4846$, $A=(0.9998,0.0002)$. Larger scale makes the assignment almost hard (winner takes all), which sharpens segmentation but gives vanishing gradients to losing slots.
4. Segregation: separating the features of different objects (red vs blue, cube vs sphere) into distinct representations; composition: combining the right features into one object entity. A failure: the colour slot leaks across objects so the model reports "blue cube" (blue from the sphere, shape from the cube), the characteristic binding error.
5. Best assignment: object 0 to slot 0 (0.9), object 1 to slot 2 (0.8), object 2 to slot 1 (0.7); mean IoU $=0.8$. The diagonal gives $0.9+0.1+0.1=1.1$ over 3 $=0.367$, which punishes arbitrary slot order.
6. Output `(1,)`: with one detection at 3.5, track 1 at 4 is closer (squared distance 0.25 versus 12.25).
7. Relative speed is $10\,\text{mm}/0.02\,\text{s}=0.5$ m/s, consistent. From A's old position $(-2,0)$: distance to A's new $(3,0)$ is 5 mm, to B's new $(-2,3)$ is 3 mm, so the nearest-detection tracker gives A the wrong detection (swap). With velocity $(+5,0)$ the prediction is $(3,0)$, at distance 0 from A's new position and $\sqrt{25+9}=5.8$ mm from B's, so the identity is kept. Identical blocks leave motion as the only cue.
8. Slot order is arbitrary, so slot $i$ is generally not object $i$. After optimal matching, good slots would give mean IoU near 0.7-0.9; the 0.12 number mostly reflects random ordering (about $1/K$ chance of the right slot).
9. $d^2=(0.5^2+0.1^2)/0.04=0.26/0.04=6.5$. Since $6.5>5.99$, the gate rejects the detection. Over long occlusions covariance grows, so the gate widens; nearest-neighbour without a covariance-based gate would accept wrong detections, whereas a gated, covariance-aware association can reject them or keep the track coasting.
10. A good answer reports mean and spread of errors over 200 scenarios, defines the stopped object's effect (velocity keeps predicting motion, causing a mismatch at the stop), and names the falsifier, for example position-only beating velocity on scenarios with stop-and-go motion.
