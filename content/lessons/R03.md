## Why this matters

Compose frame mappings in a declared order and verify rigid-motion invariants. This lesson develops the core calculation before asking you to apply it in a new setting. Start with the diagnostic if you think you already know it; prior tool use is not evidence of understanding.

## Intuition

A rotation changes direction while preserving lengths and angles. A matrix with the right dimensions is not necessarily a rotation: it might scale, shear, or reflect. Frame subscripts help compose motions without guessing multiplication order.

## Theory and derivation

A proper 3D rotation satisfies $R^TR=I$ and $\det R=+1$. Orthogonality preserves dot products: $(Ru)^T(Rv)=u^TR^TRv=u^Tv$. Determinant −1 is an improper orthogonal map containing a reflection, not a physical rigid rotation.

Write ${}^AT_B$ for the mapping from B coordinates to A coordinates. Then ${}^AT_C={}^AT_B{}^BT_C$. The adjacent B labels identify the intermediate frame. With $T_1=(R_1,t_1)$ and $T_2=(R_2,t_2)$, substitution yields $T_1T_2=(R_1R_2,R_1t_2+t_1)$. Translation $t_2$ must be rotated before adding it to $t_1$.

The inverse is $T^{-1}=(R^T,-R^Tt)$. Rotating an object in a fixed basis and changing the basis for a fixed object can use inverse mappings; define the equation instead of relying on ambiguous words like “rotate coordinates”.

## Worked example

Take R₁ as +90° planar rotation, t₁=(1,0), and T₂ as translation (2,0). The composed translation is R₁(2,0)+(1,0)=(1,2). Reversing order gives (3,0). The difference is expected because rigid transform composition is not commutative.

## Exercises

1. **(Easy)** *(Adapted from: Modern Robotics, ch. 3, section 3.2.1, properties of rotation matrices)* Classify each matrix as a proper rotation, a reflection, or neither, using $R^TR=I$ and $\det R$: $A=\begin{bmatrix}0&-1\\1&0\end{bmatrix}$, $B=\begin{bmatrix}0&1\\1&0\end{bmatrix}$, $C=\begin{bmatrix}2&0\\0&0.5\end{bmatrix}$. Note that $\det C=1$.
2. **(Easy)** Rotate the point $(1,2,0)$ by $90^\circ$ about the $z$ axis. Compute the result and show that its length is unchanged.
3. **(Easy, frame labels)** A mobile base frame $B$ sits at $t=(2,1)$ in the world $W$, rotated $90^\circ$ counter-clockwise. A sensor sees an obstacle at $(1,0)$ in $B$. Write the equation that maps it to $W$ with the frame subscripts, and compute the world position.
4. **(Medium, predict)** Compute $R_x(90^\circ)R_z(90^\circ)p$ and $R_z(90^\circ)R_x(90^\circ)p$ for $p=(1,0,0)$. What does the result say about the order of 3D rotations, and how does it relate to the order in the product (which rotation is applied first)?
5. **(Medium, find the bug)** A student inverts a pose with `T_inv = make_T(R.T, -t)`. For $R=R_z(90^\circ)$ and $t=(1,0,0)$ give the true inverse translation, the student's, and a one-line test that would have caught the bug.
6. **(Medium, applied)** *(Adapted from: Modern Robotics, ch. 3, section 3.3, homogeneous transformation matrices)* A wrist camera sits at $t=(0.1,0,0.05)$ m with the same orientation as the wrist. The wrist pose in the world is $R=R_z(90^\circ)$, $t=(0.5,0.2,0.8)$. The camera sees a point at $(0,0,0.4)$ m in its own frame. Find the point in world coordinates, showing the chain ${}^WT_C={}^WT_{wrist}\,{}^{wrist}T_C$.
7. **(Medium-hard, derivation)** Multiply two homogeneous matrices to prove $T_1T_2=(R_1R_2,\ R_1t_2+t_1)$, and verify that $T^{-1}=(R^T,-R^Tt)$ by multiplying out $T^{-1}T$.
8. **(Medium-hard)** Show that $R=\begin{bmatrix}0&0&1\\1&0&0\\0&1&0\end{bmatrix}$ is a proper rotation. Use $\mathrm{tr}\,R=1+2\cos\theta$ to find its angle, and guess its axis from the fact that the matrix cyclically permutes the coordinates.
9. **(Hard, numerics)** A flight controller multiplies 100 000 small rotation updates (about 1 milli-radian each, all about the same axis). After the loop $\max|R^TR-I|$ is about $10^{-11}$ in float64 but of order $10^{-3}$ to $10^{-2}$ in float32 (a typical run gives $8\times10^{-12}$ and $5\times10^{-3}$). Explain where the drift comes from, why the result is no longer exactly a rotation, and describe two ways to repair it.
10. **(Hard, conceptual)** *(Adapted from: Modern Robotics, Appendix B, Euler angles and gimbal lock)* Show numerically or algebraically that $R_z(a)R_y(90^\circ)R_x(b)$ depends only on $a-b$ (or $a+b$, depending on convention). Check with $(a,b)=(30^\circ,10^\circ)$ and $(50^\circ,30^\circ)$. What is lost, and what does that mean for a controller that uses Euler angles?
11. **(Hard, trade-off)** You must (a) compose 1000 rotations per second, (b) interpolate smoothly between two orientations, and (c) store 10 million orientations compactly. Compare rotation matrices, unit quaternions and axis-angle for each need.
12. **(Mini-project)** Build a kinematic loop test: create three random poses $T_{AB},T_{BC},T_{CA}$ such that $T_{AB}T_{BC}T_{CA}=I$ (choose the third as the inverse of the product of the first two), then perturb one rotation slightly and measure how the loop error grows. Use it as a calibration-consistency check for a camera-robot-world setup.

## Independent practice

### Goal

### Tasks

2. Implement `make_T`, `inv_T` (use $(R^T,-R^Tt)$, not a general matrix inverse) and `transform_points` for an $(N,3)$ array.
3. Implement `rotation_angle(R)` from the trace.
4. Compose the wrist-camera chain and verify that a point maps back to the camera frame through the inverse.
5. Implement `reorthonormalize(R)` (SVD) and show that it repairs a drifted matrix.
6. Show that swapping the order of two 3D rotations changes the result.

### Tests

```python
d = np.radians
# hand-computed cases
assert np.allclose(rot_z(d(90)) @ [1, 2, 0], [-2, 1, 0])
assert is_rotation(rot_x(0.3) @ rot_y(-1.1) @ rot_z(2.0))
assert not is_rotation(np.array([[0, 1, 0], [1, 0, 0], [0, 0, 1.0]]))      # reflection
assert not is_rotation(np.diag([2.0, 0.5, 1.0]))                           # det 1, not orthogonal
Tws = make_T(rot_z(d(90)), [0.5, 0.2, 0.8])
Twc = make_T(np.eye(3), [0.1, 0.0, 0.05])
assert np.allclose(transform_points(Tws @ Twc, [[0, 0, 0.4]]), [[0.5, 0.3, 1.25]])
assert np.allclose(inv_T(make_T(rot_z(d(90)), [1, 0, 0]))[:3, 3], [0, 1, 0])

# non-commutativity of 3D rotations
p = np.array([1.0, 0, 0])
assert np.allclose(rot_x(d(90)) @ rot_z(d(90)) @ p, [0, 0, 1])
assert np.allclose(rot_z(d(90)) @ rot_x(d(90)) @ p, [0, 1, 0])

# edge: identity and half turn
assert abs(rotation_angle(np.eye(3))) < 1e-9 and abs(rotation_angle(rot_z(np.pi)) - np.pi) < 1e-7

# properties: inverse, lengths, angle recovery, loop closure, repair
rng = np.random.default_rng(1)
for _ in range(20):
    R = rot_z(rng.uniform(-3, 3)) @ rot_y(rng.uniform(-1.5, 1.5)) @ rot_x(rng.uniform(-3, 3))
    T = make_T(R, rng.normal(size=3))
    assert np.allclose(inv_T(T) @ T, np.eye(4))
    P = rng.normal(size=(5, 3))
    Q = transform_points(T, P)
    assert np.allclose(np.linalg.norm(Q[1:] - Q[0], axis=1), np.linalg.norm(P[1:] - P[0], axis=1))
    assert np.allclose(transform_points(inv_T(T), Q), P)
assert abs(rotation_angle(rot_x(0.7)) - 0.7) < 1e-9
Rd = rot_z(0.4) @ rot_x(0.2) + 1e-3 * rng.normal(size=(3, 3))
Rf = reorthonormalize(Rd)
assert is_rotation(Rf) and np.abs(Rf - Rd).max() < 5e-3
print("angle of rot_x(0.7): %.3f rad; repaired matrix orthogonal to 1e-12: %s" % (rotation_angle(rot_x(0.7)), np.abs(Rf.T @ Rf - np.eye(3)).max() < 1e-12))
print("all tests passed")
```

### Library track

Check your matrices against `scipy.spatial.transform.Rotation` and use it for the drift experiment. Install with `pip install numpy scipy`, put this file next to `se3_lab.py` (importing it runs your tests first) and run it.

```python
import numpy as np
from scipy.spatial.transform import Rotation as Rot
from se3_lab import rot_x, rot_y, rot_z, is_rotation, rotation_angle, reorthonormalize

rng = np.random.default_rng(0)
for _ in range(50):
    a, b, c = rng.uniform(-3, 3, 3)
    R = rot_z(a) @ rot_y(b) @ rot_x(c)
    r = Rot.from_matrix(R)
    assert np.allclose(r.as_matrix(), R)
    assert np.isclose(r.magnitude(), rotation_angle(R))              # angle from the trace
    assert np.allclose(Rot.from_euler("ZYX", [a, b, c]).as_matrix(), R)   # intrinsic Z-Y-X
    # composition: matrix product == Rotation product (right-most acts first)
    p = rng.normal(size=3)
    assert np.allclose((r * Rot.from_matrix(rot_x(0.3))).apply(p), R @ rot_x(0.3) @ p)

# non-commuting rotations, and gimbal lock at pitch 90 degrees
ra, rb = Rot.from_euler("x", 90, degrees=True), Rot.from_euler("z", 90, degrees=True)
print("Rx Rz p =", (ra * rb).apply([1, 0, 0]).round(3), " Rz Rx p =", (rb * ra).apply([1, 0, 0]).round(3))
m1 = Rot.from_euler("ZYX", [30, 90, 10], degrees=True).as_matrix()
m2 = Rot.from_euler("ZYX", [50, 90, 30], degrees=True).as_matrix()
assert np.allclose(m1, m2)                                           # same rotation: two angle triples

# drift and repair with the real library
U = Rot.from_rotvec(1e-3 * np.ones(3) / np.sqrt(3)).as_matrix().astype(np.float32)
R32 = np.eye(3, dtype=np.float32)
for _ in range(100_000):
    R32 = R32 @ U
err = np.abs(R32.T @ R32 - np.eye(3)).max()
fixed = Rot.from_matrix(R32.astype(np.float64)).as_matrix()          # SciPy orthonormalises on input
print("float32 drift %.1e -> after SciPy repair %.1e" % (err, np.abs(fixed.T @ fixed - np.eye(3)).max()))
assert err > 1e-4 and is_rotation(fixed) and np.allclose(fixed, reorthonormalize(R32.astype(np.float64)), atol=1e-6)
print("library track passed")
```

Expected: `Rx Rz p = [0. 0. 1.]  Rz Rx p = [0. 1. 0.]`, a float32 drift of about $10^{-3}$ to $10^{-2}$ that SciPy's `from_matrix` (nearest rotation) reduces to round-off, and `library track passed`.

## Failure modes

Orthogonality alone allows reflections. Negating translation without rotating it does not invert a general transform. Euler angle addition is not general 3D rotation composition.

## Alternatives and trade-offs

Matrices make composition and vector transformation direct. Quaternions are compact for 3D orientation interpolation but need normalization and sign conventions. Euler angles are intuitive locally but have parameterization singularities.

## Exercise answers

1. $A$: $A^TA=I$, $\det A=1$: proper rotation ($90^\circ$). $B$: orthogonal ($B^TB=I$) but $\det B=-1$: a reflection across $y=x$, not a rigid rotation. $C$: $\det C=1$ but $C^TC=\mathrm{diag}(4,0.25)\ne I$: it stretches and squeezes, so neither. A unit determinant alone does not make a rotation.
2. $R_z(90^\circ)(1,2,0)=(-2,1,0)$ since $x'=x\cos\theta-y\sin\theta=-2$, $y'=x\sin\theta+y\cos\theta=1$. Lengths: $\sqrt{1+4}=\sqrt5$ and $\sqrt{4+1}=\sqrt5$.
3. ${}^Wp={}^WR_B\,{}^Bp+{}^Wt_B$. ${}^WR_B(1,0)=(0,1)$, so ${}^Wp=(0,1)+(2,1)=(2,2)$.
4. $R_xR_zp$: $R_z p=(0,1,0)$, then $R_x(0,1,0)=(0,0,1)$. $R_zR_xp$: $R_xp=(1,0,0)$, then $R_z(1,0,0)=(0,1,0)$. Different results, so 3D rotations do not commute. In a product, the right-most matrix acts on the vector first.
5. True: $-R^Tt=-(0,-1,0)=(0,1,0)$ (since $R^T(1,0,0)=(0,-1,0)$). Student's: $(-1,0,0)$. Test: `assert np.allclose(inv_T(T) @ T, np.eye(4))` (or transform a point and back); it fails with the student's version.
6. ${}^{wrist}T_C$ takes $(0,0,0.4)$ to $(0.1,0,0.45)$. Then ${}^WT_{wrist}$ rotates $(0.1,0,0.45)$ by $90^\circ$ about $z$: $(0,0.1,0.45)$, and adds $t$: $(0.5,0.3,1.25)$ m.
7. $\begin{bmatrix}R_1&t_1\\0&1\end{bmatrix}\begin{bmatrix}R_2&t_2\\0&1\end{bmatrix}=\begin{bmatrix}R_1R_2&R_1t_2+t_1\\0&1\end{bmatrix}$. And $\begin{bmatrix}R^T&-R^Tt\\0&1\end{bmatrix}\begin{bmatrix}R&t\\0&1\end{bmatrix}=\begin{bmatrix}R^TR&R^Tt-R^Tt\\0&1\end{bmatrix}=I$.
8. Columns are the unit vectors $e_2,e_3,e_1$ (orthonormal), so $R^TR=I$; it is a cyclic permutation (even), so $\det R=+1$. $\mathrm{tr}\,R=0=1+2\cos\theta\Rightarrow\cos\theta=-\tfrac12$, $\theta=120^\circ$. The axis $(1,1,1)/\sqrt3$ is fixed because $R(1,1,1)^T=(1,1,1)^T$.
9. Each product rounds to the nearest float, and the rounding errors (about $10^{-16}$ in float64, $10^{-7}$ in float32, per operation) accumulate over 100 000 multiplications as a random walk plus bias, so $R^TR$ drifts from $I$ and $R$ picks up scale and shear. Repairs: re-orthonormalise periodically (SVD: $R\leftarrow UV^T$, or Gram-Schmidt/QR), or integrate a unit quaternion and renormalise it (cheaper, and easy to repair).
10. At pitch $90^\circ$ the first and third rotation axes align, so only the combined angle matters: $R_z(30^\circ)R_y(90^\circ)R_x(10^\circ)$ and $R_z(50^\circ)R_y(90^\circ)R_x(30^\circ)$ are identical (max element difference about $10^{-16}$). One degree of freedom is lost (gimbal lock): the map from angles to rotations is singular, so the Euler-angle rates needed for a given angular velocity become unbounded. Controllers should use rotation matrices or quaternions internally.
11. (a) Matrices: composition is 27 multiplies and robust; quaternions: 16 multiplies and easy to renormalise. (b) Quaternions with slerp give constant-speed interpolation on the shortest arc; matrices cannot be interpolated entrywise. (c) Quaternions: 4 floats (16 B in float32), axis-angle 3 floats, matrices 9 floats. Use quaternions for storage and interpolation and convert to matrices only to rotate many points.
12. A good answer builds random rotations (e.g. from `rot_z` etc.), defines $T_{CA}=(T_{AB}T_{BC})^{-1}$, checks that the loop product is the identity to about $10^{-15}$, then perturbs a rotation by angle $\epsilon$ and shows the rotation part of the loop error is $\approx\epsilon$ (angle from the trace), with a translation error growing with the lever arm (distance to the origin). In practice, a calibration residual above the measurement noise flags a wrong frame label or inverse.
