## Why this matters

A robot that fetches a cup does not choose torques for every millisecond of "go to the kitchen". It chooses skills: navigate to the table, align with the cup, grasp. Planning and credit assignment at the level of skills means far fewer decisions per task, so rewards that are hundreds of primitive steps away become a handful of decisions away. Hierarchical RL gives these skills a precise definition, the *option*, and a precise way to learn and plan with them.

This builds on RL02 (MDPs and Bellman equations) and on RL08 (value-based learning with Q-functions). Here the only new ingredient is that a decision can last a variable number of time steps.

## Intuition

A primitive action lasts one step. An option, once chosen, keeps control until it decides to stop. From the high-level point of view the world is still a decision process, but each transition now takes a random duration $\tau$ and collects the rewards of all the steps inside. That is a semi-Markov decision process (SMDP).

## Theory and derivation

### The option triple

An option $o=(\mathcal I_o,\pi_o,\beta_o)$ consists of

- an **initiation set** $\mathcal I_o\subseteq\mathcal S$: the states where the option may be started (its precondition);
- an **intra-option policy** $\pi_o(a|s)$: how it acts while it runs;
- a **termination condition** $\beta_o(s)\in[0,1]$: the probability that it stops on reaching state $s$.

A primitive action is the special option with $\tau=1$ ($\beta\equiv1$). Two designs of $\beta$ matter: a deterministic one (stop at landmarks, 0 or 1) and a stochastic one (stop with probability $\beta$ each step, which makes $\tau$ geometric with mean $1/\beta$).

### Option return and the SMDP Bellman equation

Running option $o$ from $s$ ends after $\tau$ steps in state $s'$ with discounted reward
$$R=\sum_{k=0}^{\tau-1}\gamma^k r_k .$$
The return from $s$ splits at the termination time: first $\tau$ steps, then everything after, which is discounted by a further $\gamma^\tau$:
$$G_t=\underbrace{\sum_{k=0}^{\tau-1}\gamma^kr_{t+k}}_{R}+\gamma^{\tau}\,G_{t+\tau}.$$
Taking expectations gives the option-value equation
$$Q(s,o)=\mathbb E\!\left[R+\gamma^{\tau}\max_{o'\in\mathcal O(s')}Q(s',o')\right],$$
where $\mathcal O(s')$ is the set of options (including primitives) whose initiation set contains $s'$. The common mistake is to discount by $\gamma$ instead of $\gamma^\tau$: that makes long skills look cheaper than they are. SMDP Q-learning updates $Q(s,o)\leftarrow Q(s,o)+\alpha\,[R+\gamma^\tau\max_{o'}Q(s',o')-Q(s,o)]$ after each option ends.

### Why options help, and when they hurt

If all primitive actions remain available, the optimal value is unchanged: options only add more choices, and the max over a larger set cannot be smaller. What changes is how fast information travels. A single backup across an option moves value $\tau$ steps. Exploration also benefits, because a good option is a coherent multi-step behaviour that random primitive actions would almost never produce.

If primitives are removed, the best behaviour available may be worse than flat optimal ("hierarchically optimal" versus "flat optimal"). A grasp option that always runs to completion cannot be aborted when the object slips. Options that terminate too rarely give coarse control; options that terminate every step collapse back to primitives and give no abstraction.

## Worked example

Corridor with states $0,\dots,11$, goal at 11 (absorbing), reward $-1$ per step, $\gamma=0.9$. Option run_right: $\mathcal I=\{0,\dots,10\}$, $\pi(s)=+1$, $\beta(s)=1$ for $s\in\{4,8,11\}$, else 0.

**Step 1, execute from state 0.** The option moves 0→1→2→3→4 and stops at 4, so $\tau=4$.

**Step 2, option reward.** $R=-(1+0.9+0.81+0.729)=-3.439$.

**Step 3, value at the landing state.** Without options, $V^*(s)=-\frac{1-\gamma^{11-s}}{1-\gamma}$. For $s=4$ that is $-\frac{1-0.9^7}{0.1}=-5.2170$.

**Step 4, SMDP backup.** $Q(0,\text{run\_right})=-3.439+0.9^4\cdot(-5.2170)=-3.439-3.4229=-6.8619$. This equals $V^*(0)=-\frac{1-0.9^{11}}{0.1}=-6.8619$: the option is part of an optimal path, and one backup replaced four.

**Step 5, the wrong discount.** Using $\gamma$ instead of $\gamma^4$ gives $-3.439+0.9\cdot(-5.2170)=-8.134$, which says the option is worse than it is.

**Step 6, propagation speed.** Starting from $V=-100$ (pessimistic), value iteration over primitives needs 11 sweeps for the goal's value to reach state 0, plus one confirming sweep: 12. With run_right added, the doorways give 3 sweeps plus one: 4.

## Reference implementation

Options on a corridor, the SMDP backup, and value iteration with and without the option.

```python
from dataclasses import dataclass
from typing import Callable, Set

N, GOAL, GAMMA = 11, 11, 0.9           # states 0..11 in a corridor, goal at 11

def step(s, a):
    """Primitive transition: a is -1 or +1; reward -1 per step; goal is absorbing."""
    if s == GOAL:
        return s, 0.0
    return min(max(s + a, 0), N), -1.0

@dataclass
class Option:
    name: str
    init: Set[int]                      # initiation set I
    policy: Callable[[int], int]        # intra-option policy pi(s)
    beta: Callable[[int], float]        # termination probability beta(s) (0 or 1 here)

def run_option(opt, s, gamma=GAMMA, max_steps=100):
    """Execute until termination. Return (s_end, discounted reward R, duration tau)."""
    if s not in opt.init:
        raise ValueError("%s cannot start in state %d" % (opt.name, s))
    R, tau = 0.0, 0
    while True:
        s, r = step(s, opt.policy(s))
        R += gamma ** tau * r; tau += 1
        if opt.beta(s) >= 1.0 or tau >= max_steps:
            return s, R, tau

doorways = {4, 8, 11}
run_right = Option("run_right", set(range(0, 11)), lambda s: +1, lambda s: 1.0 if s in doorways else 0.0)

def sweeps_to_converge(options, tol=1e-9):
    """Synchronous value iteration over primitives + options; returns (#sweeps, V)."""
    V = [-100.0] * N + [0.0]; sweeps = 0   # pessimistic start; goal value is 0
    while True:
        new = V[:]
        for s in range(N):
            cands = []
            for a in (-1, +1):
                s2, r = step(s, a); cands.append(r + GAMMA * V[s2])
            for o in options:
                if s in o.init:
                    s2, R, tau = run_option(o, s)
                    cands.append(R + GAMMA ** tau * V[s2])       # SMDP backup
            new[s] = max(cands)
        sweeps += 1
        if max(abs(x - y) for x, y in zip(new, V)) < tol:
            return sweeps, new
        V = new

if __name__ == "__main__":
    print(run_option(run_right, 0))
    n0, V0 = sweeps_to_converge([]); n1, V1 = sweeps_to_converge([run_right])
    print("sweeps primitives only: %d, with option: %d" % (n0, n1))
    print("V(0) = %.4f, %.4f" % (V0[0], V1[0]))
    assert max(abs(a - b) for a, b in zip(V0, V1)) < 1e-6 and n1 < n0
    print("self-test passed")
```

Expected: `(4, -3.439, 4)`, then 12 sweeps without the option and 4 with it, the same $V(0)=-6.8619$ in both cases.

### Extension challenge

Make the termination stochastic ($\beta=0.25$ everywhere). Estimate $\mathbb E[\tau]$ and $\mathbb E[R]$ by simulation with a fixed seed and compare with the geometric-distribution prediction.

### Library track

Redo the option value iteration with NumPy (`pip install numpy`). Save your stdlib solution as `lab20.py` (the starter code with the stubs implemented; importing it will also run your tests). The script builds the SMDP as arrays of next state, reward and $\gamma^\tau$, runs vectorised value iteration and compares it with your `sweeps_to_converge`; the last part checks the stochastic-termination extension by simulation (it ignores the goal and walls, so $\tau$ is exactly geometric).

```python
import numpy as np
from lab20 import N, GOAL, GAMMA, step, run_option, run_right, sweeps_to_converge

# Build the SMDP as arrays: for every (state, decision) store next state, reward R and gamma**tau.
decisions = []                                   # (name, callable s -> (s_end, R, tau) or None)
decisions.append(("left",  lambda s: (*step(s, -1)[:1], step(s, -1)[1], 1)))
decisions.append(("right", lambda s: (*step(s, +1)[:1], step(s, +1)[1], 1)))
decisions.append(("run_right", lambda s: run_option(run_right, s) if s in run_right.init else None))

S = N + 1
nxt = np.zeros((S, len(decisions)), int); R = np.zeros_like(nxt, float)
disc = np.zeros_like(R); valid = np.zeros_like(R, bool)
for s in range(N):                               # the goal state is terminal with V = 0
    for j, (_, f) in enumerate(decisions):
        out = f(s)
        if out is not None:
            nxt[s, j], R[s, j], tau = out
            disc[s, j] = GAMMA ** tau; valid[s, j] = True

V = np.full(S, -100.0); V[GOAL] = 0.0
sweeps = 0
while True:                                      # synchronous SMDP value iteration, vectorised
    Q = np.where(valid, R + disc * V[nxt], -np.inf)
    new = V.copy(); new[:N] = Q[:N].max(axis=1)
    sweeps += 1
    if np.abs(new - V).max() < 1e-9: break
    V = new

n1, V1 = sweeps_to_converge([run_right])
assert sweeps == n1 == 4
assert np.allclose(V, V1, atol=1e-9)
print("sweeps", sweeps, "V(0) = %.4f" % V[0])

# Extension: stochastic termination, beta = 0.25 every step -> tau ~ Geometric(0.25), E[tau] = 4
rng = np.random.default_rng(0)
tau = rng.geometric(0.25, size=100_000)
assert abs(tau.mean() - 4.0) < 0.05
Rs = (1 - GAMMA ** tau) / (1 - GAMMA) * -1.0     # reward -1 per step, discounted sum of tau terms
# exact E[R] = -sum_k gamma^k P(tau > k) = -sum_k (0.9*0.75)^k = -1/(1-0.675)
assert abs(Rs.mean() - (-1 / (1 - 0.9 * 0.75))) < 0.03
print("E[tau] %.3f, E[R] %.3f" % (tau.mean(), Rs.mean()))
```

Expected: 4 sweeps, $V(0)=-6.8619$, $\mathbb E[\tau]\approx4$ and $\mathbb E[R]\approx-3.08$ (exact $-1/(1-0.9\cdot0.75)=-3.077$).

## Verification

- Hand-check one option execution: the end state, the duration, and the discounted sum.
- Compare the option-level value with the flat optimal value from a primitive-only solver; they must agree when primitives are kept.
- Count how often each option is chosen and its average duration; a duration of 1 means it is not an abstraction.
- Hold out a start state and check that the skill's initiation set actually covers it.

## Failure modes

- **Discounting by $\gamma$** rather than $\gamma^\tau$: $Q(0,\text{run\_right})$ becomes $-8.13$ instead of $-6.86$.
- **Optimistic initial values** hide the speed-up: with $V\equiv0$ the maximum is dominated by too-good primitive values and the example needed 12 sweeps even with the option.
- **Never-terminating options**: without a `max_steps` guard or a timeout a bad $\beta$ blocks the agent.
- **Option collapse** in learned hierarchies: one option used everywhere, or $\beta\approx1$ everywhere.
- **Initiation set too large**: the option is started where its policy cannot succeed, and the high level blames the wrong decision.
- **Non-stationary low level**: when intra-option policies are still learning, the high level sees transitions that change over time.

## Alternatives and trade-offs

| Approach | When to use | Cost |
| --- | --- | --- |
| Flat RL | Short horizon, dense reward | Slow credit assignment for long tasks |
| Hand-designed options | Known sub-skills (grasp, navigate) | Engineering effort; fixed abstraction |
| Option-critic (learned) | No prior on decomposition | Degeneracy, extra hyperparameters |

Prefer hand-designed options with learned intra-option policies when the decomposition is obvious; prefer learning the decomposition when you cannot name the sub-skills.

## Exercise answers

1. After $\tau$ steps the remaining return is further discounted by $\gamma^\tau$ because it starts $\tau$ steps later. With $\gamma$ the future would be discounted only once; for negative rewards the value comes out too pessimistic (the negative continuation is counted too heavily), e.g. $-8.13$ instead of $-6.86$ in the worked example. A good answer states both facts.
2. Initiation: the robot is in front of the doorway region with the door open and clear path; policy: a controller that drives through; termination: pose beyond the door (success), or timeout/collision (failure). Too large an initiation set starts the skill where it cannot succeed (e.g. door closed), producing failures that the high level cannot predict.
3. End state 8, $\tau=3$, $R=-(1+0.9+0.81)=-2.71$.
4. $Q=-2.71+0.9^3(-2.71)=-2.71-1.97559=-4.68559$; $V^*(5)=-(1-0.531441)/0.1=-4.68559$. They agree because the option follows an optimal path.
5. Errors: the reward sum is not discounted ($\sum_k\gamma^kr_k$ needed); the continuation uses $\gamma$ instead of $\gamma^{\tau}$; there is no handling of a terminal end state (value 0). Correct: `sum(g**k*r for k,r in enumerate(rewards)) + gamma**tau*V[s_end]`.
6. Geometric: $\mathbb E[\tau]=1/\beta=10$; $P(\tau>20)=0.9^{20}=0.1216$.
7. If one option is used everywhere, the hierarchy adds nothing (equivalent to a flat policy); if every option terminates each step, durations are 1 and there is no temporal abstraction. Diagnostics: histogram of option usage and the mean duration of each option; a deliberation cost on terminations is a common mitigation.
8. Split $G_t$ at $\tau$ as in the text; $\tau$ and $s'$ are jointly random given $(s,o)$, so the expectation is over the joint distribution $p(s',\tau|s,o)$. With primitives included, the flat Bellman optimality backup is the special case $\tau=1$ and the option set is a superset of the flat actions; the max over a superset is at least the flat max, while every option's behaviour is realisable by a flat policy, so the value cannot exceed $V^*_{\text{flat}}$. Hence equality.
9. A flat policy can react at every step (reopen, re-grasp); the option commits for 2 s. Fixes: make the termination depend on a state signal (terminate when slip is detected, or when grip force is reached) and let the high level re-select; or add an interrupt/failure outcome that returns control to the manager (interruptible options).
10. A good answer reports sweeps and $V(0)$ for each set, shows that values stay equal when primitives are kept, notes that run_left or misaligned doorways add choices without speed-up (or even slightly slower exploration in learning), and rejects "more options always help" if a set shows no sweep reduction or a longer wall-clock time.
