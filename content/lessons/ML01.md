## Why this matters

Separate data, targets, objectives, and evaluation assumptions. This lesson develops the core calculation before asking you to apply it in a new setting. Start with the diagnostic if you think you already know it; prior tool use is not evidence of understanding.

## Intuition

Machine learning is an experimental claim: a model fitted on observed data should perform on a declared future distribution. Choosing the prediction target and evaluation split is part of the algorithm. A sophisticated network cannot rescue an invalid test.

![A pipeline diagram: all data split into train, validation and test; the scaler and model are fit on train, choices are made on validation, test is used once at the end, and a crossed-out leakage path from test to training.](/lesson-figures/ML01.svg)

*Evaluation is only honest if no test information reaches fitting or selection.*

Before any formula, picture what a test score is. You hand a model a set of questions it has never seen and count its mistakes; the number only means something if the questions resemble the ones it will meet after deployment and if nothing about them leaked into its preparation. A student who has memorised last year's exam and then sits the same exam scores 100%, and nobody concludes that the student knows the subject. Every concept in this lesson (splits, baselines, metrics, leakage) is a way of making sure the exam is a fair one.

A concrete robot example: ten warehouse robots each record 5,000 camera frames while driving, and you want to predict battery drain from the frames. Consecutive frames from one robot are almost the same picture with the same worn wheel and the same battery. If you shuffle all 50,000 frames and hold out 20%, almost every test frame has a near-twin in the training set, and the model can score well just by recognising the robot. The question you actually care about is "how will it do on robot number eleven?", and only a split that holds out whole robots asks that question.

**Predict before you compute.** Suppose a model that always predicts the training mean has a test MSE of 4.0 and your neural network reports 3.8. Before reading on, decide: is that a good result? What extra information would change your mind (the noise level of the target, the number of test samples, whether 3.8 was the best of many tries)? You should end up with "I cannot tell yet": a loss number has no scale without a reference, a noise floor and an uncertainty.

**The common wrong intuition** is that more data in the training set and a lower number on the test set always mean a better model. Both can be false at the same time: the test number can be lower because the split was easier (near-duplicates, an easy class balance) or because the test set was used to pick the model, and a fitted model can be worse than a trivial baseline on the distribution that matters. Honest evaluation is therefore a design decision made before training, not a calculation done afterwards.

## Theory and derivation

For supervised data $D=\{(x_i,y_i)\}_{i=1}^N$, a predictor $f_\theta(x)$ is fitted by minimizing empirical risk $\hat R(\theta)=N^{-1}\sum_i\ell(f_\theta(x_i),y_i)$. The future risk $R(\theta)=E_{(x,y)\sim P}[\ell(f_\theta(x),y)]$ depends on the deployment distribution $P$, which training data only approximates.

Training data fits parameters; validation data selects models and hyperparameters; the test set estimates final performance after those choices are fixed. If normalization, feature selection, or duplicate samples use test information, the reported test result is biased. Fit preprocessing on training data and reuse its parameters unchanged.

Choose a baseline before a complex model. For squared error with a constant predictor $c$, differentiate $N^{-1}\sum_i(c-y_i)^2$ to get $2(c-\bar y)$, so the optimal training constant is the training mean. Baselines turn “the loss is small” into a meaningful comparison.

### The best constant for each loss: mean, median and mode

The lesson derived the training mean as the best constant for squared error. The general statement is Bishop's decision-theory result for regression (Bishop, *Pattern Recognition and Machine Learning*, §1.5.5). For a target $t$ with conditional distribution $p(t\mid x)$ and a prediction $y(x)$, the expected squared loss is $E[(y-t)^2]=\int (y(x)-t)^2p(x,t)\,dx\,dt$. Writing $h(x)=E[t\mid x]$ and adding and subtracting it inside the square,
$$E[(y-t)^2]=E[(y-h)^2]+2E[(y-h)(h-t)]+E[(h-t)^2].$$
The cross term vanishes because $E[h-t\mid x]=0$ and $y-h$ depends only on $x$. Hence
$$E[(y-t)^2]=\underbrace{E[(y(x)-h(x))^2]}_{\text{controlled by the model}}+\underbrace{E[\operatorname{Var}(t\mid x)]}_{\text{irreducible noise}}$$
(Bishop's eq. 1.90). Two consequences for evaluation: the best possible predictor is $h(x)$, and **no model can have expected test MSE below the noise term**, so a test loss must be read against *both* a constant baseline (the upper reference, with $\operatorname{Var}(t)$ in place of the model term) and the noise floor (the lower reference).

For other losses the optimal constant changes. For the absolute loss $E|t-c|$ with a continuous distribution, $\frac{d}{dc}E|t-c|=P(t<c)-P(t>c)=2F(c)-1$, which vanishes at $F(c)=\tfrac12$: the **median**. For the asymmetric *pinball* loss $\rho_\tau(u)=\tau u$ for $u\ge0$ and $(\tau-1)u$ for $u<0$, with $u=t-c$, the derivative is $F(c)-\tau$, so the minimiser is the $\tau$-quantile. Because each loss is convex in $c$, the stationary point is the global minimum. As $q\to0$ the loss $|t-c|^q$ approaches a 0-1 loss and the minimiser tends to the **mode** (Bishop, §1.5.5 and Exercise 1.27). The lesson on baselines follows: pick the constant that matches the loss you will be judged by, because the mean baseline is not the right reference for an absolute-error metric.

### Cross-validation as an estimator, and why the leave-one-out error is a little pessimistic

$K$-fold cross-validation (Mathematics for Machine Learning, §8.2.4) partitions the data into $K$ chunks, trains $f^{(k)}$ on $K-1$ of them and evaluates on the held-out chunk $V^{(k)}$, and averages: $E_V[R(f,V)]\approx\frac1K\sum_k R(f^{(k)},V^{(k)})$ (MML eq. 8.13). The authors note two sources of error in that approximation: each $f^{(k)}$ is trained on less data than the final model, and each validation chunk is finite. With $K=N$ this is leave-one-out (LOO).

For the constant-mean predictor LOO has a closed form, a good test of the definition. The mean without point $i$ is $\bar y_{-i}=(N\bar y-y_i)/(N-1)$, so the LOO residual is
$$y_i-\bar y_{-i}=\frac{N}{N-1}\,(y_i-\bar y),\qquad \text{LOO MSE}=\Big(\frac N{N-1}\Big)^2\cdot \underbrace{\tfrac1N\textstyle\sum_i(y_i-\bar y)^2}_{\text{training MSE}}.$$
If the $y_i$ are i.i.d. with variance $\sigma^2$, then $E[\text{training MSE}]=\sigma^2\frac{N-1}{N}$, so $E[\text{LOO MSE}]=\sigma^2\frac N{N-1}$, while the true error on a fresh point is $E(y^*-\bar y)^2=\sigma^2\frac{N+1}{N}$. The ratio $N^2/(N^2-1)>1$: LOO is slightly **pessimistic** (it trains on $N-1$ points) and the training error is optimistic. The same pattern, a gap that shrinks like $1/N$, is what to expect from any cross-validation.

### Selecting on the test set: the best of $K$ is biased upward

Exercise 6 showed a numerical example. The general fact: if $\hat A_1,\dots,\hat A_K$ are noisy estimates of the true accuracies $A_k$ with $E\hat A_k=A_k$, then $E[\max_k\hat A_k]\ge\max_kE[\hat A_k]=\max_kA_k$, by applying $\max_k\hat A_k\ge\hat A_{k^*}$ to the index $k^*$ of the best true accuracy and taking expectations. The inequality is strict when the estimates are noisy and several candidates are close. The reported score is therefore biased upward, and the bias grows with $K$ and with the estimator's noise. The remedy is to keep the test set out of model selection entirely, or when data is scarce to use **nested cross-validation** (MML §8.6.1), whose outer loop estimates the performance of the *whole selection procedure*, not of one chosen model.

### Risk, empirical risk and the assumptions behind a test score

Define the loss $\ell(\hat y,y)$ and the **risk** $R(f)=E_{(x,y)\sim P}[\ell(f(x),y)]$ of a predictor $f$; the **empirical risk** on a finite sample is $\hat R(f)=N^{-1}\sum_i\ell(f(x_i),y_i)$ (MML §8.2, empirical risk minimisation). Three facts do all the work in this lesson. First, $\hat R$ computed on the data that was used to choose $f$ is a biased (optimistic) estimate of $R$, because $f$ was selected to make exactly that number small; this is the *generalisation gap*. Second, if $f$ is fixed *before* looking at a sample $S$ whose points are drawn i.i.d. from $P$, then $\hat R_S(f)$ is an **unbiased** estimate of $R(f)$, since $E[\hat R_S(f)]=N^{-1}\sum_iE[\ell(f(x_i),y_i)]=R(f)$ by linearity; this is why a test set must be untouched. Third, the standard error of that estimate shrinks like $1/\sqrt N$ only under the independence assumption, which we examine below.

Every word of "i.i.d. from $P$" is an assumption that can fail in robotics. *Identically distributed* fails under distribution shift: a new robot, a new warehouse, a battery that has aged since training. *Independent* fails for frames of one run, for time series, and for several samples of the same physical part. When the assumptions fail the estimate is still a number, but it estimates the risk under a different distribution (the one the split happened to create), not the deployment risk. The remedy is to build the split so that it mimics the deployment shift: hold out whole robots, whole runs or the most recent time period (MML §8.2.4 discusses the validation set as a proxy for unseen data, and the choice of proxy is the engineer's responsibility).

### Confusion matrices, base rates and why accuracy misleads

For a binary classifier let $\pi=P(y=1)$ be the prevalence (base rate) of the positive class, $\mathrm{TPR}=P(\hat y=1\mid y=1)$ the recall and $\mathrm{FPR}=P(\hat y=1\mid y=0)$ the false-alarm rate. Then
$$\text{accuracy}=\pi\,\mathrm{TPR}+(1-\pi)(1-\mathrm{FPR}),\qquad \text{precision}=\frac{\pi\,\mathrm{TPR}}{\pi\,\mathrm{TPR}+(1-\pi)\,\mathrm{FPR}},$$
the second being Bayes' theorem. With $\pi=0.02$, as in exercise 1, the always-negative classifier has $\mathrm{TPR}=0$, $\mathrm{FPR}=0$ and accuracy $1-\pi=0.98$: accuracy is dominated by the majority class. More importantly, precision depends on the prevalence: a detector with a respectable $\mathrm{TPR}=0.75$ and $\mathrm{FPR}=0.03$ has precision $0.02\cdot0.75/(0.02\cdot0.75+0.98\cdot0.03)=0.338$ at this base rate, but precision $0.96$ on a dataset where the same detector faces $\pi=0.5$. So precision measured on a rebalanced test set does not transfer to the deployment prevalence, while recall and false-alarm rate (which condition on the true class) do. Bishop's decision-theory treatment (§1.5.1-1.5.2) formalises the underlying point: the right operating point is the one that minimises *expected loss* given the class costs, not the one that maximises accuracy.

### How certain is a test estimate? Binomial error and clustered data

For $n$ independent test cases with true accuracy $p$, the number correct is Binomial$(n,p)$, so the estimate $\hat p$ has variance $p(1-p)/n$ and standard error $\sqrt{p(1-p)/n}$ (use $\hat p$ in place of $p$ for an approximate $\hat p\pm1.96\,\mathrm{SE}$ interval, valid when $n\hat p$ and $n(1-\hat p)$ are not small). Now suppose the $n=km$ cases come in $k$ clusters (robots, runs) of $m$ cases, with a common pairwise correlation $\rho$ inside a cluster and zero between clusters. For unit-variance cases, the variance of the overall mean is
$$\operatorname{Var}\Big(\frac1n\sum_i z_i\Big)=\frac1{n^2}\Big(n+k\,m(m-1)\rho\Big)=\frac{1+(m-1)\rho}{n},$$
because each cluster contributes $m$ variance terms and $m(m-1)$ ordered covariance terms. The **design effect** is $1+(m-1)\rho$ and the **effective sample size** is $n_{\text{eff}}=n/(1+(m-1)\rho)$. With ten robots and $m=500$ frames each at $\rho=0.5$, $n=5000$ gives $n_{\text{eff}}\approx20$: the interval you would compute from 5000 independent frames is about $\sqrt{250}\approx16$ times too narrow. This is the quantitative reason that a split by robot and a report of the spread across robots (the lesson's exercise 4) is the honest procedure, and why exercise 8's "independence might fail" is not a technicality.

### Choosing a split that matches the deployment question

A split is a statement about the future. Write the deployment question first, then choose the split whose held-out part differs from the training part in the same way the future differs from the past. If the model will run on **new robots**, hold out whole robots (grouped $K$-fold or leave-one-group-out). If it will run **next month**, hold out the latest period and train on earlier ones, because shuffling lets the model interpolate between neighbouring time points that it would never have in advance. If one class is rare, **stratify** so that each fold contains the rare class; stratification fixes the variance of the estimate, not its bias. If the aim is only to compare algorithms on i.i.d. data, ordinary $K$-fold (MML §8.2.4) is adequate. In every case the rule that preprocessing is fitted on training data only applies inside each training fold: scalers, feature selection, class weights and hyper-parameter choices are fitted on the training fold alone.

When hyper-parameters are also tuned, one level of cross-validation is no longer enough to *report* performance, because the selection step has used every fold. Nested cross-validation (MML §8.6.1) wraps the whole procedure: the inner loop chooses hyper-parameters using only the outer training part, the outer loop scores the chosen model on data the inner loop never saw. The price is $K_{\text{outer}}\times K_{\text{inner}}$ training runs. Report the mean and the spread across outer folds (or across groups), not only the mean, because the spread is the information about robustness that a single number hides; the worst held-out group is often the one that matters for safety.

## Worked example

### Basic case

**Problem.** A dataset has 95 nondefective and 5 defective items. (a) A model always predicts "nondefective". Compute its accuracy and its defect recall and say whether accuracy is a suitable metric. (b) Images of the same physical part appear in both the train and the test set after a random image split. Explain what goes wrong with the test score.

**Solution.**

1. *Confusion counts for (a).* Always predicting nondefective gives true negatives $TN=95$, false negatives $FN=5$ (every defect is missed), true positives $TP=0$, false positives $FP=0$.
2. *Accuracy.* $\text{accuracy}=\dfrac{TP+TN}{N}=\dfrac{0+95}{100}=0.95=95\%$.
3. *Defect recall.* $\text{recall}=\dfrac{TP}{TP+FN}=\dfrac{0}{0+5}=0$. The model finds none of the defects it exists to find.
4. *Choosing the metric.* A 95% score hides a useless detector, so the metric should reflect the cost of missed defects: recall on the defect class (together with precision, or a cost-weighted error) instead of plain accuracy.
5. *Leakage for (b).* A random image split puts some images of part $P$ in train and others in test. Test images of $P$ are near-duplicates of training images (same part, same lighting and texture), so a model that memorises part identity scores well on test without learning the defect pattern. The test set no longer represents unseen parts, so the split must be done by part (group split), not by image.

**Check.** Sanity bound: with 5 positives, recall can only be $0,\ 0.2,\ 0.4,\dots,1$, and the baseline sits at the lowest value. The balanced accuracy $\tfrac12(\text{recall}+\text{specificity})=\tfrac12(0+1)=0.5$ equals the chance level, which agrees with "useless", whereas accuracy $0.95$ does not.

**Takeaway.** Accuracy on imbalanced data and random splits on grouped data both produce flattering numbers; choose the metric by the cost of errors and the split by how the model will be deployed.

### Harder case: the same data, three honest-looking scores

**Problem.** Six frames come from three robots A, B, C, two frames each, with target (battery drain, %/h) $y=(10,12\,|\,20,22\,|\,30,32)$. Two predictors are compared: the global mean, and a "robot memoriser" that predicts the mean target of the training frames from the *same robot* (and falls back to the global training mean if the robot was never seen). Compute the baseline training MSE, the random leave-one-frame-out MSE and the leave-one-robot-out MSE of both predictors, and interpret the three scores.

**Solution.**

1. *Baseline spread.* $\bar y=(10+12+20+22+30+32)/6=126/6=21$. The squared deviations are $121,81,1,1,81,121$, summing to $406$, so the training MSE of the global mean is $406/6=67.67$.
2. *Leave-one-frame-out, global mean.* Leaving out frame $i$ the training mean is $(6\bar y-y_i)/5$, so the residual is $y_i-\frac{6\bar y-y_i}{5}=\frac65(y_i-\bar y)$ (the closed form of the theory section). The residuals are $\frac65(-11,-9,-1,1,9,11)=(-13.2,-10.8,-1.2,1.2,10.8,13.2)$ and the MSE is $1.44\times67.67=97.44$.
3. *Leave-one-frame-out, memoriser.* The left-out frame's partner from the same robot is still in training, so the prediction is the partner's value. The residuals are $(-2,+2,-2,+2,-2,+2)$, every one $\pm2$, so MSE $=4.0$. The score "4.0" looks excellent.
4. *Leave-one-robot-out, global mean.* Remove both frames of a robot and fit on the other four. Holding out A: training mean $(20+22+30+32)/4=26$, errors $10-26=-16$ and $12-26=-14$. Holding out B: mean $(10+12+30+32)/4=21$, errors $-1,+1$. Holding out C: mean $(10+12+20+22)/4=16$, errors $+14,+16$. MSE $=(256+196+1+1+196+256)/6=906/6=151.0$.
5. *Leave-one-robot-out, memoriser.* The held-out robot has never been seen, so the memoriser falls back to the same global training mean as in step 4 and scores the same $151.0$.
6. *Reading the three numbers.* The memoriser's $4.0$ against $151.0$ is the leakage gap: the random split rewards recognising the robot, which will not exist for a new robot. Both predictors tie at $151.0$ under the split that matches deployment, which says the memoriser has learned nothing transferable, and the per-robot errors $(16,14,1,1,14,16)$ show that an "average robot" is a poor description of the extremes.

**Check.** All figures were recomputed in Python (baseline $406/6$, LOO $97.44$, memoriser $4.0$, grouped $906/6=151.0$). Cross-check of step 2: $97.44/67.67=1.44=(6/5)^2$, as the formula predicts. Sanity bound: the grouped score $151$ is above the in-sample $67.67$, as expected when the held-out unit is a whole new robot.

**Takeaway.** The same predictor scored $4.0$ or $151.0$ depending only on how the data were split; the split must mirror the deployment unit (a new robot), or the score measures memory, not generalisation.

# 3. Leakage demo: a one-hot group id predicts y by memorising per-group offsets
from sklearn.model_selection import KFold
from sklearn.preprocessing import OneHotEncoder
rng = np.random.default_rng(0)
groups = np.repeat(np.arange(10), 50)
y = rng.normal(0, 5, 10)[groups] + rng.normal(0, 0.5, 500)    # per-group offset plus noise
X = groups.reshape(-1, 1)
model = make_pipeline(OneHotEncoder(handle_unknown="ignore"), LinearRegression())
r2_random = cross_val_score(model, X, y, cv=KFold(5, shuffle=True, random_state=0)).mean()
r2_group = cross_val_score(model, X, y, cv=GroupKFold(5), groups=groups).mean()
assert r2_random > 0.9 and r2_group < 0.1                     # honest grouped score exposes the memorisation
for tr, te in GroupKFold(5).split(X, y, groups):
    assert set(groups[tr]).isdisjoint(groups[te])
print("random-split R^2 > 0.9:", r2_random > 0.9, "| grouped R^2 < 0.1:", r2_group < 0.1)
