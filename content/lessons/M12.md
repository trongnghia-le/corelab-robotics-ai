## Why this matters

Attach every coordinate to a frame and keep point and direction transforms distinct. This lesson develops the core calculation before asking you to apply it in a new setting. Start with the diagnostic if you think you already know it; prior tool use is not evidence of understanding.

## Intuition

A frame is a coordinate ruler with an origin and oriented axes. Two observers can describe the same physical point with different numbers. A robot camera, wrist, and world frame need explicit relationships; coordinates without frame labels invite mistakes that can look numerically plausible.

## Theory and derivation

Let ${}^Ap$ be coordinates of a point in frame A. If frame B has orientation ${}^AR_B$ and origin ${}^At_B$ in A, then
$${}^Ap={}^AR_B\,{}^Bp+{}^At_B.$$
The columns of the rotation are B basis directions expressed in A. A direction or displacement has no origin offset: ${}^Av={}^AR_B{}^Bv$.

For a planar angle $\theta$, rotated basis vectors are $(\cos\theta,\sin\theta)$ and $(-\sin\theta,\cos\theta)$, hence $R=[[\cos\theta,-\sin\theta],[\sin\theta,\cos\theta]]$. Orthogonality gives $R^TR=I$, so solving $p_A=Rp_B+t$ yields $p_B=R^T(p_A-t)$.

Homogeneous coordinates combine rotation and translation: $T=[[R,t],[0,1]]$. Use the last coordinate 1 for a point and 0 for a direction. This bookkeeping encodes why translation acts on one but not the other.

## Worked example

B is rotated +90° and translated (1,2) in A. The B point (2,0) becomes R(2,0)+(1,2)=(1,4) in A. Subtract the translation and rotate by −90° to recover (2,0). The direction (2,0) transforms to (0,2), without adding (1,2).

## Exercises

1. **(Easy)** Frame B is rotated $30^\circ$ and its origin is at $(2,1)$ in frame A. A point has B-coordinates $(1,0)$. Find its A-coordinates, then recover the B-coordinates using $R^T$. *(Adapted from: Lynch and Park, Modern Robotics, Ch. 3 on rigid-body motions)*
2. **(Easy)** Write the homogeneous $3\times3$ matrix for the frame in the lesson's worked example (rotation $+90^\circ$, translation $(1,2)$). Transform the point $(2,0,1)$ and the direction $(2,0,0)$. Which has the last coordinate 1 and why?
3. **(Medium)** **Sensor chain.** A mobile robot has world pose $x=3,\ y=1,\ \theta=90^\circ$. A lidar is mounted at $(0.3,0)$ in the robot frame (no rotation relative to the robot). It reports a point at $(1.7,0.5)$ in the lidar frame. Find the point in robot coordinates and in world coordinates, showing the two transforms. *(Adapted from: Thrun, Burgard and Fox, Probabilistic Robotics, Ch. 6 on robot perception and measurement geometry)*
4. **(Medium)** Derive the inverse of $T=\begin{pmatrix}R&t\\0&1\end{pmatrix}$ and compute it for $R=R(90^\circ),\ t=(1,2)$. Check it by applying it to $(1,4)$. Why is it wrong to invert a transform by negating $t$ only?
5. **(Medium)** **Predict the output.** $T_1$ rotates by $90^\circ$ and translates by $(1,0)$; $T_2$ is a pure translation by $(0,1)$. Predict $(T_1T_2)(1,0)$ and $(T_2T_1)(1,0)$ as plain points before running any code, and explain which transform acts first in each product.
6. **(Medium)** **Find the bug.** A controller converts the robot's velocity from robot to world coordinates:
   ```python
   vx_w = R[0][0]*vx + R[0][1]*vy + tx
   vy_w = R[1][0]*vx + R[1][1]*vy + ty
   ```
   with $R=R(90^\circ)$, $t=(3,1)$, $v=(1,0)$ m/s. Compute the buggy and the correct world velocity and say which physical rule was violated.
7. **(Hard)** **Proof.** Show $R(\theta)^TR(\theta)=I$ and $\det R=1$, and prove $R(a)R(b)=R(a+b)$. Why does this imply that planar rotations commute but planar rigid transforms with translation generally do not?
8. **(Hard)** Compare "rotate $90^\circ$ then translate $(0,1)$" with "translate $(0,1)$ then rotate $90^\circ$" on the point $(1,0)$. Give the homogeneous matrix product that represents each and relate the order of matrices to the order of operations.
9. **(Hard)** **Design.** A camera is mounted on an arm on a mobile base. List every calibration quantity needed to express a camera detection in the world frame, and compute how a $1^\circ$ error in the base-to-camera rotation moves a detection $2$ m away. Which error would you expect to dominate for a long-range detection? *(Adapted from: Szeliski, Computer Vision: Algorithms and Applications, Ch. 2 on geometric primitives and transformations)*
10. **(Project)** Write an `SE2` class with `compose`, `inverse`, `apply_point` and `apply_direction`. Test: $T\,T^{-1}=I$, associativity, a point versus a direction, and that composing $a$ then $b$ differs from $b$ then $a$.

Paste this below the starter code (same file) and run it. Every check is a plain `assert`; the first failure stops the run.

```python
import random
def close(a, b, t=1e-9): return all(abs(x - y) < t for x, y in zip(a, b))
def eye_ok(M): return all(abs(M[i][j] - (1.0 if i == j else 0.0)) < 1e-9 for i in range(3) for j in range(3))
R90 = math.pi / 2
T = make_T(R90, 1, 2)

assert close(apply_point(inverse_T(T), (1, 4)), (2, 0))
# sensor chain: world <- robot <- lidar
T_WR = make_T(R90, 3, 1); T_RL = make_T(0, 0.3, 0)
assert close(apply_point(matmul3(T_WR, T_RL), (1.7, 0.5)), (2.5, 3.0))
# order matters: T1 = rotate 90 + translate (1,0); T2 = translate (0,1)
T1, T2 = make_T(R90, 1, 0), make_T(0, 0, 1)
assert close(apply_point(matmul3(T1, T2), (1, 0)), (0, 1)) and close(apply_point(matmul3(T2, T1), (1, 0)), (1, 2))
# invariants on random rigid transforms
random.seed(4)
for _ in range(100):
    A = make_T(random.uniform(-3, 3), random.uniform(-5, 5), random.uniform(-5, 5))
    B = make_T(random.uniform(-3, 3), random.uniform(-5, 5), random.uniform(-5, 5))
    p, q = (random.uniform(-3, 3), random.uniform(-3, 3)), (random.uniform(-3, 3), random.uniform(-3, 3))
    assert eye_ok(matmul3(A, inverse_T(A)))
    assert close(apply_point(matmul3(A, B), p), apply_point(A, apply_point(B, p)))                # composition
    d = math.dist(p, q); assert abs(math.dist(apply_point(A, p), apply_point(A, q)) - d) < 1e-9   # rigid: distances preserved
    dv = apply_direction(A, (p[0] - q[0], p[1] - q[1]))
    assert close(dv, (apply_point(A, p)[0] - apply_point(A, q)[0], apply_point(A, p)[1] - apply_point(A, q)[1]))
print("world point of the lidar hit:", tuple(round(v, 3) for v in apply_point(matmul3(T_WR, T_RL), (1.7, 0.5))))
```

### Library track
Redo the lab with NumPy and SciPy (`pip install numpy scipy` in a virtual environment): $3\times3$ homogeneous matrices as NumPy arrays with `@`, `np.linalg.inv` against your closed-form inverse, and `scipy.spatial.transform.Rotation` to build the rotation of a $4\times4$ 3D transform. Every assert reuses a number from the lesson.

```python
import numpy as np
from scipy.spatial.transform import Rotation

def make_T(theta, tx, ty):
    c, s = np.cos(theta), np.sin(theta)
    return np.array([[c, -s, tx], [s, c, ty], [0, 0, 1.0]])

T = make_T(np.pi / 2, 1, 2)
assert np.allclose(T @ [2, 0, 1], [1, 4, 1]) and np.allclose(T @ [2, 0, 0], [0, 2, 0])   # point vs direction
assert np.allclose(np.linalg.inv(T) @ [1, 4, 1], [2, 0, 1])

# Sensor chain world <- robot <- lidar (exercise 3)
T_WR, T_RL = make_T(np.pi / 2, 3, 1), make_T(0, 0.3, 0)
assert np.allclose(T_WR @ T_RL @ [1.7, 0.5, 1], [2.5, 3.0, 1])

# Order matters (exercise 5)
T1, T2 = make_T(np.pi / 2, 1, 0), make_T(0, 0, 1)
assert np.allclose((T1 @ T2) @ [1, 0, 1], [0, 1, 1]) and np.allclose((T2 @ T1) @ [1, 0, 1], [1, 2, 1])

# SciPy's Rotation agrees with the 2D matrix when the rotation is about z
R = Rotation.from_euler("z", 90, degrees=True)
assert np.allclose(R.apply([2, 0, 0]), [0, 2, 0])
assert np.allclose(R.as_matrix()[:2, :2], T[:2, :2])

# 3D version: a 4x4 homogeneous transform built from a SciPy rotation, with its closed-form inverse
T3 = np.eye(4); T3[:3, :3] = R.as_matrix(); T3[:3, 3] = [1, 2, 0]
T3_inv = np.eye(4); T3_inv[:3, :3] = R.as_matrix().T; T3_inv[:3, 3] = -R.as_matrix().T @ [1, 2, 0]
assert np.allclose(T3 @ T3_inv, np.eye(4)) and np.allclose(T3_inv, np.linalg.inv(T3))
print("library track ok")
```

## Failure modes

A translation vector must use the output frame of the equation. “Rotate the frame” and “rotate the object” can use inverse matrices; write the mapping equation to remove ambiguity.

## Alternatives and trade-offs

Cartesian coordinates are convenient for translation and linear maps. Polar coordinates expose radius and bearing but have angle wrapping and an undefined bearing at the origin. Choose the representation to match the calculation.

## Exercise answers

1. $R=\begin{pmatrix}\cos30^\circ&-\sin30^\circ\\\sin30^\circ&\cos30^\circ\end{pmatrix}$, $R(1,0)=(0.866,0.5)$, so $p_A=(2.866,1.5)$. Back: $R^T(p_A-t)=R^T(0.866,0.5)=(1,0)$.
2. $T=\begin{pmatrix}0&-1&1\\1&0&2\\0&0&1\end{pmatrix}$. Point $(2,0,1)\to(1,4,1)$. Direction $(2,0,0)\to(0,2,0)$. The point carries a 1 so the translation column is added; the direction has 0 and ignores it: displacements do not depend on where the origin is.
3. Lidar to robot: $(1.7,0.5)+(0.3,0)=(2.0,0.5)$. Robot to world: $R(90^\circ)(2.0,0.5)=(-0.5,2.0)$, plus $(3,1)$ gives $(2.5,3.0)$. As matrices $T_{WR}T_{RL}$ acting on the lidar point (rightmost first).
4. $p'=Rp+t\Rightarrow p=R^T(p'-t)=R^Tp'-R^Tt$, so $T^{-1}=\begin{pmatrix}R^T&-R^Tt\\0&1\end{pmatrix}$. Here $R^T=\begin{pmatrix}0&1\\-1&0\end{pmatrix}$, $-R^Tt=-(2,-1)=(-2,1)$. Apply to $(1,4)$: $R^T(1,4)=(4,-1)$, plus $(-2,1)$ gives $(2,0)$. Negating $t$ alone ignores that the translation was applied after the rotation.
5. $T_1T_2$ means $T_2$ first: $(1,0)\to(1,1)\to R(1,1)+(1,0)=(-1,1)+(1,0)=(0,1)$. $T_2T_1$ means $T_1$ first: $(1,0)\to(0,1)+(1,0)=(1,1)\to(1,2)$. Results $(0,1)$ and $(1,2)$.
6. Buggy: $(0+3,\ 1+1)=(3,2)$; correct: $R(1,0)=(0,1)$ m/s. A velocity is a direction (displacement per time) and must not receive the frame's translation; use the last homogeneous coordinate 0.
7. $R^TR=\begin{pmatrix}c&s\\-s&c\end{pmatrix}\begin{pmatrix}c&-s\\s&c\end{pmatrix}=\begin{pmatrix}c^2+s^2&0\\0&s^2+c^2\end{pmatrix}=I$; $\det=c^2+s^2=1$. $R(a)R(b)$ has entries such as $\cos a\cos b-\sin a\sin b=\cos(a+b)$ and $\sin a\cos b+\cos a\sin b=\sin(a+b)$, hence $R(a+b)$. Angles add commutatively, so planar rotations commute. With translations the order changes which vector gets rotated, so $T_aT_b\ne T_bT_a$ in general.
8. Rotate then translate: $(1,0)\to(0,1)\to(0,2)$, matrix $T_{\rm trans}R$. Translate then rotate: $(1,0)\to(1,1)\to(-1,1)$, matrix $R\,T_{\rm trans}$. The matrix written leftmost acts last.
9. Needed: world-to-base pose (localisation), base-to-arm mounting, arm joint angles through forward kinematics, arm-to-camera extrinsics (hand-eye calibration), plus camera intrinsics to convert pixels to a ray. A $1^\circ$ rotation error at 2 m gives lateral error $2\sin1^\circ\approx0.035$ m. For long range the rotation errors dominate because they scale with distance, while translation errors stay constant.
10. A good answer checks $T\,T^{-1}\approx I$ with a tolerance, includes a non-commuting pair, verifies directions ignore translation, and tests angle wrap-around.
