## Why this matters

Value-based methods learn how good actions are and then act greedily. That breaks down when actions are continuous, when you want a stochastic policy (for exploration, or because the state is partly hidden), or when a tiny change in values flips the chosen action and makes learning jump. Policy gradient methods skip the middle step: they parametrise the policy $\pi_\theta(a\mid s)$ directly and climb the expected return by gradient ascent. Every modern robot-learning algorithm that outputs actions from a network (PPO, SAC, diffusion policies fine-tuned with RL) builds on the identity derived here.

The derivation is short, but the estimator it gives is noisy, can vanish, and is easy to implement with a wrong sign. This lesson works on the smallest case, a softmax policy over two or three actions, where the exact gradient can be written down and every claim checked.

## Intuition

The return depends on $\theta$ only through the probabilities with which actions are chosen. If action 1 pays more than the average, you want to raise its probability; if it pays less, lower it. The policy gradient says exactly this: each action's logit moves in proportion to how much better than average it is and how often it is chosen.

![Expected return of a two-action softmax policy as a function of the logit gap, with slope 0.5 at the origin and flat tails](/lesson-figures/RL08.svg)

*With rewards (1, 3), $J=1+2\sigma(d)$ in the logit gap $d$. The slope at $d=0$ is the policy gradient; in both tails the policy is nearly deterministic and the slope, hence the learning signal, vanishes.*

Two practical facts follow from the picture. A gradient computed from one sampled action is a noisy stand-in for the slope. And a policy that has become almost deterministic barely learns, because it almost never tries the alternative.

## Theory and derivation

### Objective and the log-derivative trick

For a one-step problem with reward $R(a)$ and policy $\pi_\theta(a)$,

$$J(\theta)=\sum_a\pi_\theta(a)R(a)=\mathbb E_{a\sim\pi_\theta}[R(a)].$$

Differentiate under the sum and use $\nabla\pi=\pi\,\nabla\log\pi$:

$$\nabla_\theta J=\sum_a R(a)\nabla_\theta\pi_\theta(a)=\sum_a\pi_\theta(a)R(a)\nabla_\theta\log\pi_\theta(a)=\mathbb E_{a\sim\pi_\theta}\bigl[R(a)\,\nabla_\theta\log\pi_\theta(a)\bigr].$$

The right side is an expectation under the policy itself, so you can estimate it from samples without knowing how $R$ depends on the action. For an episode with states, the same argument gives the **policy gradient theorem**

$$\nabla_\theta J=\mathbb E_\pi\Bigl[\sum_t \nabla_\theta\log\pi_\theta(a_t\mid s_t)\,G_t\Bigr],$$

with $G_t$ the return from time $t$ onward (reward-to-go). Only future rewards depend on $a_t$, so using $G_t$ instead of the whole-episode return is unbiased and has lower variance. This is the REINFORCE algorithm.

### The softmax score function

For $\pi_\theta(a)=e^{\theta_a}/\sum_b e^{\theta_b}$,

$$\frac{\partial\log\pi(a)}{\partial\theta_i}=\mathbf 1[i=a]-\pi_i,\qquad\text{so}\qquad \frac{\partial J}{\partial\theta_i}=\pi_i\,(R_i-J).$$

The second formula is the exact gradient: logit $i$ rises when action $i$ beats the current average $J$ and falls when it does not. The gradient sums to zero over $i$ because adding a constant to all logits does not change the policy.

### Baselines

The expected score is zero: $\sum_a\pi(a)\nabla\log\pi(a)=\nabla\sum_a\pi(a)=\nabla 1=0$. Therefore for any $b$ that does **not** depend on the action,

$$\mathbb E\bigl[(R-b)\nabla\log\pi\bigr]=\mathbb E[R\nabla\log\pi]-b\cdot0=\nabla J.$$

The mean is unchanged but the variance changes. For the constant $b$ minimising the total variance of the one-sample estimator,

$$b^*=\frac{\sum_a\pi(a)R(a)\,\|\nabla\log\pi(a)\|^2}{\sum_a\pi(a)\,\|\nabla\log\pi(a)\|^2}.$$

In practice one uses the state value $V(s)$ as the baseline, which leads directly to actor-critic methods (next lesson). A baseline that depends on the *action* is generally biased.

### Why the signal can vanish

If $\pi_i\to1$ for one action then $\pi_j\to0$ for the others and $\pi_i(R_i-J)\to0$ because $J\to R_i$. The gradient is zero at every deterministic policy, whether or not it is good. Entropy bonuses, initial near-uniform policies and careful step sizes exist for this reason.

## Worked example

Two actions with rewards $R=(1,3)$, logits $\theta=(0,0)$.

1. Policy: $\pi=(0.5,0.5)$. Return: $J=0.5\cdot1+0.5\cdot3=2$.
2. Exact gradient: $\pi_i(R_i-J)=(0.5\cdot(-1),\;0.5\cdot1)=(-0.5,\,0.5)$.
3. Scores: $\nabla\log\pi(0)=(0.5,-0.5)$, $\nabla\log\pi(1)=(-0.5,0.5)$.
4. Single-sample estimates with no baseline: action 0 gives $1\cdot(0.5,-0.5)=(0.5,-0.5)$, action 1 gives $3\cdot(-0.5,0.5)=(-1.5,1.5)$. Mean: $0.5(0.5,-0.5)+0.5(-1.5,1.5)=(-0.5,0.5)$, equal to the exact gradient.
5. Second moment: $0.5\cdot0.5+0.5\cdot4.5=2.5$; $\|\text{mean}\|^2=0.5$; total variance $=2.0$.
6. With $b=J=2$: action 0 gives $(-1)(0.5,-0.5)=(-0.5,0.5)$ and action 1 gives $(1)(-0.5,0.5)=(-0.5,0.5)$. Both samples are identical, so the mean is still $(-0.5,0.5)$ and the variance is $0$.
7. Independent check: $J(d)=1+2\sigma(d)$ with $d=\theta_1-\theta_0$, so $dJ/d\theta_1=2\sigma(0)(1-\sigma(0))=0.5$. This matches step 2.

## Reference implementation

```python
"""Two-action softmax policy gradient on a one-step problem (stdlib only)."""
import math, random

def softmax(theta):
    m = max(theta)
    e = [math.exp(t - m) for t in theta]
    s = sum(e)
    return [x / s for x in e]

def grad_log_prob(theta, a):
    """d log pi(a) / d theta_i = 1[i == a] - pi_i for a softmax policy."""
    p = softmax(theta)
    return [(1.0 if i == a else 0.0) - p[i] for i in range(len(theta))]

def expected_return(theta, rewards):
    return sum(p * r for p, r in zip(softmax(theta), rewards))

def exact_gradient(theta, rewards):
    """grad J = sum_a pi(a) * (r_a - J) * (e_a - pi) simplifies to pi_i (r_i - J)."""
    p = softmax(theta)
    J = expected_return(theta, rewards)
    return [p[i] * (rewards[i] - J) for i in range(len(theta))]

def finite_difference(theta, rewards, h=1e-6):
    g = []
    for i in range(len(theta)):
        up = list(theta); up[i] += h
        dn = list(theta); dn[i] -= h
        g.append((expected_return(up, rewards) - expected_return(dn, rewards)) / (2 * h))
    return g

def estimator_moments(theta, rewards, baseline=0.0):
    """Exact mean vector and total variance (trace of covariance) of the
    single-sample estimator g = (r_a - baseline) * grad log pi(a), a ~ pi."""
    p = softmax(theta)
    n = len(theta)
    mean = [0.0] * n
    second = 0.0
    for a in range(n):
        g = [(rewards[a] - baseline) * x for x in grad_log_prob(theta, a)]
        for i in range(n):
            mean[i] += p[a] * g[i]
        second += p[a] * sum(x * x for x in g)
    return mean, second - sum(m * m for m in mean)

def reinforce(theta, rewards, steps, alpha, baseline_fn, rng):
    theta = list(theta)
    for _ in range(steps):
        p = softmax(theta)
        a = rng.choices(range(len(theta)), weights=p)[0]
        g = grad_log_prob(theta, a)
        adv = rewards[a] - baseline_fn(theta)
        theta = [t + alpha * adv * x for t, x in zip(theta, g)]
    return theta

if __name__ == "__main__":
    th, rw = [0.0, 0.0], [1.0, 3.0]
    print("pi", softmax(th), "J", expected_return(th, rw))
    print("exact grad", exact_gradient(th, rw))
    print("finite diff", [round(x, 6) for x in finite_difference(th, rw)])
    for b in (0.0, 2.0):
        m, v = estimator_moments(th, rw, b)
        print("baseline", b, "mean", m, "total variance", round(v, 6))
    th2, rw2 = [0.5, 0.0, -0.5], [0.0, 1.0, 2.0]
    for b in (0.0, expected_return(th2, rw2)):
        m, v = estimator_moments(th2, rw2, b)
        print("3-action baseline", round(b, 4), "mean", [round(x, 4) for x in m], "variance", round(v, 4))
    out = reinforce([0.0, 0.0], rw, 2000, 0.05, lambda t: expected_return(t, rw), random.Random(0))
    print("after REINFORCE with baseline, pi =", [round(x, 3) for x in softmax(out)])
    assert all(abs(a - b) < 1e-6 for a, b in zip(exact_gradient(th, rw), finite_difference(th, rw)))
    assert softmax(out)[1] > 0.9
    print("self-test passed")
```

from torch.distributions import Categorical

theta = torch.tensor([0.7, -0.2, 0.1], requires_grad=True)

pi = torch.softmax(theta, 0)

def sample_grads(b, n=20000, seed=0):

def run(seed, use_baseline, steps=100, lr=0.02):

    th = torch.zeros(2, requires_grad=True)
    rew = torch.tensor([11.0, 13.0])
    opt = torch.optim.SGD([th], lr=lr)
    for _ in range(steps):
        dist = Categorical(logits=th)
        a = dist.sample()

        loss = -(rew[a] - b) * dist.log_prob(a)                    # minimise the negative: ascent on J
        opt.zero_grad(); loss.backward(); opt.step()
    return torch.softmax(th, 0)[1].item()

for use_b in (False, True):

## Verification

- **Finite differences**: the analytic gradient and the central difference should agree to about $10^{-6}$ at $h=10^{-6}$. A disagreement of order one means a sign or indexing bug.
- **Sum to zero**: the gradient over softmax logits must sum to zero.
- **Unbiasedness**: average many single-sample estimates and compare with the exact gradient; the standard error shrinks like $1/\sqrt N$.
- **Boundary**: equal rewards must give a zero gradient; a saturated policy must give a near-zero gradient.
- **Learning curve**: with a positive learning rate the exact $J$ must increase on a small enough step; if it drops, the update has the wrong sign.

## Failure modes

- **Gradient descent instead of ascent.** Subtracting the update makes the policy minimise return; $J$ falls from 2 toward 1 in the worked example.
- **Dropping the $-\pi$ term in the score.** Exercise 5 shows the update then has mean $(-0.75,-0.75)$ instead of $(-0.375,0.375)$, so learning stalls or follows the wrong direction.
- **Baseline that depends on the action.** It biases the gradient by $-\sum_ab(a)\nabla\pi(a)$.
- **Large positive rewards without a baseline.** In Exercise 4 the variance grows from 2 to 72 although the gradient is identical; seeds then disagree wildly.
- **Premature determinism.** Once $\pi$ is near one-hot the gradient is near zero and the policy can stay stuck on a bad action.
- **Overflow in softmax.** `exp(1000)` raises or returns infinity unless the maximum is subtracted first.

## Alternatives and trade-offs

| Method | Strength | Weakness |
|---|---|---|
| REINFORCE (Monte Carlo) | unbiased, simple | high variance, needs full episodes |
| REINFORCE with state baseline | same bias, lower variance | needs a value estimate |
| Actor-critic | online, lower variance | bias from the critic |
| Value-based (Q-learning) | sample efficient, off-policy | greedy actions, awkward for continuous control |
| Finite-difference / evolution strategies | no gradient of log-probs needed | needs many rollouts, scales poorly with parameters |

Use policy gradients when the action space is continuous or the optimal policy is stochastic; use value methods when the action set is small and data is expensive.

## Transfer and retention

For a robot arm the policy is a network producing the mean of a Gaussian over joint torques. The score is $(a-\mu)/\sigma^2$ times the Jacobian of $\mu$ with respect to the weights, and everything in this lesson (baseline, reward-to-go, variance) carries over unchanged. Retain: the log-derivative identity, the softmax score $e_a-\pi$, the fact that the expected score is zero, and the habit of checking an analytic gradient numerically before trusting a training run.

## Exercise answers

1. $\nabla\pi$ alone gives a sum we can only evaluate by enumerating actions; writing $\nabla\pi=\pi\nabla\log\pi$ turns the sum into an expectation under $\pi$, which is estimated by sampling the policy and multiplying the observed reward by the score. We never need the derivative of the reward with respect to the action.
2. $\pi=(0.25,0.75)$. The score for action 1 is $e_1-\pi=(-0.25,\,0.25)$.
3. $J=0.25\cdot2+0.75\cdot0=0.5$. Gradient $=(0.25\cdot1.5,\;0.75\cdot(-0.5))=(0.375,-0.375)$: logit 0 rises (action 0 pays more than average) and logit 1 falls.
4. The exact gradient is unchanged, $(-0.5,0.5)$, because shifting rewards by $c$ changes it by $c\cdot\sum_a\nabla\pi(a)=0$. Samples are $11(0.5,-0.5)$ and $13(-0.5,0.5)$: second moment $0.5\cdot60.5+0.5\cdot84.5=72.5$, minus $0.5$ gives variance $72.0$, 36 times larger than 2.0.
5. The expected update is $\sum_a\pi_ar_ae_a=(0.25\cdot(-3),\,0.75\cdot(-1))=(-0.75,-0.75)$. Both logits go down equally, so the policy does not change. The true gradient is $\pi_i(R_i-J)$ with $J=-1.5$: $(-0.375,0.375)$. The missing term is $-r\pi$ (the $-\pi_i$ in the score).
6. With $p=0.5$ the expected steps $T$ satisfy $T_0=1+\tfrac12T_1+\tfrac12T_0$, $T_1=1+\tfrac12T_0+\tfrac12T_2$, $T_2=1+\tfrac12T_1$, giving $T_0=12$, $T_1=10$, $T_2=6$. With $p=1$ the robot moves right from $s_0$ to $s_1$, then "right" in $s_1$ moves left back to $s_0$, forever, so the expected steps are infinite; $p=0$ never leaves $s_0$. A numerical search gives the best $p\approx0.586$ with about 11.66 steps, so the best policy is stochastic because the states are aliased.
7. Use the average return of the batch (or a learned $V(s)$ that does not depend on the sampled action) as the baseline; compute it from other samples or the whole batch consistently. Avoid any baseline that is a function of the action taken at the step being weighted. Subtracting about 95 turns signals of size 5 into signals around 0 and reduces variance.
8. $\mathbb E[(R-b(a))\nabla\log\pi(a)]=\nabla J-\sum_a\pi(a)b(a)\nabla\log\pi(a)=\nabla J-\sum_ab(a)\nabla\pi(a)$. The sum is zero for constant $b$ (because $\sum\nabla\pi=0$) but not in general.
9. $\pi=(0.5114,0.2079,0.2807)$, $J=0.9096$, gradient $(-0.4652,\,0.0188,\,0.4464)$ (finite differences agree). Total variance: $b=0$: 1.2275; $b=J$: 0.3220; $b^*=1.2623$: 0.2453.
10. Expect the no-baseline run to have the larger spread. A seed-0..19 run gave mean $\pi_1\approx0.54$ with standard deviation $\approx0.37$ without baseline and mean $0.84$ with standard deviation $\approx0.02$ with the baseline. A good answer reports both numbers and notes that the baseline run is both faster and more consistent while estimating the same gradient.
