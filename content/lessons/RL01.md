## Vì sao học bài này?

Write a tiny decision process and compute values before training an agent. This lesson develops the core calculation before asking you to apply it in a new setting. Start with the diagnostic if you think you already know it; prior tool use is not evidence of understanding.

## Trực giác · Intuition

Reinforcement learning studies decisions that affect future data and reward. An MDP is a modeling language for that interaction. It is not a guarantee that your observation contains enough information: a single camera frame can hide velocity and make the observation non-Markov.

## Định nghĩa và suy luận · Theory & derivation

A discounted MDP contains states $\mathcal S$, actions $\mathcal A$, transition probabilities $P(s'|s,a)$, expected rewards $r(s,a)$, and discount $0\le\gamma<1$. A policy $\pi(a|s)$ selects actions; the environment transition selects the next state. The Markov assumption says the modeled state summarizes the relevant history for future transitions and rewards.

Return is $G_t=\sum_{k=0}^{\infty}\gamma^kr_{t+k+1}$. Splitting off the first reward gives $G_t=r_{t+1}+\gamma G_{t+1}$. Taking expectations under a fixed policy yields the Bellman expectation equation:
$$V^\pi(s)=\sum_a\pi(a|s)\sum_{s'}P(s'|s,a)[r(s,a,s')+\gamma V^\pi(s')].$$
A terminal state has zero future value under the declared episodic convention. Reward describes the objective, not the correct action. Optimizing a poorly designed reward can produce behavior that is numerically successful and practically undesirable.

## Ví dụ có lời giải · Worked example

Two steps give rewards 1 then 2, with γ=0.5 and termination. G₀=1+0.5×2=2. A state with a self-loop reward 1 forever has V=1+0.5V, so V=2. This is a future-return quantity, not its immediate reward of 1.

## Triển khai tham khảo · Reference implementation

Read the contract first. Predict the output before running the code locally. This reference is for studying; a submission copied from it is assisted practice, not independent evidence.

```python
rewards=[1.,2.]; gamma=.5
G=0.
for reward in reversed(rewards):
    G=reward+gamma*G
assert G == 2.
assert abs(1/(1-gamma)-2) < 1e-12
```

## Hiểu lầm thường gặp · Failure modes

Observations are not automatically states. A high training return can exploit a reward loophole. Truncating an episode for a time limit is not always equivalent to reaching a true terminal state.

## So sánh và lựa chọn · Alternatives

Dynamic programming uses a known model. Monte Carlo learns from complete sampled returns. Temporal-difference methods bootstrap from estimates and can learn before an episode ends. Begin with a tabular problem so estimation and control errors are visible.
