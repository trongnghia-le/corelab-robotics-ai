## Why this matters

Write a tiny decision process and compute values before training an agent. This lesson develops the core calculation before asking you to apply it in a new setting. Start with the diagnostic if you think you already know it; prior tool use is not evidence of understanding.

## Intuition

Reinforcement learning studies decisions that affect future data and reward. An MDP is a modeling language for that interaction. It is not a guarantee that your observation contains enough information: a single camera frame can hide velocity and make the observation non-Markov.

## Theory and derivation

A discounted MDP contains states $\mathcal S$, actions $\mathcal A$, transition probabilities $P(s'|s,a)$, rewards $r(s,a,s')$ (or their expectation $r(s,a)$), and discount $0\le\gamma<1$. A policy $\pi(a|s)$ selects actions; the environment transition selects the next state. The Markov assumption says the modeled state summarizes the relevant history for future transitions and rewards.

Return is $G_t=\sum_{k=0}^{\infty}\gamma^kr_{t+k+1}$. Splitting off the first reward gives $G_t=r_{t+1}+\gamma G_{t+1}$. Taking expectations under a fixed policy yields the Bellman expectation equation:
$$V^\pi(s)=\sum_a\pi(a|s)\sum_{s'}P(s'|s,a)[r(s,a,s')+\gamma V^\pi(s')].$$
A terminal state has zero future value under the declared episodic convention. Reward describes the objective, not the correct action. Optimizing a poorly designed reward can produce behavior that is numerically successful and practically undesirable.

## Worked example

### Return of a short episode and value of a self-loop

**Problem.** (a) An episode has two steps with rewards 1 then 2; the discount is $\gamma=0.5$ and the episode terminates after the second step. Find the return $G_0$. (b) A state has a self-loop that gives reward 1 at every step forever, with $\gamma=0.5$. Find its value $V$, and say whether $V$ equals its immediate reward.

**Solution.** The return is the discounted sum of future rewards, $G_0=r_1+\gamma r_2+\gamma^2r_3+\dots$, and the value is its expectation, which satisfies $V=r+\gamma V'$ (Bellman relation).

1. Write the return of the episode: $G_0=r_1+\gamma r_2$ (no later rewards because the episode terminates).
2. Substitute: $G_0=1+0.5\cdot2=1+1=2$.
3. For the self-loop, the next state is the same state, so $V'=V$ and $V=1+0.5V$.
4. Solve: $V-0.5V=1$, so $0.5V=1$ and $V=1/0.5=2$.
5. Compare with the immediate reward $1$: $V=2\ne1$.

**Check.** The infinite sum $1+0.5+0.25+\dots=1/(1-\gamma)=2$ gives the same $V$ (partial sum over 60 terms is $2.0$). Bound: a constant reward $r$ must give $V=r/(1-\gamma)$, so $V\ge r$ for $0<\gamma<1$.

**Takeaway.** Value is a future-return quantity: the self-loop state is worth 2 although its immediate reward is 1, because the discounted rewards keep arriving.

### Tests

```python
CORRIDOR = {
    0: {"L": [(0.8, 0, -1.0), (0.2, 0, -1.0)], "R": [(0.8, 1, -1.0), (0.2, 0, -1.0)]},
    1: {"L": [(0.8, 0, -1.0), (0.2, 1, -1.0)], "R": [(0.8, 2, -1.0), (0.2, 1, -1.0)]},
    2: {"L": [(0.8, 1, -1.0), (0.2, 2, -1.0)], "R": [(0.8, 3, -1.0), (0.2, 2, -1.0)]},
}
ALWAYS_R = {s: {"R": 1.0} for s in CORRIDOR}
ALWAYS_L = {s: {"L": 1.0} for s in CORRIDOR}
UNIFORM = {s: {"L": 0.5, "R": 0.5} for s in CORRIDOR}

assert abs(discounted_return([1.0, 2.0], 0.5) - 2.0) < 1e-12

assert abs(V[2] + 1 / 0.82) < 1e-8
assert abs(V[1] - (-1 + 0.72 * V[2]) / 0.82) < 1e-8
assert abs(V[0] - (-1 + 0.72 * V[1]) / 0.82) < 1e-8
# edge: gamma = 0 gives the expected immediate reward; a loop that never ends is bounded
assert all(abs(v + 1.0) < 1e-12 for v in policy_evaluation(CORRIDOR, UNIFORM, 0.0).values())
assert all(abs(v + 10.0) < 1e-6 for v in policy_evaluation(CORRIDOR, ALWAYS_L, 0.9).values())
# property 1: Bellman residual is ~0 for any policy
Vu = policy_evaluation(CORRIDOR, UNIFORM, 0.9)
for s in CORRIDOR:
    rhs = sum(pa * q_value(CORRIDOR, Vu, s, a, 0.9) for a, pa in UNIFORM[s].items())
    assert abs(Vu[s] - rhs) < 1e-8

assert greedy_policy(CORRIDOR, Vu, 0.9) == ALWAYS_R

mc = mc_value(CORRIDOR, ALWAYS_R, 0, 0.9, 20000, seed=0)
assert abs(mc - V[0]) < 0.05
print("V(0) always-R exact %.4f, Monte Carlo %.3f; uniform %.3f; always-L %.1f" %
```

### Library track

Redo the lab with NumPy and Gymnasium (`pip install numpy gymnasium`). Append this to `mdp_lab.py` after the tests (it reuses `CORRIDOR`, `ALWAYS_R` and `policy_evaluation`). Part 1 solves $V=(I-\gamma P_\pi)^{-1}r_\pi$ directly and must match your iterative evaluation. Part 2 wraps the corridor in a `gymnasium.Env`, uses the standard `TimeLimit` wrapper (which reports `truncated`, not `terminated`) and checks that the Monte Carlo mean lies within four standard errors of the exact value.

```python
import numpy as np
import gymnasium as gym
from gymnasium import spaces

def exact_numpy(mdp, policy, gamma):
    states = list(mdp)
    idx = {s: i for i, s in enumerate(states)}
    P = np.zeros((len(states), len(states)))
    r = np.zeros(len(states))
    for s in states:
        for a, pa in policy[s].items():
            for p, s2, rew in mdp[s][a]:
                r[idx[s]] += pa * p * rew
                if s2 in idx:                    # terminal states have no column
                    P[idx[s], idx[s2]] += pa * p
    return dict(zip(states, np.linalg.solve(np.eye(len(states)) - gamma * P, r)))

V_np = exact_numpy(CORRIDOR, ALWAYS_R, 0.9)
V_lab = policy_evaluation(CORRIDOR, ALWAYS_R, 0.9)
assert all(abs(V_np[s] - V_lab[s]) < 1e-8 for s in CORRIDOR)

class Corridor(gym.Env):
    def __init__(self):
        self.observation_space = spaces.Discrete(3)
        self.action_space = spaces.Discrete(2)       # 0 = L, 1 = R
    def reset(self, *, seed=None, options=None):
        super().reset(seed=seed)
        self.s = 0
        return self.s, {}
    def step(self, action):
        if self.np_random.random() < 0.8:            # the move succeeds
            self.s += 1 if action == 1 else -1
        self.s = max(self.s, 0)
        terminated = self.s == 3                      # true terminal state
        return min(self.s, 2), -1.0, terminated, False, {}

env = gym.wrappers.TimeLimit(Corridor(), max_episode_steps=200)
rets = []
for ep in range(5000):
    obs, _ = env.reset(seed=ep)
    G, disc, done = 0.0, 1.0, False
    while not done:
        obs, rew, terminated, truncated, _ = env.step(1)   # always R
        G += disc * rew
        disc *= 0.9
        done = terminated or truncated
    rets.append(G)
se = np.std(rets) / np.sqrt(len(rets))
print("numpy exact %.4f | lab %.4f | gymnasium MC %.3f +- %.3f" % (V_np[0], V_lab[0], np.mean(rets), se))
assert abs(np.mean(rets) - V_np[0]) < 4 * se
```

Expected output (last line; the Monte Carlo digits depend on the library version): `numpy exact -3.2305 | lab -3.2305 | gymnasium MC -3.241 +- 0.009`. Extension: add a `TimeLimit` of 5 steps and bootstrap from $V(s')$ when `truncated` is true but not when `terminated` is true.

## Failure modes

Observations are not automatically states. A high training return can exploit a reward loophole. Truncating an episode for a time limit is not always equivalent to reaching a true terminal state.

## Alternatives and trade-offs

Dynamic programming uses a known model. Monte Carlo learns from complete sampled returns. Temporal-difference methods bootstrap from estimates and can learn before an episode ends. Begin with a tabular problem so estimation and control errors are visible.

## Exercise answers

1. Directly: $2+0.9\cdot0+0.81\cdot3+0.729\cdot1=2+2.43+0.729=5.159$. Backwards: $G_3=1$, $G_2=3+0.9=3.9$, $G_1=0+0.9\cdot3.9=3.51$, $G_0=2+0.9\cdot3.51=5.159$. Same.
2. $V=2/(1-\gamma)$: $20$ for $\gamma=0.9$ and $200$ for $0.99$. The effective horizon is about $1/(1-\gamma)$ steps (10 and 100): rewards much further away than that are almost ignored.
3. A single image gives position but not velocity, so two balls with the same image position and different velocities need different actions: the observation is not Markov. A better state is $(x,y,\dot x,\dot y)$ (or position plus velocity estimate). Stacking two frames lets the network infer velocity, so it helps, at the cost of a larger input; a recurrent policy is the alternative.
4. $V_h=2+0.9(0.7V_h+0.3V_l)$ and $V_l=0+0.9V_h$. Substitute: $V_h=2+0.63V_h+0.27\cdot0.9V_h=2+0.873V_h$, so $V_h=2/0.127=15.75$ and $V_l=14.17$.
5. $V(2)=-1+0.9(0.2V(2)+0.8\cdot0)\Rightarrow V(2)(1-0.18)=-1\Rightarrow V(2)=-1.2195$. $V(1)(0.82)=-1+0.72V(2)=-1.878\Rightarrow V(1)=-2.290$. $V(0)(0.82)=-1+0.72V(1)=-2.649\Rightarrow V(0)=-3.231$. Starting at the cell next to the terminal state is convenient because $V$(terminal)$=0$ is known; each cell then depends only on the one before it.
6. The loop runs forward, so the update discounts the earliest rewards instead of the later ones: $G=1$, then $0.5\cdot1+2=2.5$. Iterate in reverse, `for r in reversed(rewards)`: $G=2$, then $G=1+0.5\cdot2=2.0$.
7. True value of a state just before step 100: $1/(1-0.99)=100$ (the patrol continues). If the cut-off is treated as terminal the value near the limit is only about the few rewards left, e.g. 1 at step 99: an error of nearly 100, so the agent learns that states close to the time limit are bad and its behaviour depends on the clock. Fix: treat time-limit truncation as non-terminal when bootstrapping (use $V(s')$), or include the remaining time in the state.
8. $G_t=r_{t+1}+\gamma r_{t+2}+\gamma^2r_{t+3}+\dots=r_{t+1}+\gamma(r_{t+2}+\gamma r_{t+3}+\dots)=r_{t+1}+\gamma G_{t+1}$. Geometric series: infinite $c/(1-\gamma)$, finite $c(1-\gamma^n)/(1-\gamma)$. For $c=1,\gamma=0.95,n=50$: $(1-0.95^{50})/0.05=(1-0.0769)/0.05=18.46$.
9. Examples: cleaning the same tile, dumping dirt and re-cleaning it (infinite loop of reward); cleaning only the easy tiles near the dock and ignoring the rest; pushing the dirt around so the sensor counts it as clean. Better: reward the net change in a dirt map (final dirtiness reduction), subtract a penalty for re-dirtying, add a time/energy cost, and evaluate with held-out metrics (area actually clean at the end). The reward says *what* is wanted, not *how*.
10. $0.9^{50}=0.0052$, $0.99^{50}=0.605$, $0.999^{50}=0.951$. With $\gamma=0.9$ the delivery reward is almost invisible. $\gamma=0.99$ ($\approx1/(1-\gamma)=100$ steps = 2 s) is a good choice. Too large a $\gamma$ (0.999) makes value estimates large and noisy, slows learning and makes the algorithm more sensitive to errors.
11. 'Always L' never reaches the goal: every step costs $-1$ forever, so $V=-1/(1-0.9)=-10$ everywhere. Uniform random: $-6.75$. The greedy improvement uses $q(s,a)=\sum_{s'}p\,(r+\gamma V(s'))$ and picks R in every cell (moving toward the goal raises the value), so the new policy is 'always R'.
12. Error falls like $1/\sqrt n$ (standard error of a mean). The return of one episode from cell 0 has standard deviation about $0.64$, so the standard error is $\approx0.20,0.064,0.020,0.0064$ for $n=10,100,1000,10000$ (single runs scatter around these values; they depend on the seed). With a horizon that is too short the return of long episodes is cut and the estimate is biased (always too high here, since remaining rewards are negative); the bias does not vanish with more episodes, whereas the variance does.
