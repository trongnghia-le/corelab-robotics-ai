## Why this matters

A robot team rarely has the budget to collect and label millions of images. A vision foundation model offers a shortcut: a network pretrained on a very large, broad dataset that can be used for a new task by writing a text prompt, giving a point or box, or fitting a small head on frozen features. That is powerful and also dangerous, because the first demo usually works. What matters for a robot is how the model behaves on your cameras, objects, lighting and rare classes, and how sure you can be from a test set of a few dozen images. This lesson covers what pretraining scale does, how prompting works mechanically, and how to evaluate transfer without fooling yourself.

## Intuition

Pretraining on a huge, diverse corpus (hundreds of millions of image-text pairs for CLIP, a curated 142 million images for DINOv2, over a billion masks for SAM) gives features that are useful in many domains because they have seen many appearances of many things. Three usage modes follow.

- **Zero-shot with text**: embed the image and a text prompt per class, pick the class whose text embedding is most similar.
- **Promptable models**: give a geometric prompt (point, box) and the model returns a mask; the prompt specifies *which* object, not *what* class.
- **Frozen features plus a small head**: the probe approach of V14, now on a stronger encoder.

Scale makes the average case better. It does not remove the need to measure: the pretraining distribution is not your robot's distribution, rare or novel objects may be missing, and a prompt's wording can change the answer.

## Theory and derivation

### Zero-shot classification

Given an image embedding $z$ and, for each class $c$, a text embedding $t_c$ (both L2-normalised), the model scores
$$p(c\mid z)=\frac{\exp(\cos(z,t_c)/\tau)}{\sum_{c'}\exp(\cos(z,t_{c'})/\tau)} .$$
The temperature $\tau$ (CLIP learns a small value around 0.01) sets how sharply the softmax separates classes; it affects confidence but not the arg-max. The class set is whatever you put in the prompts, so adding or removing a class changes every probability, and "none of the above" is not available unless you add it.

### Prompt sensitivity and ensembles

Text embeddings of "a photo of a mug" and "mug" differ, so predictions can differ. A **prompt ensemble** averages the unit-normalised text embeddings of several templates for one class and re-normalises, which reduces variance from any single wording. The CLIP paper reports gains from templates such as "a photo of a {label}." and from ensembling. Prompts are hyperparameters: choosing them by looking at the test set is leakage.

### Scale and transfer

Empirically, accuracy on many downstream tasks grows smoothly with pretraining data, model size and compute, but with diminishing returns and very uneven effects per task. What scale cannot guarantee: coverage of your objects, robustness to your sensor (thermal, depth, fisheye), or calibrated confidence.

### Transfer evaluation

1. Define the **held-out distribution**: your robot's images, never used for choosing prompts or heads.
2. Pick **baselines**: majority class, a small supervised model trained on your own labels, and an untrained-encoder probe.
3. Report **per-class recall** and macro accuracy, not just accuracy. With 90 percent of images in one class, accuracy rewards ignoring the rare class.
4. Report an **interval**. For $k$ successes in $n$ trials the Wilson score interval is
$$\frac{\hat p+\frac{z^2}{2n}\pm z\sqrt{\frac{\hat p(1-\hat p)}{n}+\frac{z^2}{4n^2}}}{1+z^2/n},$$
with $z=1.96$ for 95 percent. For a normal approximation, the test-set size for half-width $h$ near $p$ is $n\approx z^2p(1-p)/h^2$: about 385 images for $\pm5$ points at $p=0.5$.

## Worked example

Image embedding $z=(1,0.3)$. Two classes, each with two prompt embeddings: mug $\{(0.6,0.8),(1,0)\}$, can $\{(0.9,0.5),(0.1,1)\}$. Use $\tau=0.1$.

1. Prompt A only: $\cos(z,\text{mug}_A)=0.8046$, $\cos(z,\text{can}_A)=0.9768$. Logits $8.046,\ 9.768$. Softmax: $p(\text{can})=1/(1+e^{-1.722})=0.848$. Prediction: can.
2. Prompt B only: $\cos(z,\text{mug}_B)=0.9578$, $\cos(z,\text{can}_B)=0.3812$. Logits $9.578,\ 3.812$. $p(\text{mug})=0.997$. Prediction: mug.
3. Ensemble: normalise each prompt, average and re-normalise. Mug becomes $(0.8944,0.4472)$, can becomes $(0.5494,0.8355)$. Cosines $0.9852$ and $0.7663$; logits $9.852,\ 7.663$; $p(\text{mug})=1/(1+e^{-2.189})=0.899$. Prediction: mug.

The same image gets two different labels from two reasonable prompts. If the true label is mug, the ensemble is right here, but a single example proves nothing: you must compare prompt sets on a validation split.

**Interval.** 34 of 40 correct gives $\hat p=0.85$ and a 95 percent Wilson interval $[0.709,\,0.929]$: the real accuracy could be 71 percent. With 340 of 400 the interval shrinks to $[0.812,\,0.882]$.

## Reference implementation

Hand-sized embeddings stand in for model outputs so every number can be checked by hand.

```python
import math

def dot(a, b): return sum(x*y for x, y in zip(a, b))
def norm(a): return math.sqrt(dot(a, a))
def unit(a):
    n = norm(a)
    return [x/n for x in a]
def cosine(a, b): return dot(a, b)/(norm(a)*norm(b))

def softmax(xs):
    m = max(xs)
    e = [math.exp(x - m) for x in xs]
    s = sum(e)
    return [v/s for v in e]

def zero_shot(img, class_embs, tau=0.01):
    """CLIP-style: logits = cosine(image, class text embedding)/tau. Returns (best class, probabilities)."""
    names = list(class_embs)
    probs = softmax([cosine(img, class_embs[c])/tau for c in names])
    best = max(range(len(names)), key=lambda i: probs[i])
    return names[best], dict(zip(names, probs))

def prompt_ensemble(embs):
    """Average the unit-normalised text embeddings of several prompts for one class."""
    d = len(embs[0])
    us = [unit(e) for e in embs]
    return unit([sum(u[i] for u in us)/len(us) for i in range(d)])

def accuracy(pred, true):
    return sum(p == t for p, t in zip(pred, true))/len(true)

def macro_accuracy(pred, true):
    """Mean of per-class recalls: every class counts equally, however rare."""
    classes = sorted(set(true))
    rec = []
    for c in classes:
        idx = [i for i, t in enumerate(true) if t == c]
        rec.append(sum(pred[i] == c for i in idx)/len(idx))
    return sum(rec)/len(rec)

def wilson_interval(k, n, z=1.96):
    """Wilson score interval for a proportion k/n (better than +-z*sqrt(p(1-p)/n) when n is small)."""
    p = k/n
    d = 1 + z*z/n
    centre = (p + z*z/(2*n))/d
    half = z*math.sqrt(p*(1-p)/n + z*z/(4*n*n))/d
    return max(0.0, centre - half), min(1.0, centre + half)

if __name__ == "__main__":
    img = [1.0, 0.3]
    # two prompts per class; each single prompt is a noisy view of the class direction
    mug_a, mug_b = [0.6, 0.8], [1.0, 0.0]
    can_a, can_b = [0.9, 0.5], [0.1, 1.0]
    for name, classes in (("prompt A only", {"mug": mug_a, "can": can_a}),
                          ("prompt B only", {"mug": mug_b, "can": can_b}),
                          ("ensemble", {"mug": prompt_ensemble([mug_a, mug_b]), "can": prompt_ensemble([can_a, can_b])})):
        label, probs = zero_shot(img, classes, tau=0.1)
        print("%-14s -> %s  %s" % (name, label, {k: round(v, 3) for k, v in probs.items()}))
    lo, hi = wilson_interval(34, 40)
    print("34/40 correct: Wilson 95%% interval [%.3f, %.3f]" % (lo, hi))
    pred = ["a"]*9 + ["b"]*1 + ["a"]*1
    true = ["a"]*9 + ["a"]*1 + ["b"]*1
    assert abs(accuracy(pred, true) - 9/11) < 1e-12 and abs(macro_accuracy(pred, true) - 0.45) < 1e-12
    assert abs(wilson_interval(34, 40)[0] - 0.7093) < 1e-3
    print("self-test passed")
```

## Verification

- Choose prompts and heads on a validation split; touch the held-out set once.
- Check that $\tau$ changes confidences, not the arg-max, then check calibration separately.
- Always list the baselines next to the model; a lower interval bound below the majority-class rate means no evidence of learning.
- Re-run with a fresh sample of images from the same robot to see run-to-run spread.

## Failure modes

| Mistake | Effect |
|---|---|
| Choosing prompts on the test set (Exercise 6) | Optimistic accuracy |
| Reporting accuracy on a 90/10 split | A constant predictor scores 90 percent |
| Reading 34/40 as exactly 85 percent | True value may be 71 to 93 percent |
| Adding a class and keeping old thresholds | All probabilities shift because softmax is over the list |
| Assuming zero-shot confidence is calibrated | Confident wrong answers at low temperature |
| Sensor mismatch (fisheye, infrared) | Large unexplained drop from benchmark numbers |

## Alternatives and trade-offs

- **Zero-shot prompts**: no labels needed; sensitive to wording and class lists.
- **Frozen features plus a small head**: needs a few labels, robust and cheap; limited by feature coverage.
- **Fine-tuning**: best accuracy with enough data; costs compute and risks forgetting.
- **Task-specific small model**: smaller and faster on the robot; needs labelled data and may be less robust.
- **Promptable segmentation plus a classifier**: separates "where" from "what"; two stages to validate.

## Transfer and retention

The evaluation habit (held-out distribution, baselines, intervals, per-class numbers) applies to every learned component, including policies trained in simulation. Foundation features feed advanced perception (V20) and 3D representations (V19). Retrieval prompts: What does temperature change? Why is a prompt a hyperparameter? How many test images give $\pm5$ points?

## Exercise answers

1. Zero-shot compares the image with text for each class you supply, so the class list defines the problem. Adding "other" with a vague prompt only gives the softmax one more competitor; it will take probability from real classes without being a meaningful "none of the above".
2. The arg-max is unchanged (logits keep their order). At $\tau=1$ the logits are cosines in $[-1,1]$, so the probabilities become close to uniform, far from 0.62/0.30/0.08 shapes at $\tau=0.01$.
3. Accuracy $=90/100=0.90$; recall A $=1$, recall B $=0$, macro $=0.5$.
4. A point lies in several nested objects (handle, mug, table). The prompt is ambiguous, so the model returns one valid mask. Resolve by adding a second point or box, using the multi-mask outputs, or filtering by a class or size prior.
5. $n=1.96^2\cdot0.8\cdot0.2/0.03^2=683$ (682.95, round up).
6. Prompts are chosen using the test images, so the test set is no longer held out; the reported accuracy is the maximum over several candidates and is optimistically biased. Use `val_images` to choose and report `test_images` once.
7. $0.86$ at $n=50$: interval about $[0.74,0.93]$; $0.84$: about $[0.72,0.92]$. The intervals overlap almost entirely, so no claim. Rule of thumb: differences of a few points need hundreds of images (or paired comparisons on the same images).
8. Hypotheses: (a) lens distortion shifts the geometry, test by undistorting; (b) the object set is different, test by checking per-class recall; (c) lighting or colour distribution differs, test by augmenting or colour-matching a benchmark subset. A good answer pairs each with a controlled experiment.
9. Dividing logits by $\tau$ does not change their order, so the arg-max is the same. Small $\tau$ stretches the gaps, driving the top probability to near 1 even for an image that is nearly equidistant, so confidence is high where accuracy is not; calibrate $\tau$ on validation data.
10. A good answer names classes and the rare class, a warehouse held-out set with different shelves or lighting, majority-class and trained-small-model baselines, macro accuracy and per-class recall with Wilson intervals, and a rejection rule such as "lower bound of rare-class recall below 0.6".
