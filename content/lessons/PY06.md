## Why this matters

Neural networks, differentiable simulators, learned controllers and even classical calibration problems all reduce to the same loop: compute a scalar loss, obtain its gradient with respect to many parameters, and move the parameters downhill. Writing gradients by hand does not scale beyond a neuron; **automatic differentiation** (autograd) does it exactly for any composition of differentiable operations. PyTorch exposes this through tensors that remember how they were computed. The risk is treating `loss.backward()` as magic: most real training bugs (gradients accumulating, a tensor detached from the graph, an in-place edit, the wrong dtype, a learning rate beyond the stability limit) come from not knowing what autograd actually does. This lesson builds that understanding on a neuron small enough to differentiate by hand.

## Intuition

A **tensor** is an $n$-dimensional array, like a NumPy array, with extra metadata: dtype (float32 by default), device (CPU or GPU) and, if `requires_grad=True`, a record of the operations that produced it. Every operation on such tensors adds a node to a **graph**. The forward pass computes values and keeps what the backward pass will need. `loss.backward()` walks the graph from the loss to the leaves, applying the chain rule at each node, and **adds** the result to each leaf's `.grad`. The optimizer then reads `.grad` and updates the parameters.

Think of a robot that must learn how hard to push its wheel for a given command. The loss is the mean squared gap between the speeds the model predicts and the speeds an encoder reports; the parameter is the gain by which the command is multiplied. A person would nudge the gain up when the predictions are too low and down when they are too high, by an amount that depends on how wrong the prediction is and on how much a nudge changes it. The gradient is exactly that recipe, one number per parameter, and the job of autograd is to compute all of those numbers at once without anyone writing the algebra.

Predict before you compute. Let $L=w^2$ with $w=5$ stored in a tensor with `requires_grad=True`. `L.backward()` is called once; then $L$ is built again and `backward()` is called a second time without touching `w.grad`. What is `w.grad` afterwards: 10, 20, or something else? Decide before reading on; the answer follows the figure.

![A computation graph for a sigmoid neuron: forward arrows with values z=0.1, y=0.52498, L=0.11282, and dashed backward arrows with gradients -0.47502, 0.24938, -0.11846 and the weight gradient](/lesson-figures/PY06.svg)

*Forward values (blue) are stored; backward gradients (orange) multiply local derivatives along the graph. The numbers are the worked example below.*

The answer is 20: each call computes $2w=10$ and *adds* it to `.grad`. Accumulation is deliberate (it lets the gradients of several mini-batches be summed before one update) and a classic bug when it is not intended. Two more wrong intuitions are worth removing early. "Autograd approximates derivatives by finite differences": it does not; it applies the chain rule to the recorded graph, so results are exact up to rounding. "A gradient belongs to a tensor": it belongs to a *computation*; cut the graph with `detach()` or change an operation and the same tensor receives a different gradient. Finally, a loss that decreases is not proof of a correct gradient, because a wrong gradient can still point downhill for a while; the lesson therefore keeps comparing autograd with hand derivations and finite differences.

## Theory and derivation

### Tensors

`torch.tensor([[1., 2.], [3., 4.]])` has `shape == (2, 2)` and `dtype == torch.float32`; integers give `int64`, and `mean()` on an integer tensor raises an error until you call `.float()`. Broadcasting follows NumPy: shapes are aligned from the right, and a dimension of size 1 stretches. `x.sum(0)` removes axis 0; `keepdim=True` keeps it as size 1. Basic slicing returns **views** sharing storage; `clone()` copies. `float32` has about 7 decimal digits: `torch.tensor(0.1).item()` is `0.10000000149011612`. Use `dtype=torch.float64` when you verify gradients (M11).

**Example.** Four waypoints (metres) and a target point; broadcasting, a view, a copy and two dtypes:

```python
import torch

p = torch.tensor([[0., 0.], [3., 4.], [6., 8.], [1., 1.]])   # four waypoints (x, y) in metres
c = torch.tensor([3., 0.])                                     # a target point
d = (p - c).norm(dim=1)                                        # (4,2) - (2,) broadcasts to (4,2)
print(p.shape, (p - c).shape, d)
v = p[1:3]                                                     # a view: shares storage
v[0, 0] = 99.
print(p[1, 0].item())
k = p[2:4].clone()                                             # a copy: independent
k[0, 0] = 7.
print(p[2, 0].item(), torch.tensor([1, 2, 3]).dtype, torch.tensor(0.1).dtype)
```

Output:

```text
torch.Size([4, 2]) torch.Size([4, 2]) tensor([3.0000, 4.0000, 8.5440, 2.2361])
99.0
6.0 torch.int64 torch.float32
```

The shape $(4,2)$ minus the shape $(2,)$ is aligned from the right, so the target is subtracted from every row, and the distances are $3,\,4,\,\sqrt{9+64}=8.544,\,\sqrt5=2.2361$ m. Editing the view `v` changed `p[1, 0]` to 99.0 because both share storage, while editing the clone left `p[2, 0]` at 6.0. The integer list gave `int64`, the float literal `float32`.

### Reverse-mode autodiff

For a scalar loss $L=f(\theta)$ built from elementary operations $v_k=g_k(v_{\text{parents}})$, reverse mode computes the **adjoints** $\bar v_k=\partial L/\partial v_k$ from the output backward: $\bar L=1$, and for each node $\bar v_j\mathrel{+}=\bar v_k\,\partial g_k/\partial v_j$. One backward pass costs about as much as one forward pass and returns the gradient with respect to *all* parameters, whereas finite differences need one extra forward pass per parameter.

**Example.** A two-input function $f(a,b)=ab+e^{b}$ at $a=1.5$, $b=-0.5$, with the adjoint of the intermediate node $u=ab$ kept by `retain_grad()`:

```python
import torch

a = torch.tensor(1.5, requires_grad=True)
b = torch.tensor(-0.5, requires_grad=True)
u = a * b
u.retain_grad()                      # keep the adjoint of the intermediate node
f = u + torch.exp(b)
print(f.item(), f.grad_fn.name())
f.backward()
print(u.grad.item(), a.grad.item(), b.grad.item())
print(b.item(), (a + torch.exp(b)).item())   # hand results: df/da = b, df/db = a + e^b
```

Output:

```text
-0.14346933364868164 AddBackward0
1.0 -0.5 2.1065306663513184
-0.5 2.1065306663513184
```

The forward value is $f=-0.75+0.6065=-0.1435$ and the last operation is an addition (`AddBackward0`). Reverse mode starts with $\bar f=1$; the addition passes 1 to $u$ (`u.grad = 1.0`) and 1 to the $e^b$ branch. Then $\bar a=\bar u\,b=-0.5$ and $\bar b=\bar u\,a+\bar f\,e^{b}=1.5+0.6065=2.1065$: $b$ feeds two operations, so its two contributions are added, which is the "$\mathrel{+}=$" of the rule above.

### A neuron by hand

For $z=w^Tx+b$, $y=\sigma(z)=1/(1+e^{-z})$ and $L=\tfrac12(y-t)^2$:

$$\frac{\partial L}{\partial y}=y-t,\quad\frac{\partial y}{\partial z}=y(1-y),\quad\frac{\partial L}{\partial z}=(y-t)\,y(1-y),\quad\frac{\partial L}{\partial w}=\frac{\partial L}{\partial z}\,x,\quad\frac{\partial L}{\partial b}=\frac{\partial L}{\partial z}.$$

**Example.** A different neuron: $x=(2,-1)$, $w=(0.3,0.8)$, $b=-0.2$ and target $t=0$, in float64. By hand $z=0.6-0.8-0.2=-0.4$, $y=\sigma(-0.4)=0.401312$, $L=\tfrac12y^2=0.080526$ and $\partial L/\partial z=(y-t)\,y(1-y)=0.401312\cdot0.598688\cdot0.401312=0.09642$. Autograd and the formulas side by side:

```python
import torch

x = torch.tensor([2.0, -1.0], dtype=torch.float64)
w = torch.tensor([0.3, 0.8], dtype=torch.float64, requires_grad=True)
b = torch.tensor(-0.2, dtype=torch.float64, requires_grad=True)
t = 0.0
z = w @ x + b
y = torch.sigmoid(z)
L = 0.5 * (y - t) ** 2
L.backward()
dz = (y - t) * y * (1 - y)                      # hand formula dL/dz
print(round(z.item(), 4), round(y.item(), 6), round(L.item(), 6), round(dz.item(), 6))
print(w.grad.numpy().round(6), round(b.grad.item(), 6), (dz * x).detach().numpy().round(6))
```

Output:

```text
-0.4 0.401312 0.080526 0.09642
[ 0.192839 -0.09642 ] 0.09642 [ 0.192839 -0.09642 ]
```

The first line is $z$, $y$, $L$ and $\partial L/\partial z$; the second shows `w.grad`, `b.grad` and the hand result $(\partial L/\partial z)\,x$, which agree: $\partial L/\partial w=(0.192839,-0.09642)$ and $\partial L/\partial b=0.09642$. The gradient of $w_2$ is negative because $x_2=-1$ flips the sign of $\partial L/\partial z$.

### Accumulation, no_grad, detach, in-place

- `.grad` **accumulates**: calling `backward()` twice without clearing adds the gradients. Hence `optimizer.zero_grad()` (or `p.grad = None`) before each backward.
- `with torch.no_grad():` disables graph recording (evaluation, manual updates). `t.detach()` returns a tensor that shares data but is cut from the graph: gradients do not flow through it.
- In-place operations (`add_`, `mul_`, `x[i] = ...`) on a tensor that the backward pass needs raise `RuntimeError: one of the variables needed for gradient computation has been modified by an inplace operation`.

**Example.** Accumulation, `detach` and an in-place edit, each with its numbers. $L=4w^2$ at $w=1.5$ has $\partial L/\partial w=8w=12$; for $z=(wx)\,w$ with $x=5$ the gradient is $2wx=15$, but with the first factor detached only the second factor counts and the gradient is the constant $wx=7.5$:

```python
import torch

w = torch.tensor(1.5, requires_grad=True)
for _ in range(2):
    (4 * w ** 2).backward()
    print(w.grad.item())             # accumulates: 12, then 24
w.grad = None                        # what zero_grad() does
x = torch.tensor(5.0)
(w * x * w).backward(); print(w.grad.item())              # 2*w*x = 15
w.grad = None
((w * x).detach() * w).backward(); print(w.grad.item())   # first factor frozen: 7.5
a = torch.ones(3, requires_grad=True)
c = a.sigmoid()
c.mul_(2)                            # edits the output that sigmoid's backward needs
try:
    c.sum().backward()
except RuntimeError as e:
    print(str(e).split(":")[0])
```

Output:

```text
12.0
24.0
15.0
7.5
one of the variables needed for gradient computation has been modified by an inplace operation
```

The first two lines show 12 then 24: the second `backward()` added another 12. After resetting, the full graph gives 15 and the detached one 7.5, half, because one of the two factors of $w$ no longer counts. The last line is the error raised when `mul_` rewrote the output of `sigmoid`, which its backward pass needs.

### The training loop and SGD

Gradient descent updates $\theta\leftarrow\theta-\eta\,\nabla L(\theta)$ with learning rate $\eta$. A step in PyTorch has a fixed order:

```
opt.zero_grad(); loss = loss_fn(model(x), y); loss.backward(); opt.step()
```

For a quadratic loss with Hessian eigenvalues up to $\lambda_{\max}$, the iteration is stable only if $\eta<2/\lambda_{\max}$; at $\eta=2/\lambda_{\max}$ it oscillates forever and above it diverges. Use `model.eval()` and `torch.no_grad()` for evaluation, and `torch.manual_seed` for reproducibility.

**Example.** A robot's wheel gain $k$ in $\text{speed}=k\cdot\text{command}$ learned by three SGD steps from commands $(1,2,3)$ and measured speeds $(2.1,3.9,6.2)$, with $\eta=0.05$ and the loss $\mathrm{mean}((kx-y)^2)$:

```python
import torch

x = torch.tensor([1.0, 2.0, 3.0])                 # commanded speeds
y = torch.tensor([2.1, 3.9, 6.2])                 # measured speeds
k = torch.tensor(0.0, requires_grad=True)         # gain to learn
opt = torch.optim.SGD([k], lr=0.05)
for step in range(3):
    opt.zero_grad()
    loss = ((k * x - y) ** 2).mean()
    loss.backward()
    g = k.grad.item()
    opt.step()
    print(step, round(loss.item(), 4), round(g, 4), round(k.item(), 4))
```

Output (step, loss, gradient, new gain):

```text
0 19.3533 -19.0 0.95
1 5.515 -10.1333 1.4567
2 1.5788 -5.4044 1.7269
```

Step 0: the loss is $(4.41+15.21+38.44)/3=19.3533$, the gradient $2\,\mathrm{mean}(x(kx-y))=-19.0$, and $k\leftarrow0-0.05\cdot(-19)=0.95$. The loss falls from 19.35 to 5.515 to 1.579 while $k$ approaches the least-squares gain $\sum xy/\sum x^2=28.5/14=2.0357$: the error shrinks by the factor $1-\eta\cdot2\,\mathrm{mean}(x^2)=1-0.05\cdot9.333=0.5333$ per step (1.0857, then 0.5790, then 0.3088).

### Forward mode, dual numbers and the cost of a Jacobian

Reverse mode is not the only way to differentiate a program. Write the computation as an evaluation trace $v_1,\dots,v_l$ of elementary operations (Baydin et al., *Automatic Differentiation in Machine Learning: a Survey*, §3). **Forward mode** attaches to every $v_i$ a tangent $\dot v_i=\partial v_i/\partial x_j$, seeded with $\dot x=e_j$, and applies the chain rule operation by operation, in lockstep with the forward pass. One pass therefore returns $J\dot x$, a Jacobian–vector product, which for $\dot x=e_j$ is column $j$ of the Jacobian (Baydin et al., §3.1). **Reverse mode** instead seeds the adjoint $\bar y=r$ and propagates backwards; one pass returns $J^{T}r$, a vector–Jacobian product, and with $r=e_i$ it gives row $i$ of $J$ (§3.2).

A neat way to see why forward mode "just works" is dual numbers $v+\dot v\,\varepsilon$ with $\varepsilon^2=0$ and $\varepsilon\neq0$. For any smooth $f$,

$$f(v+\dot v\,\varepsilon)=f(v)+f'(v)\,\dot v\,\varepsilon,$$

so that $(v+\dot v\varepsilon)(u+\dot u\varepsilon)=vu+(v\dot u+\dot v u)\varepsilon$ reproduces the product rule, and two applications of the identity give $f(g(v+\dot v\varepsilon))=f(g(v))+f'(g(v))\,g'(v)\,\dot v\,\varepsilon$, the chain rule (§3.1.1). Evaluating the program on $x+1\cdot\varepsilon$ and reading the $\varepsilon$-coefficient is the derivative. Nothing is approximated, so there is no step size and no truncation error, unlike finite differences.

**Cost.** If evaluating $f:\mathbb R^n\to\mathbb R^m$ costs $\mathrm{ops}(f)$, the full $m\times n$ Jacobian costs about $n\,c\,\mathrm{ops}(f)$ in forward mode (one pass per input) and $m\,c\,\mathrm{ops}(f)$ in reverse mode (one pass per output), with a constant $c<6$, typically 2 to 3 (§3.2, citing Griewank and Walther). A training loss has $m=1$ and $n$ in the millions, so reverse mode wins by a factor $n$. The price is memory: the reverse pass needs the intermediate values of the forward pass, so storage grows in proportion to the number of operations. This is why `torch.no_grad()` saves memory at evaluation time, and why activation checkpointing trades recomputation for storage. When $n\ll m$ (a few parameters, many outputs, for example calibrating three constants of a simulator that returns a million-point trajectory) forward mode is the cheaper choice.

**Example.** The map $f(x)=(x_0x_1,\ \sin x_0)$ at $x=(1.2,0.5)$ has the Jacobian $\begin{bmatrix}x_1&x_0\\\cos x_0&0\end{bmatrix}$. One forward-mode pass (`jvp`) with the seed $e_1$ returns a *column*, one reverse-mode pass (`vjp`) with the seed $e_2$ returns a *row*:

```python
import torch
from torch.func import jvp, vjp

f = lambda x: torch.stack([x[0] * x[1], torch.sin(x[0])])   # R^2 -> R^2
x = torch.tensor([1.2, 0.5])
_, col = jvp(f, (x,), (torch.tensor([1., 0.]),))            # one forward-mode pass: J e1
_, back = vjp(f, x)
row = back(torch.tensor([0., 1.]))[0]                       # one reverse-mode pass: e2^T J
print(col, row)
print(torch.autograd.functional.jacobian(f, x))
```

Output:

```text
tensor([0.5000, 0.3624]) tensor([0.3624, 0.0000])
tensor([[0.5000, 1.2000],
        [0.3624, 0.0000]])
```

The `jvp` result $(0.5,\,0.3624)$ is the first column of $J$ and the `vjp` result $(0.3624,\,0)$ is its second row, as the full Jacobian in the last lines confirms. Both modes need two passes for this $2\times2$ matrix; for a loss with $n=1{,}000$ parameters and $m=1$ output the counts are 1,000 forward passes against 1 reverse pass, and for a simulator with $n=3$ parameters and $m=500$ outputs they are 3 against 500.

![Left: the 2 by 2 Jacobian of the example with its first column filled by one forward pass and its second row by one reverse pass; right: bars for the number of passes needed for a full Jacobian in two settings](/lesson-figures/PY06-2.svg)

*Figure: forward mode fills the Jacobian one column per pass, reverse mode one row per pass. The cost of the full Jacobian is the smaller of the two counts times a small constant, so a scalar loss with many parameters is a job for reverse mode.*

### Gradient descent on a quadratic: the full stability and rate analysis

The lesson states that $\eta<2/\lambda_{\max}$ is needed. Here is the derivation, followed by what the best step size achieves. Take $f(\theta)=\tfrac12\theta^{T}H\theta$ with $H$ symmetric positive definite, eigenvalues $0<\lambda_{\min}=\lambda_1\le\dots\le\lambda_d=\lambda_{\max}$ and minimizer $0$. The update $\theta_{k+1}=\theta_k-\eta H\theta_k$ gives the error recursion $e_{k+1}=(I-\eta H)e_k$. In the eigenbasis of $H$ every component decouples,

$$e_k^{(i)}=(1-\eta\lambda_i)^k\,e_0^{(i)},$$

so the iteration converges for every start iff $|1-\eta\lambda_i|<1$ for all $i$, that is $0<\eta<2/\lambda_{\max}$. At $\eta=2/\lambda_{\max}$ the top component is multiplied by $-1$ forever (it oscillates), above it the component grows geometrically. The asymptotic rate is $\rho(\eta)=\max_i|1-\eta\lambda_i|=\max\{|1-\eta\lambda_{\min}|,|1-\eta\lambda_{\max}|\}$. The first term decreases in $\eta$ and the second increases once $\eta>1/\lambda_{\max}$, so $\rho$ is minimal where they cross, $1-\eta\lambda_{\min}=\eta\lambda_{\max}-1$:

$$\eta^\star=\frac{2}{\lambda_{\min}+\lambda_{\max}},\qquad\rho^\star=\frac{\kappa-1}{\kappa+1},\quad\kappa=\frac{\lambda_{\max}}{\lambda_{\min}}.$$

Reducing the error by a factor $\varepsilon$ takes $k\approx\ln(1/\varepsilon)/\ln\frac{\kappa+1}{\kappa-1}\approx\frac\kappa2\ln\frac1\varepsilon$ steps, so the cost is proportional to the condition number $\kappa$. This is the quantitative content of the exercise in Dive into Deep Learning §12.3.5 that asks for an objective on which gradient descent is "exceedingly slow": scale the coordinates very differently. For a general smooth loss the same analysis applies locally with $H$ the Hessian at the minimum, and globally a gradient that is $L$-Lipschitz guarantees $f(\theta-\eta\nabla f)\le f(\theta)-\eta(1-L\eta/2)\|\nabla f\|^2$, hence descent for $\eta<2/L$ (the Taylor expansion of Dive into Deep Learning §12.3.1–12.3.2 with the second-order remainder bounded by $L$). Newton's method replaces $\eta$ by $H^{-1}$ and solves a quadratic in one step (§12.3.3.1), but it trusts the quadratic model blindly: where the true curvature is tiny or negative the step is huge or goes uphill (Exercise 13).

**Example.** A diagonal Hessian with eigenvalues $\lambda=(0.5,\,8)$, start $\theta_0=(2,-1)$, 60 steps. The stability limit is $2/8=0.25$ and the best step is $\eta^\star=2/8.5=0.2353$ with $\rho^\star=(16-1)/17=0.8824$ ($\kappa=16$):

```python
import torch

H = torch.tensor([0.5, 8.0], dtype=torch.float64)          # eigenvalues of a diagonal Hessian
def run(eta, steps=60):
    th = torch.tensor([2.0, -1.0], dtype=torch.float64)
    for _ in range(steps):
        th = th - eta * H * th                             # gradient of 0.5*th^T H th is H*th
    return th.norm().item()
for eta in (0.2, 2 / 8.5, 0.25, 0.26):
    print(round(eta, 4), f"{run(eta):.3e}")
```

Output (step size, $\|\theta_{60}\|$):

```text
0.2 3.594e-03
0.2353 1.225e-03
0.25 1.000e+00
0.26 1.013e+02
```

At $\eta=0.2$ the slow direction has factor $|1-0.2\cdot0.5|=0.9$, so $\|\theta_{60}\|\approx2\cdot0.9^{60}=3.6\times10^{-3}$. The optimal step balances the two factors, $+0.8824$ and $-0.8824$, and gives $2.236\cdot0.8824^{60}=1.2\times10^{-3}$, only three times better than $\eta=0.2$: tuning $\eta$ cannot beat $\kappa$. At $\eta=0.25$ the stiff component is multiplied by exactly $-1$ and keeps its amplitude 1.000; at 0.26 it is multiplied by $-1.08$ and has grown to $1.08^{60}=101$.

### Softmax cross-entropy: gradient, Hessian and numerical stability

For logits $z\in\mathbb R^K$, probabilities $p=\mathrm{softmax}(z)$ and a one-hot label $y$, the loss is $\ell(z)=-\sum_ky_k\log p_k=-z_c+\log\sum_je^{z_j}$ where $c$ is the true class (Dive into Deep Learning §4.1). Differentiating, $\partial\ell/\partial z_k=-y_k+e^{z_k}/\sum_je^{z_j}$, that is

$$\nabla_z\ell=p-y,\qquad\nabla_z^2\ell=\mathrm{diag}(p)-pp^{T}.$$

The Hessian does not depend on the label. It is the covariance matrix of the one-hot vector of a class drawn from $p$, which is the content of the exercise in §4.1 relating the second derivative to the variance of the distribution. It is positive semi-definite, since $v^{T}(\mathrm{diag}(p)-pp^{T})v=\sum_kp_kv_k^2-(\sum_kp_kv_k)^2=\mathrm{Var}_p(v)\ge0$, and it annihilates $\mathbf 1$ because adding a constant to all logits changes nothing: the loss is convex but never strictly convex in $z$.

Numerically, $e^{z}$ overflows in `float32` once $z\gtrsim88.7$ and underflows to 0 for $z\lesssim-104$, producing `inf/inf` or `0/0` = `nan`. The log-sum-exp identity $\log\sum_je^{z_j}=m+\log\sum_je^{z_j-m}$ with $m=\max_jz_j$ is exact and keeps every exponent $\le0$, so the largest term is exactly 1. Library losses such as `torch.nn.functional.cross_entropy` take logits for this reason, and you should never apply `softmax` and then `log` yourself (Dive into Deep Learning §4.4, exercises).

**Example.** Four logits $z=(1.5,-0.5,3.0,0)$ with the true class at index 2, from `cross_entropy`, compared with $p-y$; then the naive and the max-subtracted softmax in `float32` for $z=(90,80,70)$:

```python
import torch

z = torch.tensor([1.5, -0.5, 3.0, 0.0], requires_grad=True)
loss = torch.nn.functional.cross_entropy(z[None], torch.tensor([2]))   # true class index 2
loss.backward()
p = torch.softmax(z.detach(), 0)
print(round(loss.item(), 4), z.grad.numpy().round(4), (p - torch.tensor([0., 0., 1., 0.])).numpy().round(4))
big = torch.tensor([90., 80., 70.])                                    # float32
naive = big.exp() / big.exp().sum()
m = big - big.max()
print(naive, m.exp() / m.exp().sum())
```

Output:

```text

tensor([nan, 0., 0.]) tensor([9.9995e-01, 4.5398e-05, 2.0611e-09])
```

The loss is $0.2648$ and `z.grad` equals $p-y=(0.1712,0.0232,-0.2326,0.0382)$, which sums to 0 as the null direction $\mathbf 1$ requires. In the naive version $e^{90}\approx1.2\times10^{39}$ exceeds the `float32` maximum $3.4\times10^{38}$ and becomes `inf`, so the first entry is $\mathrm{inf}/\mathrm{inf}=$ `nan`; after subtracting the maximum the result is $(0.99995,4.54\times10^{-5},2.06\times10^{-9})$.

## Worked example

Three cases for this lesson. All numbers were recomputed with PyTorch 2.15.0 (CPU) in float64 unless stated.

### Case 1: a sigmoid neuron by hand, by autograd and by finite differences

**Problem.** A neuron has $x=(1,2)$, $w=(0.5,-0.25)$, $b=0.1$, $z=w^Tx+b$, $y=\sigma(z)$, target $t=1$ and loss $L=\tfrac12(y-t)^2$. Compute $L$ and the gradients $\partial L/\partial w$, $\partial L/\partial b$ by hand, confirm them with autograd and a central finite difference, and take one SGD step with $\eta=0.5$.

**Solution.**
1. *Forward pass* (theory, "A neuron by hand"). $z=0.5\cdot1+(-0.25)\cdot2+0.1=0.1$; $y=\sigma(0.1)=0.524979$; $L=\tfrac12(0.524979-1)^2=\tfrac12(0.225645)=0.112822$.
2. *Backward pass.* $\partial L/\partial y=y-t=-0.475021$; $\sigma'(z)=y(1-y)=0.524979\cdot0.475021=0.249376$; chain rule: $\partial L/\partial z=-0.475021\cdot0.249376=-0.118459$.
3. *Parameter gradients.* $\partial L/\partial w=\partial L/\partial z\cdot x=-0.118459\cdot(1,2)=(-0.118459,\,-0.236918)$ and $\partial L/\partial b=-0.118459$.
4. *Autograd.* In float64, `w.grad = [-0.118459, -0.236918]` and `b.grad = -0.118459`; the difference from the hand values is below $10^{-16}$. A central difference with $\epsilon=10^{-6}$ differs by $5\times10^{-12}$ to $10^{-11}$.
5. *SGD step* with $\eta=0.5$: $w\leftarrow(0.5+0.059230,\,-0.25+0.118459)=(0.559230,-0.131541)$ and $b\leftarrow0.1+0.059230=0.159230$.
6. *New loss.* $z=0.559230-0.263082+0.159230=0.455378$, $y=0.611917$, $L=\tfrac12(0.388083)^2=0.075304$.

**Check.** The loss fell from 0.112822 to 0.075304. The first-order prediction is $-\eta\|\nabla L\|^2=-0.5\,(0.118459^2+0.236918^2+0.118459^2)=-0.042097$, close to the actual change $-0.037518$ (the difference is the second-order term).

**Takeaway.** Hand derivation, autograd and finite differences agree to the displayed digits, and a small step along $-\nabla L$ lowers the loss.

### Case 2: accumulation and detach

**Problem.** (a) With $w=3$ and $L=w^2$, call `backward()` three times in a row without zeroing; what does `w.grad` show? (b) With $w=2$ and $x=3$, compare the gradient of $z=(wx)\,w$ with that of `(w*x).detach()*w`.

**Solution.**
1. *Rule* (theory, "Accumulation, no_grad, detach, in-place"): `backward()` adds to `.grad`.
2. (a) Each call computes $\partial L/\partial w=2w=6$ and adds it: after the three calls `w.grad` is $6,\,12,\,18$.
3. (b) *Full graph:* $z=w^2x$, so $\partial z/\partial w=2wx=2\cdot2\cdot3=12$.
4. *Detached:* `(w*x).detach()` is the constant $wx=6$, so $z=6\,w$ and $\partial z/\partial w=6$.

**Check.** Running both in PyTorch prints `6.0, 12.0, 18.0` and `12.0`, `6.0`. The detached gradient is exactly half, because only one of the two factors of $w$ is differentiated.

**Takeaway.** Gradients accumulate unless cleared, and `detach` removes a path from the gradient without changing the forward value.

### Case 3: the stability limit of the learning rate

**Problem.** Fit $y=ax+b$ to the 20 points $x_i=-1+2i/19$ ($i=0,\dots,19$) of the line $y=2x+1$ by full-batch gradient descent on $L=\tfrac1{20}\sum(ax_i+b-y_i)^2$, from $(a,b)=(0,0)$. Predict from the Hessian which of $\eta=0.1,\,0.5,\,1.0,\,1.1$ converge, and compare with the loss at step 200.

**Solution.**
1. *Hessian* (theory, "Gradient descent on a quadratic"). For $r_i=ax_i+b-y_i$, $H=\tfrac2{20}\sum\begin{bmatrix}x_i^2&x_i\\x_i&1\end{bmatrix}$. The points are symmetric about 0, so $\overline x=0$ and $\overline{x^2}=7/19=0.368421$. The matrix is diagonal with eigenvalues $\lambda_a=2\cdot7/19=0.736842$ and $\lambda_b=2$.
2. *Stability.* The error $e=(a-2,\,b-1)$ obeys $e_{k+1}=(I-\eta H)e_k$, with per-step factors $|1-\eta\lambda_a|$ and $|1-\eta\lambda_b|$. Convergence needs both $<1$, that is $\eta<2/\lambda_{\max}=1$.
3. *Loss formula.* From $e_0=(-2,-1)$ the loss is $L_k=1.4737\,f_a^{2k}+1.0\,f_b^{2k}$ with $f_a=|1-\eta\lambda_a|$, $f_b=|1-\eta\lambda_b|$ (the initial loss $2.4737$ splits as $\tfrac12\lambda_a\cdot4=1.4737$ and $\tfrac12\lambda_b\cdot1=1$).
4. *Factors.* $\eta=0.1$: $f_a=0.9263$, $f_b=0.8$. $\eta=0.5$: $0.6316$, $0$. $\eta=1.0$: $0.2632$, $1$. $\eta=1.1$: $0.1895$, $1.2$.
5. *Loss at step 200* (the loss is evaluated before the 200th update, so $k=199$): $\eta=0.1$: $1.4737\cdot0.9263^{398}=8.7\times10^{-14}$; $\eta=0.5$: the formula gives about $10^{-80}$, but float64 round-off sets a floor near $10^{-32}$, and the run shows $3.9\times10^{-32}$; $\eta=1.0$: $f_b=1$ keeps the intercept error at magnitude 1 with alternating sign, so the loss stays at $1.0$; $\eta=1.1$: $1.2^{398}=3.3\times10^{31}$.

**Check.** A PyTorch run with `torch.optim.SGD` gives $8.68\times10^{-14}$, $3.88\times10^{-32}$, $1.000$ and $3.27\times10^{31}$ at step 200, matching the formula (the intercept ends at about $-2\times10^{-15}$ for $\eta=1.0$, i.e. it flips between 0 and 2).

![Four loss curves on a logarithmic axis against the step number: eta 0.1 falls slowly to 1e-13, eta 0.5 falls to the round-off floor, eta 1.0 stays flat at 1, eta 1.1 rises to 3e31](/lesson-figures/PY06-4.svg)

*Figure: the numbers of Case 3. The slope of each curve is $2\log_{10}$ of its slowest factor; $\eta=1.0$ sits exactly at $2/\lambda_{\max}$, and $\eta=1.1$ grows by $1.2^2=1.44$ per step.*

**Takeaway.** The Hessian predicts the whole behaviour: $\eta<2/\lambda_{\max}$ converges at the rate of its slowest or stiffest factor, $\eta=2/\lambda_{\max}$ freezes the loss, and anything above diverges geometrically.

## Reference implementation

```python
import math
import torch

def neuron_loss(w, b, x, t):
    y = torch.sigmoid(w @ x + b)
    return 0.5 * (y - t) ** 2

def hand_grads(w, b, x, t):
    z = sum(wi * xi for wi, xi in zip(w, x)) + b
    y = 1 / (1 + math.exp(-z))
    dz = (y - t) * y * (1 - y)
    return [dz * xi for xi in x], dz

def autograd_grads(w, b, x, t):
    wt = torch.tensor(w, dtype=torch.float64, requires_grad=True)
    bt = torch.tensor(b, dtype=torch.float64, requires_grad=True)
    neuron_loss(wt, bt, torch.tensor(x, dtype=torch.float64), t).backward()
    return wt.grad.tolist(), bt.grad.item()

def numeric_grad(f, p, eps=1e-6):
    g = []
    for i in range(len(p)):
        hi, lo = list(p), list(p)
        hi[i] += eps; lo[i] -= eps
        g.append((f(hi) - f(lo)) / (2 * eps))
    return g

def train_linear(X, Y, lr, steps):
    X = torch.tensor(X, dtype=torch.float64); Y = torch.tensor(Y, dtype=torch.float64)
    p = torch.zeros(2, dtype=torch.float64, requires_grad=True)
    opt = torch.optim.SGD([p], lr=lr)
    losses = []
    for _ in range(steps):
        opt.zero_grad()
        loss = ((p[0] * X + p[1] - Y) ** 2).mean()
        loss.backward()
        opt.step()
        losses.append(loss.item())
    return p[0].item(), p[1].item(), losses

# self-test
hw, hb = hand_grads([0.5, -0.25], 0.1, [1, 2], 1.0)
aw, ab = autograd_grads([0.5, -0.25], 0.1, [1, 2], 1.0)
assert all(abs(a - b) < 1e-12 for a, b in zip(hw, aw)) and abs(hb - ab) < 1e-12
print(round(hw[0], 6), round(hw[1], 6), round(hb, 6))
```

## Verification

Verify gradients and loops with checks that can fail. (1) Gradient check: compare autograd with a float64 central-difference estimate (error about $10^{-9}$ to $10^{-10}$ for smooth functions). (2) Hand derivation on a tiny case, like the neuron. (3) Overfit one small batch: the loss must go to nearly zero; if not, the loop or model is wrong. (4) Loss should decrease for a small enough learning rate; a monotone increase points to a sign error, missing `zero_grad` or a too-large step. (5) Check `p.grad` is not `None` and not all zeros for every parameter after `backward()` (a `None` means the parameter is not on the graph). (6) Check shapes and dtypes at each stage with `print(t.shape, t.dtype)`.

## Failure modes

- Missing `zero_grad()`: gradients add up (6, 12, 18 for $L=w^2$), steps grow each iteration, loss oscillates or diverges.
- Calling `step()` before `backward()`, or `backward()` before the forward pass is complete: updates use stale or `None` gradients.
- In-place edits of tensors needed for backward: `RuntimeError: ... modified by an inplace operation`.
- `detach()` or `.item()` in the middle of the loss: gradient flows nowhere (gradient 6 instead of 12 in the example); the loss never decreases.
- Learning rate above $2/\lambda_{\max}$: loss explodes ($3\times10^{31}$ in the example); exactly $2/\lambda_{\max}$: loss stuck at 1.0.
- float32 finite-difference checks: errors of $3\times10^{-4}$ look like a bug; use float64.
- Integer tensors in `mean` or `requires_grad=True` on integer tensors: errors; cast to float.
- Evaluating the model without `no_grad` and `eval()`: wasted memory and dropout or batch-norm behaving as in training.
- Forgetting to seed: runs cannot be reproduced.

## Alternatives and trade-offs

Hand-derived gradients are exact and fast for tiny models and are the right test oracle, but do not scale and are error-prone. Finite differences are simple but cost one forward pass per parameter and are limited by float precision; use them only for verification. Reverse-mode autodiff (PyTorch, JAX) is efficient for many parameters and one loss; forward-mode is better for few inputs and many outputs (Jacobian-vector products). Plain SGD is simple and predictable; momentum or Adam converge faster on ill-conditioned problems but add hyperparameters. `torch.nn.Module` and optimizers remove boilerplate, but writing one loop by hand once is the best way to understand it. For classical, small least-squares problems (PY05) a direct solver is faster and exact; use PyTorch when the model or loss is not linear or when data are large.

## Transfer and retention

- A learned perception or control policy is trained with exactly this loop; the same gradient check validates a custom loss (for example a reprojection or pose loss).
- Differentiable simulators and differentiable rendering use autograd through physics or geometry; the accumulation and detach rules decide whether gradients flow through the world model.
