## Why this matters

Write small functions whose behavior you can explain and test. This lesson develops the core calculation before asking you to apply it in a new setting. Start with the diagnostic if you think you already know it; prior tool use is not evidence of understanding.

## Intuition

A program is a sequence of state changes. Reading code means predicting what each statement does before running it. A function packages a calculation behind an input/output contract; a printed message is for a person, while a returned value lets other code use the result.

![Two outer lists sharing the same inner lists after a shallow copy](/lesson-figures/PY01.svg)

*Figure: a shallow copy creates a new outer list but reuses the inner objects.*

## Theory and derivation

Python names refer to objects. `x = 3` binds a name; `x == 3` asks a question. An `if` selects a branch, and a `for` visits items in an iterable. `range(3)` produces 0, 1, 2; the stop bound is excluded. Indentation defines blocks, so moving a `return` inside a loop can stop processing after the first item.

To calculate a mean, track a running total s and count n, then return s/n. For an empty input, n=0, so define a failure contract rather than divide by zero. Avoid mutable default arguments such as `items=[]`: the same default object persists across calls. A pure function does not mutate its input and returns the same result for the same values.

Lists hold ordered references. `b=a` aliases one list; `b=list(a)` creates a shallow copy. A shallow copy does not duplicate nested lists. State whether your function reads, mutates, or owns the data it receives. Small contracts make debugging much easier than inspecting a long script with hidden global state.

## Worked example

For values=[2,4,6], initialize total=0. The loop updates it to 2, 6, then 12. Divide by len(values)=3 to return 4. If return total/len(values) sits inside the loop, the function incorrectly returns 2/3 after one iteration.

## Reference implementation

Read the contract first. Predict the output before running the code locally. This reference is for studying; a submission copied from it is assisted practice, not independent evidence.

```python
def mean(values):
    if not values:
        raise ValueError("empty input")
    total=0.0
    for value in values:
        total += value
    return total/len(values)

assert mean([2,4,6]) == 4
```

### Goal

### Setup

Python 3 standard library only. Put the starter code and the tests below into one file, `sensor_lab.py`, and run `python3 sensor_lab.py`.

### Tasks

1. Implement `mean` (raise `ValueError` on an empty list) and `median` (middle value, or the average of the two middle values; do not sort the caller's list in place).

5. Run the tests. Then deliberately move a `return` inside a loop in one function and confirm that a test catches it.

### Tests

```python
# hand-computed cases
assert mean([2, 4, 6]) == 4
assert median([1, 2, 3, 100]) == 2.5
assert median([5, 1, 3]) == 3
assert moving_average([1, 2, 3, 4, 5], 3) == [2, 3, 4]
assert parse_readings(["1.5", " 2 ", "bad", "", "nan", "3e0", "inf"]) == [1.5, 2.0, 3.0]

# edge cases: errors and single element
for bad in (lambda: mean([]), lambda: median([]), lambda: summarize([]),
            lambda: moving_average([1, 2], 3), lambda: moving_average([1, 2], 0)):
    try:
        bad()
    except ValueError:
        pass
    else:
        raise AssertionError("expected ValueError")
assert summarize([7]) == {"n": 1, "mean": 7, "median": 7, "min": 7, "max": 7}

# properties: no mutation; mean is between min and max; window k=1 is identity
data = [9.0, -2.0, 4.5, 4.5, 0.0]
copy = list(data)
s = summarize(data)
assert data == copy
assert s["min"] <= s["mean"] <= s["max"] and s["min"] <= s["median"] <= s["max"]
assert moving_average(data, 1) == data
assert len(moving_average(data, 4)) == len(data) - 4 + 1
print(summarize(parse_readings(["10", "x", " 12.5", "11", "nan", "9.5"])))
print("all tests passed")
```

## Failure modes

Printing the answer does not return it: a function without return produces None. A default list can leak state between calls. Test inputs should reveal these failures instead of copying only a happy-path example.

## Alternatives and trade-offs

A loop exposes intermediate states and supports flexible logic. A list comprehension is concise for simple transformations. Use neither as a substitute for a clear contract; vectorization comes after you can explain the scalar calculation.

## Exercise answers

1. Prints `4 3`. `y = x` binds the name `y` to the same integer object (3); `x = x + 1` then binds `x` to a new object (4) and leaves `y` unchanged. Integers are immutable, so rebinding one name never affects another.
2. `[2, 5, 8]` (start 2, step 3, stop 10 excluded) and `[]`. A `range` with a positive step and `start >= stop` is simply empty; it is not an error, and a loop over it runs zero times.
3. Prints `True [0, 1]`. The function mutates the list it receives and returns the same object, so `c` and `b` are two names for one list.
4. Prints `[1]` then `[1, 2]`. The default list is created once when the function is defined and shared by every call. Fix: `def add(x, acc=None): if acc is None: acc = []` then append and return.
5. First list: mean $=6$, median $=6$. Second: mean $=106/4=26.5$, median $=(2+3)/2=2.5$. For glitchy data report the median (or a trimmed mean): one outlier drags the mean to 26.5 but barely moves the median.
6. It returns `0`. `best` starts at 0, and neither value is greater than 0. Fix: raise `ValueError` for an empty list, start with `best = values[0]`, and loop over the rest (or use `max`). A starting value must be a real element, not an arbitrary constant.
7. `a` prints `[[1, 2, 9], [3]]` and `b` prints `[[1, 2, 9], [3], [4]]`. `list(a)` is a shallow copy: the outer list is new (so `b.append([4])` does not affect `a`) but both outer lists hold references to the same inner lists (so `b[0].append(9)` changes `a`). Use `copy.deepcopy` when nested data must be independent.
8. The `else` branch returns `-1` after inspecting only the first element, so `[3, -1]` gives `-1`. Remove the `else` and put `return -1` after the loop, at function level (dedented). The loop may stop early only when it has found the answer.
9. $n-k+1$ outputs: $5-3+1=3$, namely `[2.0, 3.0, 4.0]`. The sums are $s_i=\sum_{j=i}^{i+k-1}v_j$; so $s_{i+1}-s_i=v_{i+k}-v_i$. This gives $O(n)$ total work instead of $O(nk)$, but rounding errors accumulate along the running sum, so for long float streams recompute periodically or use `math.fsum` per window.
10. `0.1 + 0.2 == 0.3` is `False`; `sum([0.1] * 10) == 1.0` is `False` because the sum is `0.9999999999999999`. Compare with a tolerance: `abs(a - b) <= 1e-9` or `math.isclose(a, b)`.
11. A good contract: `x, lo, hi` are real numbers; return `lo` if `x < lo`, `hi` if `x > hi`, else `x`; raise `ValueError` if `lo > hi`; a value equal to a bound is returned unchanged. Tests: `clamp(5,0,10)=5`; `clamp(-1,0,10)=0`; `clamp(11,0,10)=10`; boundary `clamp(10,0,10)=10`; error `clamp(1,5,0)` raises `ValueError`.
12. Rule: bin index $=\lfloor (v-lo)/(hi-lo)\cdot \text{bins}\rfloor$ for $lo\le v<hi$; `hi` itself (and anything below `lo`) is ignored. With width 2, the counts are `[3, 1, 0, 0, 1]`: bin 0 holds 0, 1, 1; bin 1 holds 2; bin 4 holds 9.99; `10` and `-1` are dropped. A good answer allocates a new counts list and never sorts or edits the input.
