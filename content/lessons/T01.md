## Why this matters

Every robotics, ML and tooling workflow in this curriculum eventually runs on a Linux machine: training scripts on a workstation, ROS 2 nodes on a robot computer, containers in CI. The shell is how you start, inspect and stop all of it. Most "it works on my machine" failures are really failures of the basics: a script that only works from one directory, a file the wrong user cannot read, a command that silently fails inside a pipeline, a background job nobody can find. This lesson teaches the small set of ideas behind the shell (words, quoting, redirection, exit status), permissions, and processes, then turns them into a **repeatable project command** that does not depend on your shell history.

## Intuition

The shell is a program that reads a line, splits it into **words**, expands some of them (variables, globs), finds the program named by the first word, starts it as a **process** with the remaining words as arguments, and waits. Everything else is plumbing: file descriptors 0, 1 and 2 (standard input, output, error) can be redirected to files or connected by pipes; every process ends with an **exit status** (0 means success), which the shell exposes as `$?`.

Three questions explain most Linux surprises. *Where am I?* (current working directory, and the `PATH` that decides which executable a bare name finds.) *Who am I allowed to be?* (user, groups, and the nine permission bits on each file.) *What is running?* (a process tree with IDs, states and signals.)

## Theory and derivation

### Words, quoting and expansion

The shell splits on unquoted whitespace. `echo a   b` runs `echo` with two arguments; `echo "a   b"` with one. Double quotes allow `$variable` expansion; single quotes suppress everything. An unquoted `$f` containing spaces becomes several words, which is the single most common cause of scripts that delete the wrong thing. Quote every expansion: `"$f"`.

### Redirection and pipes

`cmd > out` sends stdout to a file (truncating), `>>` appends, `2> err` redirects stderr, `2>&1` makes fd 2 a copy of wherever fd 1 currently points. **Order matters**: `cmd > f 2>&1` sends both to `f`; `cmd 2>&1 > f` points stderr at the *old* stdout (the terminal) and then moves stdout to `f`. `a | b` connects `a`'s stdout to `b`'s stdin; the stages run concurrently.

### Exit status

`0` means success; anything else is a failure code chosen by the program. Conventions: `126` found but not executable, `127` command not found, `128+N` killed by signal $N$ (so `137` is SIGKILL and `143` is SIGTERM). A pipeline's status is, by default, that of the **last** stage, so `false | true` succeeds. `set -o pipefail` makes it the right-most failing stage's status. `set -e` (errexit) stops a script at the first failing command, `set -u` makes unset variables errors. The strict header `set -euo pipefail` turns many silent failures into loud ones (it has exceptions, for example commands in `if` conditions, so it is a safety net, not a proof).

### Permissions

Each file has an owner, a group and three permission triplets: **r**ead (4), **w**rite (2), e**x**ecute (1), for user, group and other. The mode `rwxr-x---` is octal $7\,5\,0$. Access is decided by the **first matching class**: owner, else group, else other. So a file with mode `070` owned by you is *not* readable by you even though your group has all rights. Directories use the same bits with different meaning: `x` is the right to enter/traverse, `r` the right to list names, `w` the right to create/delete entries. New files are created with the requested mode minus the **umask**: $\text{mode}\ \&\ \sim\text{umask}$. With umask `022`, regular files (requested `666`) become `644`, directories (`777`) become `755`. A file runs as a program only with an `x` bit; a first line `#!/usr/bin/env bash` (the shebang) chooses the interpreter.

### Processes and signals

Each process has a PID and a parent PID. The shell starts children; `cmd &` runs one in the background, `jobs` lists them, `ps`/`top` show all. Signals are asynchronous messages: `SIGINT` (Ctrl-C, 2), `SIGTERM` (15, polite "please exit", can be handled), `SIGKILL` (9, cannot be caught, no cleanup). Always try TERM first so a program can flush files. Resource state lives in `df -h` (disk), `du -sh` (directory size), `free -h` (memory) and `ulimit -a` (limits).

### A repeatable project command

A command is repeatable when it does not rely on your shell history, current directory, exported variables or manual edits. Properties: a shebang and the exec bit; strict mode; `cd` to the script's own directory; arguments with defaults and validation; deterministic outputs in a known folder; a log; meaningful exit codes (0 ok, 2 usage error); documentation in a comment header.

## Worked example

**Permission arithmetic.** `rwxr-x---`: user $4+2+1=7$, group $4+0+1=5$, other $0$: mode $750$. `0640` as symbols: $6=rw-$, $4=r--$, $0=---$: `rw-r-----`.

**Umask.** Requested $666$, umask $022$: $666\ \&\ \sim022=644$. Directory $777\to755$. With umask $027$ a file becomes $640$ and a directory $750$.

**Access check.** File `alice:robots`, mode `0640`. Alice (owner): owner class `rw-`: read yes, write yes, execute no. Bob (in `robots`): group class `r--`: read yes, write no. Carol (neither): other class `---`: nothing.

**Pipeline status.** `grep foo missing.txt | wc -l`: `grep` exits $2$ (file missing), `wc` prints `0` and exits $0$. Default status: $0$. With `pipefail`: $2$.

**Redirection order.** `ls /nonexistent > o.txt 2>&1` writes the error message into `o.txt`; `ls /nonexistent 2>&1 > o2.txt` prints the message on the terminal and leaves `o2.txt` empty.

**Exit codes.** `sleep 30 &` then `kill -9 $!`: `wait` reports $128+9=137$.

## Reference implementation

A small Python model of the rules above: permission bit conversion, umask, the owner/group/other access decision, pipeline and `set -e` semantics, word splitting, `PATH` lookup and signal exit codes. (It models the concepts; the real shell and kernel are the authority.)

```python
import shlex

def sym_to_octal(s):
    """'rwxr-x---' -> 0o750 (nine permission characters, no file-type prefix)."""
    assert len(s) == 9
    return sum((1 << (8 - i)) for i, ch in enumerate(s) if ch != "-")

def octal_to_sym(m):
    return "".join(ch if m & (1 << (8 - i)) else "-" for i, ch in enumerate("rwxrwxrwx"))

def apply_umask(mode, umask):
    """Permissions of a newly created file/dir: the requested mode with the umask bits cleared."""
    return mode & ~umask & 0o777

def can_access(mode, owner, group, uid, gids, op):
    """Classic Unix check for op in 'r', 'w', 'x'. The FIRST matching class decides:
    owner if uid == owner, else group if group in gids, else other. uid 0 (root) may read/write
    anything and may execute only if some execute bit is set."""
    bit = {"r": 4, "w": 2, "x": 1}[op]
    if uid == 0:
        return True if op != "x" else bool(mode & 0o111)
    if uid == owner:
        cls = (mode >> 6) & 7
    elif group in gids:
        cls = (mode >> 3) & 7
    else:
        cls = mode & 7
    return bool(cls & bit)

def pipeline_status(statuses, pipefail):
    """Exit status of 'a | b | c' given each stage's status: the last stage's, or with pipefail
    the status of the right-most failing stage (0 if none failed)."""
    if not pipefail:
        return statuses[-1]
    for s in reversed(statuses):
        if s != 0:
            return s
    return 0

def errexit_run(statuses, errexit):
    """Run commands whose exit statuses are given. With errexit ('set -e') stop right after the first
    non-zero status. Return (number_executed, last_status)."""
    last = 0
    for i, s in enumerate(statuses):
        last = s
        if errexit and s != 0:
            return i + 1, last
    return len(statuses), last

def split_words(line):
    """How the shell splits a command line into words (quotes group, backslash escapes)."""
    return shlex.split(line)

def find_in_path(cmd, path, executables):
    """First directory in the colon-separated PATH where dir + '/' + cmd is in the set of executables."""
    for d in path.split(":"):
        if d and f"{d}/{cmd}" in executables:
            return f"{d}/{cmd}"
    return None

def exit_code_for_signal(sig):
    """Shell convention: a process killed by signal N reports 128 + N."""
    return 128 + sig

# tiny self-test
assert sym_to_octal("rwxr-xr--") == 0o754 and octal_to_sym(0o640) == "rw-r-----"
assert apply_umask(0o666, 0o022) == 0o644 and apply_umask(0o777, 0o027) == 0o750
assert pipeline_status([1, 0], False) == 0 and pipeline_status([1, 0], True) == 1
```

        fpath, dpath = os.path.join(d, "f"), os.path.join(d, "sub")
        os.close(os.open(fpath, os.O_CREAT | os.O_WRONLY, 0o666))

        os.umask(old)

    assert stat.S_IMODE(os.stat(dpath).st_mode) == apply_umask(0o777, 0o027) == 0o750

    assert stat.filemode(os.stat(fpath).st_mode) == "-" + octal_to_sym(0o640)

    # 3. the owner class wins: mode 070 is unreadable by its owner (os.access uses the real uid)
    os.chmod(fpath, 0o070)

    os.chmod(fpath, 0o640)
    assert os.access(fpath, os.R_OK) and not os.access(fpath, os.X_OK)

def status(cmd):

## Verification

- **Same result from anywhere:** run the command from `/`, from `/tmp` and from the project directory; outputs must be identical.
- **Hand computations:** modes $750$, $644$, $640$; `137`/`143`; pipeline status $0$ vs $1$.
- **Invariants:** octal/symbolic conversion round-trips for all $512$ modes; a umask never adds permissions.
- **Failure path:** invalid input must exit non-zero and write nothing to `out/result.txt`.
- **Falsifier:** if the script depends on something not in the repository (an alias, an exported variable, the current directory), a clean shell (`env -i bash --noprofile --norc ./run.sh`) will reveal it.

## Failure modes

- **Unquoted variables** splitting at spaces or expanding to nothing (`rm -rf $DIR/` with empty `DIR` removes `/`; always quote and validate).
- **`cd` that fails silently** and later commands run in the wrong directory (`set -e`, or `cd dir || exit 1`).
- **Relying on cwd:** works from the project folder, breaks from cron or CI.
- **Pipeline hides failure:** `producer | consumer` reports success when `producer` crashed.
- **Wrong redirection order**, losing stderr.
- **Permission surprises:** the owner class overrides the group class; `x` missing on a directory blocks `cd`; `umask 077` makes shared files unreadable.
- **`kill -9` first:** no cleanup, truncated output files.
- **Editing the installed copy of a script** instead of the repository version.
- **`#!/bin/bash` hard-coded** on systems where bash is elsewhere (prefer `#!/usr/bin/env bash`).

## Alternatives and trade-offs

| Need | Tool | Trade-off |
| --- | --- | --- |
| A few commands, one machine | shell script | quick; fragile quoting; hard to test |
| Named tasks with dependencies | Makefile / `just` | declarative; tab/syntax quirks |
| Logic, parsing, data | Python script with `argparse` | portable and testable; slower start |
| Many machines or environments | container or CI pipeline (T06) | reproducible; more setup |
| Long-lived services | systemd unit / supervisor | restarts, logging; needs privileges |

Use shell for glue (a dozen lines); switch to Python once you need data structures, error handling beyond exit codes, or tests.

2. $7\,5\,0=750$; `0640` is `rw-r-----`. With umask `027`: file $666\to640$, directory $777\to750$.
3. Owner class applies to Alice: `0470` has owner bits $4=r--$, so Alice can read (cannot write). Bob is not the owner, so the group class $7=rwx$ applies: yes, he can write. Carol uses the other class $0$: no. Rule: the first matching class (owner, then group, then other) decides.
4. Without `pipefail` the status is that of `wc`: `0`. With it the status is `2` (grep's). In a nightly job the default reports success although the log is missing, so monitoring never alerts.
5. `cmd > f 2>&1`: stdout goes to `f`, then stderr is duplicated onto stdout (now `f`): both in `f`. `cmd 2>&1 > f`: stderr is duplicated onto the *current* stdout (the terminal) first, then stdout moves to `f`: only stdout in `f`. The first captures errors.
6. If `$1` is empty `cd` goes to the home directory (or fails); if `cd` fails the script continues and `rm -rf *` runs in the *current* directory. Unquoted `$1` with spaces becomes several arguments. Safer: `set -euo pipefail; dir=${1:?usage: clean DIR}; cd -- "$dir"; rm -rf -- ./*`, or avoid the glob and delete a named subdirectory.
7. `137` ($128+9$). `kill PID` sends SIGTERM (15), allowing the process to flush buffers and remove temp files; `-9` cannot be handled. `nohup` makes the process ignore SIGHUP so it survives closing the terminal; it does not change signals sent explicitly.
8. A good answer lists: one script with shebang and exec bit; strict mode; resolve the project root from the script path; a config or arguments for the download URL/paths with defaults and validation; output folder created if missing; logging with timestamps; non-zero exit codes on failure and an explicit cleanup trap; documentation header; no reliance on history, aliases or the current directory.
9. `./run.sh` gives an explicit path, so no `PATH` lookup. `run.sh` is searched in the `PATH` directories only; the project directory is not in it, so status `127` (not found). Without the exec bit the file is found but cannot be executed: `Permission denied`, status `126`. A shebang pointing to a missing interpreter yields a "bad interpreter: No such file or directory" error (the kernel cannot start it); running with an explicit interpreter (`bash run.sh`) bypasses both the exec bit and the shebang.
10. A good answer contains a script with the subcommands, strict mode and logging; a test script asserting `stat -c %a run.sh` is `755`, the same output from `/` and the project folder, and exit `2` with an error message on bad input; and the Python model tests for the permission cases used.
